# 通常AE／エンチャント分離の移行計画（2026-09-20）

状態: 計画案。ユーザーが確定した前提と、以下の提案を区別する。今回は記録のみで、実装・ワールド移行は実施しない。

追補: 同日の追加指示は [AE_Keys_and_Expiry_Design_2026-09-20.md](AE_Keys_and_Expiry_Design_2026-09-20.md) を正とする。混在効果は存在しない。通常AEから準備先設定を除去し、付与AEはアウトフィット専用・ステータス関連機能なしとする。適用先チェックは排他で、自動適用オン時は一方必須、オフ時は両方オフでドロップ付与。「次の1回の判定まで」は条件一致判定の確定後に消費し、中止は消費しない。

## 1. 出発点と維持する条件

- 本体 `2b20419` を基準とする。従来AEへの復帰は `6c33c0d`、撤回した改修版は `5e8cc02`。
- **確定事項: 「準備先に適用」がオンのアイテム上AEは、アクターへ転送しない。** 標準適用・状態・一覧と、TNX独自の判定／ダメージ補正収集の両方から除外する。チェック解除で従来の通常転送へ戻る。
- 準備先へのアイテム間コピーは維持する。`transfer` は現在、自動適用ゲートとしても使われているので、一律falseへの変更で転送を止めない。
- 既存のキー文法・識別キー・数式参照・リテラル補正後の式評価・重複制御・有効時間・神業由来フラグを維持する。
- 技能・神業はFoundry上ではItemだが、現在の設計ではキャラクターの一部。型分離を理由にすべてのItemをエンチャントの付与先にしない。
- 現存する `type: enchantment` は試行版由来で、現在は標準AEの互換登録で扱っている。型名だけでは内容の妥当性を保証しない。
- 移行v6は撤回済みの番号として保持する。復活・再利用・dataVersionの巻き戻しはしない。

経緯・既知問題は [復帰記録](AE_Rollback_2026-09-20.md)、現在の仕様は [Active_Effects](../01_Wiki/Game_Mechanics/Active_Effects.md) を参照。

## 2. 目標モデル案

型は「保存場所」ではなく「何を変更する効果か」を表す。効果定義を保持するアイテムと、実際に効果を受けるアイテムを区別する。

| 軸 | 意味・提案 |
|---|---|
| 通常AE | キャラクターの値・判定・状態など。技能／神業の実効値への遠隔補正を含む |
| エンチャント | アウトフィットの性能・名称・部位等を変更する効果 |
| 適用時期 | 常時自動適用／使用時付与。型とは別の条件 |
| 適用先 | キャラクター／アイテム自身／準備先／選択・条件に合う対象。保持元とは別に判断 |
| 由来 | 元定義／自動転送コピー／使用時付与コピー。同期・重複・削除の規則に使用 |

この役割分担は提案。新しい保存フィールドをただちに増やすのではなく、既存のtype・transfer・flags・キーで表せる範囲と不足を設計段階で確定する。

## 3. 段階的な実施

### 段階1: 仕様と対応表を確定する

通常AE／エンチャントについて、作成可能な保持元、適用先、許可キー、状態、適用時期を表にする。使用時付与・RL任意付与・プリセット・ドラッグ複製も含める。

特に次を確定する。

1. 混在効果は存在しない（ユーザー確定）。混在効果の分割機能は作らない。
2. 「準備先に適用」と使用時付与を併用する場合、誰のどのアイテムを選ぶか。現行の使用時コピーはapplyToParentを落としており、チェックの文言だけから新しい付与挙動を推測しない。
3. 付与AEからステータス状態関連機能を除去する（ユーザー確定）。非表示だけでなく保存・付与マーカー・状態集計を対象にする。移行時に不整合データを発見した場合は内容を報告する。
4. V13対応の継続範囲。現在のmanifestはminimum 13であり、V14専用の型機構へ移行するなら対応表とmanifestを一致させる。

完了条件: 新規・既存・混在効果すべてに、保存先と適用先の判断規則がある。未確定ケースをコードで推測しない。

### 段階2: 現行方式のまま保存形式の不具合を修正する

- V14の正規保存先 `system.changes` と、旧形式 `changes` の読取・変換境界を揃える。二重に存在する場合の優先順位も決める。
- ドキュメント、toObject、deepClone、JSON保存、プリセット、チャット経由の付与まで実データ形式が保たれるようにする。
- `mode` と `type` の互換変換、`priority` と `phase` の保持・比較を揃える。V14のschemaを基底にし、必要なフィールドを落とさない。
- 型分離前に、使用時付与のアイテム候補・着地・キー変換を修復する。V14更新時の `system.changes` が転送同期の更新検知を通ることも確認する。

完了条件: 現行の通常AEで、作成→保存→再読込→複製→付与→更新が通る。準備先効果は全経路でアクターへ漏れない。

### 段階3: 適用処理と新規データを型に対応させる

- 型・適用時期・適用先・由来をもとに、標準適用、独自バフ収集、物理コピー、使用時付与で同じ判断を使う。
- 通常AEのキャラクター向け適用と、エンチャントのアイテム向け適用を処理側で保証する。UIだけで制限しない。
- 新規作成、転送コピー、付与コピー、プリセット作成、RL作成、複製／インポートのすべてで型を明示する。
- 旧データは移行前でも従来どおり読み込む。未移行のbase型・試行版enchantment型・混在効果を、新規データ用制約で突然無効にしない。
- 数式の参照元、コピーの供給元、同期・削除・持続時間・重複判定が型追加で変化しないことを検証する。

完了条件: 新規データは仕様どおり適用され、旧データは互換経路で動く。型名を付け替えただけの状態では完了にしない。

### 段階4: UIを接続する

- 確定した作成可能範囲に合わせて型選択・項目・キー候補を出す。
- 「使用時付与用」「転送コピーの供給元」「有効／無効」「非表示」の意味を維持する。型による一覧分岐で後続の分類を飛ばさない。
- 準備先効果は供給元・準備先で確認でき、アクターには表示しない。
- 型変更でデータを失うケースは、既存内容と変更結果を提示する。非表示だけにして状態や無効キーを隠さない。

完了条件: 新規作成・編集保存・再表示と、実際の適用結果が一致する。

### 段階5: 読取専用の棚卸しと移行計画生成

| 保管場所 | 扱い |
|---|---|
| ワールドActorと所持Item | 直接のAEと所持ItemのAEを調査 |
| ワールドItem | AEを調査 |
| Sceneの非リンクToken | 独立したActorデータ・差分を調査。リンクTokenは元Actorとの二重処理を避ける |
| 効果プリセット | Journal等に保存された効果データを調査 |
| コンペンディウム | ワールド作成分・配布分・ロック状態を区別。読取専用パックは直接変更せず、更新またはインポート時変換 |
| 再使用可能なチャットデータ等 | 保存済み付与データを棚卸しし、過去カードの再使用時に互換読込できるようにする |

実在する保存場所はコードと複製ワールドで確認する。判定可能な変換／変更不要／要確認／読取専用に分類し、件数・UUID・変更前後・判断理由・参照先を出力する。
applyToParent付き、直接アイテム補正、転送／付与コピー、状態付き、混在、既存enchantment、参照切れを別々に扱う。型名やフラグ1つだけで一括変換しない。

完了条件: データを変更せず全対象と例外を説明できる。未処理を残して全件完了と記録しない。

### 段階6: 複製ワールドで安全な移行・復元を検証する

- 整合したバックアップを取得し、復元できることを確認してから、まず複製ワールドで実行する。
- 型更新APIの可否は対象Foundry版で検証する。前回のForcedReplacement問題を、削除先行で回避しない。
- 更新で済むならIDを保って更新する。置換が必須なら、旧データを保持した段階移行と参照付替え・失敗復元を設計し、実機で検証する。
- ID／UUIDを維持できない場合は、用途のeffectId、origin、transferredFrom、grantedFrom、重複識別等への影響を棚卸しする。参照整合性を検証できない対象は変換しない。
- 効果内容・参照・件数を照合し、移行途中の同期フックによるコピー消失・増殖も検証する。
- 中断、部分失敗、再実行、複数GM、処理中の編集を扱う。実行主体を1つに限定し、再実行で多重化しない進捗管理を用意する。
- v6は予約のまま、新しい移行番号を使用する。対象範囲の検証が成功した時点で完了を記録する。

完了条件: 正常移行だけでなく、失敗後の再開・バックアップ復元を実証できる。本番移行の前に、対象ワールドの棚卸し結果・変更内容・復元手順を提示する。

## 4. 回帰確認とリリース条件

- 準備先チェックON/OFF、未準備・準備・準備解除・準備先変更、元効果の更新・無効化・削除。
- アクターの値・判定・ダメージ・状態・一覧への漏れと二重適用がないこと。
- 通常AE、アイテム自体の補正、技能レベル補正、使用時付与、RL付与、プリセット、転送コピーの一連の動作。
- 数値／式／文字列／真偽／名称／部位、重複可否、持続と解除、神業由来情報。
- 旧形式・V14形式・試行版形式、複製・保存・再読込、非リンクTokenとインポート。
- 純ロジックのテストに加え、Foundry実機で型・スキーマ・標準適用・保存・再読込を確認する。
- 全テストの差分を確認。現在の既知の履歴入力テスト6件の失敗と、移行による新規失敗を区別する。

旧互換処理は、未移行パックや過去データの読込が不要と確認できるまで除去しない。移行後のデータを旧コードへ戻す際は、Gitのコード復帰とワールドの復元を別々に管理する。
