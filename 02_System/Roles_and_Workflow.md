# 役割分担とワークフロー

## 3者体制

| 役割 | 担当 | 責務 |
|---|---|---|
| ユーザー | プロジェクトオーナー | TNX ルール言語化、最終判断、動作確認、git push |
| チャット (Opus) | claude.ai | 設計議論、ルール引き出し、戦略判断、プロンプト組み立て |
| Claude Code | ターミナル CLI | コード調査、実装、ドキュメント作成 |

## 典型的なフロー

```
ユーザー (ルール・判断)
    ↕ 設計議論
Opus チャット (設計・プロンプト)
    ↓ プロンプト
Claude Code (実装・テスト・ドキュメント)
    ↓ PR/コミット
ユーザー (動作確認・承認)
```

## 設計 vs 実装の分担

| フェーズ種別 | Opus | Claude Code |
|---|---|---|
| 設計 (7, 9) | 中心 | 調査支援 |
| 実装 (0-B, 1-6, 8, 10-12) | プロンプト | 中心 |
| 実機確認 | — | ユーザー |

## セッション再開

| 空き期間 | 手順 |
|---|---|
| 2週間+ | CLAUDE.md + 現フェーズ TASKS 見直し |
| 1ヶ月+ | Opus に「再開します」と相談 |
| 3ヶ月+ | docs/ から現状再構築、新規チャット |
