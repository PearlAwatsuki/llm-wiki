## フェーズ詳細

### フェーズ2: User 移行 (完了)

プレイヤーの EXP・履歴・手札を User flag へ移行し、player Actor を廃止した。

- HUD ApplicationV2 化はここでは行わず、参照先の書き換えのみ実施
- KI-005 ベース連携決着 (`resolveEffectiveHandMaxSize` 新設)
- ActiveEffect 修正 (KI-020) は新設 ActiveEffect フェーズへ

→ [Phase_2_User_Migration.md](../01_Wiki/Phases/Phase_2_User_Migration.md)

### フェーズ3: シート ApplicationV2 移行 + CSS リファクタリング (完了 v0.4.0)

ApplicationV1 を完全廃止。全シート・HUD・ダイアログを V2 に移行した。
**CSS リファクタリング**（デッドコード除去・構造整理・命名統一・再利用性向上）を並走。
視覚デザインの変更はフェーズ4 に分離。

新設サブフェーズ: 3-2b（CSS 回帰修正）、3-CSS-0（CSS リファクタリング）

→ [Phase_3_Tasks_Detail.md](../01_Wiki/Phases/Phase_3_Tasks_Detail.md)

### フェーズ6: 未実装シート (完了 v0.7.0, 2026-06-14)

outfit 系 Item 11 種（weapon / armor / cyborg / ianus / tron / tap / vehicle / residence / housingArea / combiner / general）+ lifePath。
フェーズ3 + 4 のデザイン踏襲。キャストシート「アウトフィット」タブ整備を含む。
guest / troop / extra シートおよびキャストシート戦闘タブの実質的な内容（判定・CS・ダメージ等）は、
判定・神業システムの完成後にフェーズ11 で整備する（2026-06-14 決定）。

→ [Phase_6_Tasks_Detail.md](../01_Wiki/Phases/Phase_6_Tasks_Detail.md)

### フェーズ7-8: 判定システム

**7 = 設計**, **8 = 実装**。設計フェーズではユーザーとの議論で合意を固め、実装フェーズで Claude Code が実装する。
usage DataModel の pseudo-document 形式への全面再設計含む。8種の用途タイプ（skillCheck / abilityCheck / controlCheck / attack / declaration / damageBoost / damageReduce / modification）を独立 DataModel として実装。

### フェーズ9-10: 戦闘システム (新設 2026-06-16)

**9 = 設計**, **10 = 実装**。
攻撃用途（attack 用途タイプ）の固有フィールド（weaponRef・ダメージ種別 SPI・damage formula）、
ダメージカードフロー、AR（アクションランク）管理を含む。
フェーズ10 では guest / troop / extra の戦闘関連フィールドおよびキャストシート「戦闘」タブの
実質的な内容（攻撃実行・ダメージ処理・CS 管理等）も整備する。

### フェーズ11: ActiveEffect (位置確定 2026-06-16)

派生値計算パイプライン設計（`prepareDerivedData` オーバーライド）+ KI-020（handMaxSize ActiveEffect 修正層）。
判定・戦闘システムの実装完了後に行うことで、必要な修正の種類が全て出揃った状態で設計できる。
神業は他システムへの割り込み機構であり、本フェーズの ActiveEffect 層の上に構築する。

### フェーズ12-13: 神業システム

同上（7-8 と同じ設計→実装分割）。
本フェーズ実装時には ActiveEffect 層（フェーズ11）が使用可能である前提で設計する。

### フェーズ14: 残シート整備 (旧フェーズ11/12 統合)

guest / troop / extra Actor シートの最終整備（戦闘周辺を除く残フィールド）。
登場判定・シーンプレイヤー明示。
FVTT Scene 非依存の軽量サブシーン切替。
コンバットトラッカー改修。

### フェーズ15: 公開準備 (旧フェーズ13)

v1.0.0 リリース。

## UI フェーズ順序の意図

```
2: 所有モデル (User) 確立
 ↓
3: シート構造 V2 化 + CSS リファクタ（構造整理・再利用性）
 ↓
4: デザイン刷新（視覚設計）
 ↓
5: シート内容追加
 ↓
6: 未実装シート新規作成（3 の CSS 構造 + 4 のデザイン踏襲）
```
