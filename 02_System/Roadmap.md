> - **「戦闘システム」をカット進行＝コンバットトラッカー上書きと再定義**。ダメージ算出は判定システムに内包、ダメージ適用は AE の領分（ユーザー定義）。
> - **攻撃判定＋ダメージ算出は判定システムの未完部分**としてフェーズ12 に分離（v0.8.0 は能力/技能/制御まで）。

> - シナリオ進行管理（14）はシーン切替を抽象化し FVTT Scene／サブシーンの両対応。時間管理（15）はカット/シーン/アクト境界での使用回数リセット・持続失効。
> - **サブシーン（16）はマップレス概念戦闘の本命表示**。タクティクスコンバットは選択ルール（後日、FVTT Scene ベース）。
> - 辞典ブラウザ＋購入/改造判定（17）、登場判定（18）、TokenActionHUD 連携（19）を追加。
> - 神業（20）は AE・全システムの上。ルール言語化は早期着手、詳細設計＋実装は最後。

### フェーズ7-8: 判定システム（完了 v0.8.0, 2026-06-20）

**7 = 設計**（完了）, **8 = 実装**（完了）。usage DataModel を pseudo-document 形式（単一 UsageTemplate ＋ type フィールド、6種）に再設計。能力/技能/制御判定・コンボ・カード値計算・RL 要求フローを実装。用途シートを 基本/発動/効果 の3タブに整理し、発動パラメータ（対象/射程/目標値/変更不可※/対決不可）・参加技能からの自動入力・対決の読み取り表示・使用回数の消費（D&D 方式・遠隔消費・spent 管理）を実装。**攻撃判定＋ダメージ算出は判定システムの未完部分**としてフェーズ12 に分離（2026-06-20）。

### フェーズ9: ActiveEffect / 派生値計算パイプライン

`prepareDerivedData` 整備・実効値計算の一本化（現状の三重重複の解消）。N◎VA のダメージ適用＝チャート式効果累積の器。能力値/制御値の最終値0clamp（→ Character_Creation.md）。KI-020（handMaxSize AE 修正層）。効果の持続時間管理の基盤（→ Time_Management.md）。

### フェーズ10: 既存シート関連のやり残し総仕上げ（完了 v0.10.0, 2026-07-02）

フェーズ5・6 で先送り／未着手だった、既存シート（cast・各 Item）の表示・レイアウト・シート上操作を片付ける（「シート機能追加の最後の窓」）。スタイル技能のインポート時自動取得・取得まわり（EXP無効・取得数表示・レベル自動参照）、部位（part）のユーザー入力管理＋占有/超過表示、住宅アウトフィットのエリア表示、combatSpeed 入力 UI（KI-010）、キャスト戦闘タブ（表示中心。算出=12・進行=13 は持ち込まない）を含む。詳細は [Phase_10_Tasks_Detail.md](../01_Wiki/Phases/Phase_10_Tasks_Detail.md)。

> 旧定義は「アクターシート戦闘タブ」のみだったが、ユーザー意向（2026-06-25）で既存シートのやり残し全般へ拡張。新規アクターシート（guest/troop/extra）はフェーズ11 のまま。

### フェーズ11: guest / troop / extra シート（完了 v0.11.0, 2026-07-08）

guest / troop / extra Actor シートを整備（troop の heads＝HP的リソース、トループ級/エキストラのダメージ例外を含む）。残シートを1フェーズに統合。キャスト共通部品化・トループ／エニグマ／分身の本体・作成ルールを含む。詳細は [Phase_11_Tasks_Detail.md](../01_Wiki/Phases/Phase_11_Tasks_Detail.md)。

### フェーズ12: 攻撃判定 + ダメージ算出 + FS判定基幹（判定システムの完結・進行中 2026-07-08 着手）

attack 用途の起動・命中（既存判定フローに乗せる）、ダメージ算出（武器攻撃力＋カード数字＋修正−軽減、物理/精神/社会の3系統）、damageBoost/damageReduce。チャートのメカニクス枠組み＋効果文入力機能（→ Damage_Rules.md）。算出結果はフェーズ9 の AE 基盤で適用。フェーズ11 申し送りの heads 自動減算を含む。**FS判定（フォーカスシステム）の基幹**（データ構造・管理シート・進行値/カットカウンター・指定技能。→ [Focus_System.md](../01_Wiki/Game_Rules/Focus_System.md)。実判定の接続はフェーズ13）を追加（2026-07-08 ユーザー方針）。modification（改造）用途はフェーズ17（購入・改造判定）へ。

### フェーズ13: 戦闘システム（カット進行）

FVTT デフォルトのコンバットトラッカーを上書き。プロセス進行（セットアップ/イニシアチブ/メイン/クリンナップ）、アクション（ムーブ/マイナー/メジャー/リアクション/オート）、AR・CS 管理、リアクション（→ Combat_Flow.md）。マップレス概念戦闘がコア、タクティクスは選択ルール（後日）。

### フェーズ14: シナリオ進行管理

アクト＝OP/リサーチ/クライマックス/ED のフェイズ管理、シーン開始・終了トラッキング、**シーン切替の抽象化**（FVTT Scene／サブシーンのバックエンドを差し替え可能に）、境界イベント発火（→ Scenario_Progress.md）。

### フェーズ15: 時間・使用回数管理

カット/シーン/アクト境界での使用回数リセット・効果の持続時間失効（→ Time_Management.md）。フェーズ13 のカット境界・フェーズ14 のシーン/アクト境界を購読。行動回数制限は自動化しない。

### フェーズ16: サブシーンシステム

マップレス概念戦闘の本命表示（常駐トークン盤面・登場/退場操作）。シーン切替抽象の上に乗る表示層。FVTT Scene バックエンドはタクティクスコンバット選択ルールとセットで後日。

### フェーズ17: 辞典ブラウザ + 購入・改造判定UI

D&D の Compendium Browser 相当。ドロップエリアクリック起動。購入判定（信用技能・購入値）・改造技能判定はアウトフィット自体を対象とするため辞典ブラウザと連携。

### フェーズ18: 登場判定

シーン開始時の登場判定（危険値・使用技能）。チームによる判定免除。サブシーン盤面の登場/退場操作と連携。

### フェーズ19: TokenActionHUD 連携

Token Action HUD for Tokyo N◎VA。シートを開かず技能・能力・攻撃・神業を起動できるようにし、判定の煩雑さを解消する。

### フェーズ20: 神業

AE・全判定・戦闘・進行管理の上に構築（割り込み機構）。ルールの言語化は早期着手、詳細設計＋実装は最後。

### フェーズ21: 公開準備

v1.0.0 リリース。
