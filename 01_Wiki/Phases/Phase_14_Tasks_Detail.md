2. **登場状態＝Actor のフラグ**（ユーザー裁定）。登場するのはプレイヤーでなくキャラクター。ゲスト・トループ・エキストラも同じ器で持ち、RL 側に登場判定は不要（RL が直接切替＝トークンの表示切替が導線・14-5 で双方向同期）。**対象化ゲートは作らない**（2026-08-08 ユーザー裁定で撤回。「登場しているキャラクターしか対象にできない」はルールの説明であって実装指示ではなく、**非登場を対象にできる特技が存在**する。システムは可否を制限しない原則＝技能組み合わせと同じ——が対象選択にも適用される。当初記述「ゲートは target-resolution へ一点実装」は Code の誤り）。登場状態は表示・参照のための状態。
3. **シーンプレイヤーか否か＝User flag**（ユーザー裁定）。「そのシーンのメインのプレイヤー」というプレイヤー側の指定のため。アクセスカード「シーン・プレイヤー」による明示（フェーズ5 申し送り）と連動。

### 申し送り詳細: 社会ダメージ系の自動化（設計保存・2026-08-23 → フェーズ15）

2026-08-23 に Code が調査・設計提示。当初「登場判定を扱うフェーズ＝14 で自動化」とされたが、**同日ユーザー裁定で「時間に関わる部分なので次フェーズ」＝フェーズ15 で実装**（「社会ダメージの設計は残しておいて次フェーズへの申し送りに含めてください」）。確定済みのルール裁定は正本 [Appearance_Check](../Game_Rules/Appearance_Check.md)「盤面表現」にある: **逮捕令状（強制退場）はチームから抜けてから退場**（退場連動に乗せない・2026-08-23）。

**調査結果（2026-08-23 時点・damage-chart.mjs）**:

- 社会チャート21種の大半は宣言的に符号化済み（skillBlock・bountyBlock・inflicts・derivedDamage）で負傷適用時に効いている。
- 未自動化は3つ: 盗聴 soc-10（物語効果＝自動化対象外の裁定済み）・**逮捕令状 soc-17**（即座に退場・次シーン登場不可）・ID剥奪 soc-20（citizenRank に機構的消費者が無くランク機構未実装）。
- soc-6/7/8（信用失墜・スキャンダル・信頼喪失）は sceneDeferred（休眠→次シーン発火）の**休眠側のみ**実装済みで、発火機構（sceneFired を立てる側）が未実装＝**現状は永遠に休眠**。

**設計案（未承認・15 着手時に再提示して承認を得る）**:

1. **逮捕令状**: 負傷 AE の付与を activeGM が購読 → ①チームから離脱（leaveTeam）→ ②退場（setAppearing(false)・退場連動に乗せない＝2026-08-23 裁定）→ ③登場不可の期限フラグを立てる。期限＝シーン番号（逮捕シーン+1・sessionState.sceneNumber との比較で自然失効・アクト終了でクリア）。登場判定は期限内なら **forcedFailure**（理由「逮捕令状」を成否バナーに明示・判定自体は振れる＝手札交換の権利は残る・既存機構）。RL による登場はゲートを通らない（登場：不可と同じ扱い）。
2. **sceneDeferred の発火機構**: tnxSceneStart（14-2 実装済み境界イベント）を activeGM が購読し、休眠中（pendingScene）の負傷 AE に sceneFired を立てる＝次のシーン開始から効く。15 本体の境界イベント購読（失効・リセット・回復）と同居できる。
3. **ID剥奪**: ランクを消費する機構（フェーズ17 購入判定）まで見送り推奨（YAGNI）。
4. **盗聴**: 対象外（裁定済みのまま）。

**未裁定（15 着手時に確認する2点）**: ⓐ逮捕令状の登場不可の範囲＝「退場したシーンの残り＋次シーン」の推奨可否（次シーンだけだと同シーン中の振り直しで逮捕が事実上無効になるため） ⓑ治療しても期限は残るか（「次シーン登場不可」は時限効果であり、逮捕令状という負傷の持続とは別という読み＝Code 推奨）。
