# Phase 5: 修正・軽微な機能追加

## 目的

フェーズ4（デザイン刷新）完了後に残った既存シートのバグを修正し、
判定システム設計（フェーズ7）以前に実施可能な軽微な機能追加を行う。
新規シートの追加はフェーズ6に委ねる。

## スコープ外

- 新規シートの作成（フェーズ6）
- 判定システムの設計・実装（フェーズ7-8）
- 神業システム（フェーズ9-10）
- ActiveEffect パイプライン整備（ActiveEffect フェーズ）
- 用途タブ（usage-list）の完成（判定システム依存）

---

## サブフェーズ

### 5-0: 既存シートの表示バグ修正

最優先。動作確認済み機能の回帰修正が中心。

- [ ] コンテキストメニューが動作しない問題の調査・修正
- [ ] キャストシートへのアイテムドロップが想定通り動かない問題の修正
- [ ] その他、実機で確認されている表示・操作バグの修正

### 5-1: 開発者ツール警告の解消

- [ ] コンソール上の警告を全て調査・分類
- [ ] 修正可能なものを順次修正（FoundryVTT コア起因のものは記録のみ）

### 5-2: 他プレイヤーへのカード渡しダイアログ改修

現状: 渡すキャラクター（Actor）を選択する形になっている。
変更後: ユーザー（User）を選択し、そのユーザーの手札に渡す形にする。

- [ ] ダイアログの選択肢を Actor 一覧 → User 一覧に変更
- [ ] カード移譲ロジックを User flag ベースに修正

### 5-3: プレイヤーの手札エリア表示機能

- [ ] 設計・実装方針の確認（どのシート/HUDに表示するか）
- [ ] 手札エリアUI実装

### 5-4: カードセットアップをゲーム設定へ移行

現状: シナリオ作成ウィザード（TnxScenarioSettingWizard）内でカードのセットアップを行っている。
変更後: ゲーム設定（Settings）からいつでも実行できる形にする。

- [ ] 設定項目の設計・ユーザー承認
- [ ] ウィザードからの移行実装

### 5-5: スタイル・技能への識別キー追加

DataModel フィールド追加のため §4.3 事前承認が必要。

- [ ] 識別キーの仕様をユーザーと確認（型・用途・制約）
- [ ] DataModel 承認後: style / styleSkill / generalSkill の DataModel に識別キーフィールド追加
- [ ] 各シートのUI追加

### 5-6: キャストシート詳細タブ・プレイヤーシート詳細タブ UI

- [ ] 詳細タブに追加すべき内容の確認（KI-010 combatSpeed UI 含む）
- [ ] キャストシート詳細タブ UI 実装
- [ ] プレイヤーシート詳細タブ UI 実装
- [ ] キャストシート判定タブ：判定システム設計前のため、骨格のみ配置（実装はフェーズ8）
