# Phase 11: guest / troop / extra シート

> ✅ **完了（2026-07-08・v0.11.0）**。全サブフェーズ（11-0〜11-7）完了・実機確認済み（残作業なし＝2026-07-08 ユーザー明言）。タグ付け・push はユーザー。
>
> 未整備の Actor シート（guest / troop / extra）を、キャスト共通部品化のうえで実装する。トループ／エニグマ／分身の本体・作成ルールもここで確定・実装する（Roadmap: 残シートを1フェーズに統合）。依存は判定システム（完了済み）とキャスト共通部品化のみ。神業（フェーズ20）への依存はない。

## 目的

全 Actor type にカスタムシートを行き渡らせ、「シートを持たないアクター」を解消する。guest はキャストの縮退形（共通部品の再利用）、troop は heads＝HP的リソースを持つ集団、extra は名前中心の最軽量アクターとして、それぞれのルール上の性格に合ったシートを作る。

### 11-6: トループ取得技能の本体連携（NPC取得用途）

〈分心〉→エニグマ、〈分身〉→分身の本体連携。**設計確定（2026-07-04・ユーザー承認前の全体まとめ記録。ルール正本は [Troops.md](../Game_Rules/Troops.md)）**:

**用語・前提**: トループ級=トループ/エニグマ/分身の総称。エキストラは二重表現（アウトフィット=管理形態・アクター=舞台上の実体）。トループ級は**事前作成が前提・複製機能は作らない**。エキストラアクターは共有（個人専用は手動で新規作成+紐づけ替え）。

**データ構造（一括承認対象）**:
- usage に `npcAcquire`「NPC取得」タイプ+**モード選択**（エキストラ/トループ/エニグマ/分身の4択・参照先からの導出はしない）+エキストラモード用の取得アイテム参照（uuid+name 配列）
- troop に**所有者アクター参照**（呼び出し元。経験点の出所の紐づけの正本＝設計の要）
- アウトフィット（小分類エキストラ）に**エキストラアクター参照**
- 作成可能アイテム: トループ取得技能（unique="troopAcquire"）とアウトフィット系。モードはアイテム種で絞らない
- フェーズ10 の autoAcquireActors は残置するが NPC取得フローでは**使わない**（対象解決は所有者逆引き）

**使用時フロー**:
- エキストラ: 判定なし。派生データ取得（isDerivedData）+エキストラアクターのトークン配置を**同時**に
- トループ/エニグマ: 通常判定（目標値なし）→対象の heads=達成値を転記+トークン配置
- 分身: 通常判定・目標値10（**達成値10以上で成功**）→成功時のみ配置。sourceName は所有者参照から自動設定（手入力も残す）
- 対象解決: 使用者を所有者とするトループ級をワールドから逆引き+種別一致（複数該当は選択ダイアログ）
- **レベル転記**: 取得技能のレベルをそのままトループ級側レベルへ（トループレベル/エニグマレベル。敵対トループは手入力のまま）
- 権限: dnd5e 踏襲＝トークン配置権限が無ければ配置不可（警告のみ・委譲機構なし）
- 配置UX: dnd5e 実挙動踏襲＝トークン半透明プレビューのカーソル追従・左クリック確定・右クリックスキップ・グリッドスナップ（Shift解除）

**経験点算入（11-6 に含む・フェーズ分割しない）**:
- 対象: ①スタイル技能の**取得と成長** ②アウトフィットの取得 ③一般技能の成長（初期習得=Lv1 無償）。レベルは独立消費対象でない（取得技能側で計上済み）
- 集計: 既存 EXP 機構を書き換えず、所有者の消費計算時に所有トループ級を逆引き合算。再計算トリガ=トループ級側アイテム作成/更新/削除・所有者参照変更
- 表示: (a)所有者キャストの内訳に所有トループ級分の小計行 (b)**トループ/エニグマのシートに取得元キャストの経験点（残量）を表示**（分身には出さない）
- 所有者がゲストの場合は算入なし（ゲストは経験点管理を持たない）

**シート/UI**: 用途シート=モード選択+モード別表示（分身は目標値欄なし・10固定）／troop シート=所有者参照ドロップエリア・エニグマ時「エニグマレベル」ラベル切替・所有者経験点表示／小分類エキストラのアウトフィット=エキストラアクター参照ドロップエリア

**実装順**: ①DataModel 一括（npcAcquire+モード+取得アイテム参照／消費設定配列／troop 所有者参照／小分類エキストラの extraActorRef）+スキーマテスト → ②消費先設定（自動スキャン全廃・ダイアログ・全用途タイプ配線） → ③分身の使用回数共有（消費先解決に本体差し替え） → ④NPC取得の作成導線・用途シート → ⑤対象解決・判定連携・転記（heads/レベル/sourceName） → ⑥トークン配置 → ⑦EXP 算入+表示 → ⑧記録・テスト・両リポジトリコミット

**追加設計1: 分身と本体の使用回数共有（2026-07-04 Code 提案・実現性コード検証済み）**: 本体側カウンターを唯一の正本とする**参照消費方式**。自動消費経路は planUsesConsumption/_consumeUses の1系統のみ・アクターシート側に残数表示なし（コード確認済）のため、**解決関数1つ**（分身＋所有者参照あり→識別キー一致の本体側アイテムへ差し替え）を消費・ダイアログ残数の両方に通す。分身直下のアイテムシートは使用回数ブロックを「本体と共有」表示で入力無効化。照合失敗（キー空）は名前一致→ローカル消費＋警告。権限は同一プレイヤー所有で成立。

**追加設計2: 用途ごとの消費先設定（2026-07-04 ユーザー提供・確定）**: 現状「用途から判定を行うと親アイテムに使用回数制限があれば自動消費」となっている紐づけを**廃し**、**「どの回数から」消費するかを用途ごとに設定**できるようにする。UI は **D&D 5e の消費先（Consumption）設定機能を踏襲**（行の追加/削除・消費先種別=親アイテム/同アクターの特定アイテム/神業 usageCount・**消費量は可変**・既定1）。親アイテムの使用回数を消費に設定すれば従来どおりの挙動。例: 技能アイテムの用途から、同アクター所属の特定の消費アイテムの残数を自動消費／**神業の使用回数にも同様にアクセス**できる。
- **遠隔消費（コンボ参加技能の自動消費）も全廃**（2026-07-04 ユーザー確定）: **全ての消費は用途の消費設定からのみ発生**する。使用回数制限のある技能を組み合わせに参加させる場合、**その技能の使用回数を消費するよう用途に手動で設定する必要がある**（手間の増加はユーザー了承済み）。自動スキャンは一切残さない。
- 既存 check 用途の互換: 消費設定未設定は「親アイテムの使用回数×1」相当の既定として扱う（親に isLimit 無しなら無消費=従来同一）。check 用途は判定実行時に消費確定（キャンセル時非消費・確認ダイアログ流用）、他用途タイプは「使用」時に消費。

**追加設計3: 発動タブの自動入力拡張（2026-07-06 ユーザー承認）**: ①適用タイミング=**作成時に一度自動適用＋既存ボタンで明示的に再導出**。コンボ変更でのライブ追従はしない（手動調整の黙殺・設定の不可視変更を避ける） ②**消費行も導出対象に含める**——導出規則=親×1＋使用回数制限（isLimit）つき参加技能それぞれ×1。ボタン押下時は消費行を導出結果で置き換え（既存自動入力と同じ明示的上書きの意味論）。**線引き: 全廃したのは実行時の隠れた自動スキャンであり、これは設定欄への可視の入力補助**——実行時の権威は consumeTargets のみで不変。設定失念による消費漏れ（ルール違反状態）を防ぐ。スコープ=フェーズ11 内の追補（v0.11.0 に含む）。**実装完了（2026-07-06・本体 db1b532・テスト1068 green・実機確認待ち）**: deriveUsageAutoFill 共通化（作成時とボタンで共用）・deriveConsumeTargets（純関数・テスト付き）・check/attack/npcAcquire の作成時一回適用・辞典インポートの自動「判定」用途にも消費既定「親×1」を明示。
