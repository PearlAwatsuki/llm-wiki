### 12-3: ダメージ算出（算出+適用配線+damageBoost/damageReduce）

- **権限委譲（2026-07-08 実機で発覚→即修正）**: 適用（BS 付与=ActiveEffect 作成・troop の heads 減算）は対象の**所有者権限**が要り、攻撃側 PL のクライアントでは権限エラーになる。所有権のないクライアントからは `damageApply` ソケットで GM に委譲する（attackUpdate と同型）。対象側 damageReduce の消費プランも委譲ペイロードに載せて GM 側で適用。GM 側は damageApplied 済みなら何もしない（二重適用防止）・複数 GM 接続時は activeGM のみ実行。GM 不在時は消費前に中断して警告（攻撃側の資源だけ減る事故を防ぐ）。本体 `831345b`。
- **結果カード・プレビューの完成（2026-07-08 ユーザー指摘→即対応）**: 当初 Code は結果チャットを素の h3+p で出し内訳も示さず「完了」と報告した=誤り。`damage-result.hbs` を新設（check-result 意匠・台帳形式で ダメージカード/攻撃力/FA/boost・reduce 各行/手動修正/軽減内訳/報酬点/スタン/最終+参照段/適用結果 を全行表示）。算出ダイアログに 12-1 設計どおりのライブプレビュー（最終値・参照段・負傷名/heads/消滅/適用不可）を追加。用途 formula は開いた時点で事前評価し確定値を行内表示（自由文は「手動修正で反映」明示）。委譲時も同カードを GM が投稿。本体 `8bb8ae1`。
- **ダメージカードの自動確定=誤り（2026-07-08 ユーザー指摘）→ カードプレイ起点に再設計・実装済み**: Code は Damage_Rules の誤記録行（命中判定カードの流用）を根拠に自動確定で実装していた。正: **命中判定とは別のカードを出すことがトリガー**（判定と同じ考え方）・**適用ボタンはチャットカード側**・**ダイアログは手動修正値の入力のみ**・**ジョーカー=ワイルドカード**・**複数枚は合算**（カブキ〈ラッキーストライク〉等）。実装（本体 `055aa13`）: 攻撃カード「ダメージカードを出す」→最小ダイアログ（damageBoost・手動修正・スタン）→[手札から出す]/[山札から1枚めくる]=確定→**ダメージ・チャットカード**（台帳+攻撃側合計・ライブ描画）→[カードを追加で出す]（合算・枚数検証なし）／[ダメージ適用]（対象の操作者または RL）→**防御側の軽減ダイアログ**（防御力+パリー受け値自動・damageReduce・社会の報酬点軽減・プレビュー）→型分岐適用→カード上に軽減内訳+最終ダメージ。ダメージカードは判定でないため判定ルール（山札絵札ファンブル・21固定）は不適用=N◎VA 数字のみ。適用者=対象の所有者のため damageApply（GM 適用代行）ソケットは不要になり削除、フラグ更新のみ damageUpdate で委譲。`novaDamageCardValue` 廃止・攻撃カードのダメージカード行削除・flipFromDeck はカードを返すように変更。
- **手札プレイ=HUD 直接クリックに統一（2026-07-08 ユーザー指摘→修正 `c6a2faf`）**: 当初 Code が付けた「手札から出す」ボタン+カード選択ダイアログは、判定の操作系（HUD の手札を直接クリック）を踏襲しない独自 UI=誤り。damage-flow に待ち受け状態（TnxCheckFlow._context と同型）を追加し、ロールダイアログを開いたまま手札は HUD クリック・山札はダイアログのボタンで出す。[カードを追加で出す]も同方式。HUD `_onPlayCard` は判定待機→ダメージカード待機→通常プレイの順に分岐。**手札からカードを出す操作は今後も必ず HUD 直接クリックで統一する**。
- **UI 指示（2026-07-08 ユーザー・D&D 5e 踏襲）**: チャットカード上のボタンは**全幅・縦積み**（.tnx-chat-btn 全幅化・攻撃カードのボタン行縦積み）。アイテムロール時の**用途ピッカーは縦積み**（3〜4 用途で破綻する横並びは不可。V1 の .dialog-buttons セレクタ残骸で縦積み CSS が死んでいたのを修復+用途種別アイコン追加）。本体 `92d0b98`。
- **制御判定要求の本式化（2026-07-08 ユーザー指示→完了）**: フェーズ9 仮置き（素の p+button・クリックで山札自動1枚→即比較の独自処理）を全廃し、checkRequest 標準機構（check-request.hbs）で投稿。「判定する」→ 通常の制御判定フロー（手札から出す・山札判定・失敗する権利）をそのまま起動し、完了継続 ctx.controlNegate が成功=無効/降格・失敗=継続の適用のみ行う。本体 `62e35dc`。
- **攻撃用途エディタの系統別表示・攻撃力表記（2026-07-09 ユーザー指摘→修正 `1206d0b`）**: 用途シートは submitOnChange 後に再描画せず、系統を精神/社会に変えても物理用の武器・ダメージ種別欄が残り設定できてしまっていた→系統変更で即再描画。攻撃力の表示が「I0」連結表記だった→アウトフィットの `_attackLabel`（種別+符号つき数値=**I+4**）踏襲に統一（`formatAttackLabel` 純ロジック+テスト。攻撃カード・ダメージカード台帳・ロールダイアログ）。
  - **公開・ライブ書き換え・再判定バグ（2026-07-08 ユーザー指示→修正 `864fd2d`）**: 要求カードは whisper でなく**全体公開**。帰結（無効化/降格/継続）は別カードを出さず**要求カードの対象行をライブ書き換え**（成功/失敗+帰結。ユーザー提案採用・素の tnx-condition-result 通知は廃止）。再判定できたバグの根本原因は emitCheckResult が socket 送信のみで **GM 自身の判定が自クライアントに届かず結果未記録**だったこと（socket.emit は自分に届かない）。GM はローカルで直接処理するよう修正=checkRequest 全経路（RL 判定要求含む）に効く。
