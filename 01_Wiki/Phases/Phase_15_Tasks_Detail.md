## 確定した設計判断（2026-08-29 計画議論）

ユーザーの明示裁定と Code の提案採用を区別して記す。

1. **適用対象は常に登場中のアクター**（ユーザー裁定）。加えて**退場＝そのキャラクターにとってのシーンの終わり**として扱い、「シーン中」の効果は境界を待たずその時点で畳む。根拠は「**一度退場したら再登場はできない**」（同日裁定・→ [Appearance_Check](../Game_Rules/Appearance_Check.md)）。
2. **シーン境界は `tnxSceneEnd` ではなく退場を購読して駆動する**（Code 設計判断）。`endAct` もシーン切替も `_applySceneExit()`（全員退場）を**先に**走らせてから境界イベントを発火するため、`tnxSceneEnd` の時点では既に誰も登場していない。退場を購読すれば「シーン終了＝全員退場」で全員に届き、かつ上記1の「途中退場はその場で畳む」が**同じ一本の経路**で成立する。`tnxSceneEnd` は購読しない（二重適用になるだけ）。
3. **アクト終了の後始末は対象を絞らない**（Code 判断・当初 Code が「登場中が空になる」ことを問題として持ち出したが**懸念自体が空**だった）。アクトに参加していないアクターには消費も故障も残存ダメージも無く、リセットは no-op になるため、走査対象を絞る意味がない。
4. **自動適用のみ・チャット報告はしない**（ユーザー裁定）。BS 回復・使用回数リセット・効果失効はいずれも黙って適用する。
5. **例外: 邪毒のクリンナップダメージだけは既存のダメージ適用経路に乗せる**（Code 提案）。これは回復や後始末ではなくキャラクターが受ける肉体ダメージであり、山札からの1枚とチャート適用を伴う。他のダメージと同じ見え方をすべきもので、4 の「報告なし」の対象ではない。
6. **萎縮・憎悪の「メインプロセス終了時に自動回復」は、その BS を受けている本人のメインプロセス**（ユーザー裁定）。Time_Management の「メインプロセス中」効果（誰のかを問わない）とは主語が異なる。
7. **「治療するまで回復しない」BS は、ダメージを治療したら回復できるようになる**（ユーザー裁定・Bad_Status に既出の再確認）。実装は**元の負傷 AE がまだ生きているかで導出**し、フラグの立て落としをしない（Code 設計判断）——負傷が残っている間だけ境界回復をスキップし、治療されて負傷が消えれば次の境界で通常どおり回復する。治療側に「BS を消す」責務を持ち込まないので、「BS の回復 ≠ ダメージの治療」（Bad_Status の不変条件）を崩さない。
8. **逮捕令状（soc-17）の期限は負傷 AE の生存に還元する**（ユーザー裁定＋Code 設計判断）。ユーザー裁定は「効果が『次のシーンに』なので次のシーンが終われば治療されて消える／治療されれば登場可能になる」＝**次シーン終了で自然消滅し、治療されれば即座に登場可能**。両方向とも「負傷 AE が生きているか」に還元できるため、期限を独立したフラグで持たない。14 の未裁定ⓐ（登場不可の範囲）は、**同シーン中の再登場が不可能である以上「同シーン中の振り直しで逮捕が無効になる」という Code の懸念が成立しない**ため、次シーンのみで確定（→ Appearance_Check）。
9. **効果の持続時間は、効果設定シートの「持続時間」タブにプルダウンを追加して持たせる**（ユーザー裁定「そもそも持続時間タブがあるはずなので、そこにプルダウンを追加する。上書きでも良い」）。ネイティブのラウンド/秒は本システムでは死んでいる（`worldTime` に一切触れないため実時間で減る経路が無い）ので上書きしてよい。**選択肢は Time_Management の時間単位＋無期限の5つだけ**——当初 Code が入れた「治療まで」は 2026-08-29 のユーザー指摘（「存在意義が理解できません」）で削除した。境界の判定で「アクト中」と挙動が完全に同一なうえ、手で組んだ効果に「治療する」操作が無く、本来の「治療まで」BS は下記7の導出で扱うため。
10. **行動を支払って回復する BS は戦闘タブが主経路**（ユーザー裁定）。状態バッジのコンテキストメニューにも条件成立時に出してよいが、主経路は戦闘タブ。理由は、これらが「状態を編集する」操作ではなく「**アクションを支払って回復する**」操作だから（CS・AR・タイミング別の起動チップと同じ面に属する）。
11. **放棄は「行動の放棄というアクションを行ったもの」とみなす**（ユーザー裁定）。メジャーの放棄＝アクションランクの消費。したがって既存のメジャー行使と同じ記帳（`markMajorAction`）に積み、プロセス終了時に一般則どおり AR−1＋CS カレント 0 が適用される。
12. **放棄はその BS を回復するための支払いであって、メインプロセス単位の共有された事実ではない**（ユーザー裁定「あくまでも『特定の BS を回復するために放棄』」）。捕縛のために放棄したメジャーは邪毒には効かない。※Code は当初「1メインプロセスにメジャーは1つだから1回の放棄で両方に効く」と設計したが誤りとして撤回。
13. **邪毒の宣言は一度で、マイナーの放棄時点でメジャーの放棄まで含む**（ユーザー裁定）。二段のボタンにしない。これにより「マイナーだけ放棄してプロセスが終わり、マイナーを無駄に捨てて邪毒も回復しない」という行き止まりが構造的に作れなくなり、プロセス単位の途中状態を持つ必要も消える。
14. **重圧・捕縛の回復は「全て」**（ユーザー裁定）。ボタン1つで、その時点で受けている重圧／捕縛を全部回復する。したがって **1 BS 種別 = 1 ボタン**。

## 境界と適用内容

| トリガー | 発火元 | 適用 |
|---|---|---|
| メインプロセス開始 | `tnxProcessStart(phase:"main")` | 恐慌の回復（本人のメインの直前） |
| メインプロセス終了 | `tnxProcessEnd(phase:"main")` | 「メインプロセス中」効果の失効（誰のメインでも）／萎縮・憎悪の回復（**本人**のメイン終了のみ） |
| クリンナップ | `tnxProcessEnd(phase:"cleanup")` | 酩酊（大→小に変換・小→消滅）／電子妨害の回復／**邪毒の継続ダメージ** |
| カット終了 | `tnxCutEnd` | 「カット中」効果の失効・「カット中 N 回」のリセット |
| カット進行終了 | `tnxCutProgressionEnd` | 気絶／失神の回復・**BS の全解除**（Bad_Status 共通ルール） |
| **退場** | `setAppearing(actor, false)` | そのキャラのシーン終了＝「シーン中」効果の失効・「シーン中 N 回」のリセット・BS の全解除・仮死/昏睡の死亡判定 |
| シーン開始 | `tnxSceneStart` | 社会ダメージの「次のシーン」効果の休眠解除（`sceneFired` を立てる） |
| アクト終了 | `tnxActEnd` | 抹殺の適用 →「アクト中」効果の失効・アクト回数と神業のリセット・消費アイテムの個数回復・故障/破壊の解除・残存ダメージ消去・「治療まで」BS の解除（＝負傷ごと落ちる） |

BS の全解除（カット進行終了・退場）は Bad_Status の共通ルール「BS はカット進行が終了するか、シーンが変われば全て解除」に対応する**背板**であり、個別の回復タイミング（クリンナップ等）はそれより早く効く前倒しの回復として扱う。「治療まで」BS だけがこの背板から外れ、アクト終了まで残る（上記の設計判断7）。

## 中核設計

**新設2ファイル**（純ロジックとグルーの分離）:

- `scripts/module/time-boundary-logic.mjs` — 純ロジック（Foundry 非依存・TDD）。境界の種類と対象の状態から「何を失効させ・何をリセットし・何を回復するか」を決めて返す。
- `scripts/module/time-boundary.mjs` — Foundry グルー。フックの購読・対象アクターの走査・一括 update。実行は **activeGM のみ**（既存の appearance-state / info-gathering と同じ作法）。

境界ごとの手続きを各機構に散らさず購読口を一本に保つのが要点。「何が・いつ・どう畳まれるか」は宣言側（`CONDITION_KINDS` のレジストリ／`uses.type`／効果の持続欄）に置き、ディスパッチャは宣言を読んで適用するだけにする。境界が増えても購読口は増えず、適用順序も一箇所で決まる。

**効果の持続時間の器**: 効果設定シートの持続時間タブに TNX の持続を選ぶプルダウンを追加する。値は なし（無期限）／メインプロセス中／カット中／シーン中／アクト中。保存は既存の注入 UI と同じく `flags.tokyo-nova-axleration.*` の**フォーム送信**（即時 `setFlag` は未保存状態を巻き戻すため使わない＝2026-07-13 の是正）。効果一覧の「効果時間」列は現在ネイティブの `duration.label`（本システムでは常に空）を出しているので、この値の表示に差し替える。FS の支援 AE（カット終了で失効）が最初の実インスタンス。

**行動を支払う BS の回復 UI**（戦闘タブ）: 1 BS 種別につきボタン1つ。押した時点で回復まで行く（別の回復ボタンは出さない）。

| BS | ボタン | 押したときの効果 |
|---|---|---|
| 重圧 | マイナーの使用 | 受けている重圧を**全て**回復（AR に影響なし） |
| 捕縛 | メジャーの放棄 | 受けている捕縛を**全て**回復・`markMajorAction` に積む |
| 邪毒 | マイナー・メジャーの放棄（一度の宣言） | 邪毒を回復・`markMajorAction` に積む |

押せるのは**カット進行中だけ**（Code 設計判断）。カット進行外は AR という原資自体が存在せず（付与型・戦闘タブも「—」表示）、支払いが成立しないため。行動回数の制限ではなく原資の有無による区別。無効表示は既存の `applyTriggerDisable`（グレーアウト＋クリック不能・`scripts/module/ui-trigger-disable.mjs`）を再利用する。

**帰結（卓の体感）**: これらの回復はすべて「自分のメインプロセスで」行うものなので、カット進行外のシーンでは重圧・捕縛・邪毒を手動回復できない。その場合はシーンが変わるまで残る（BS の全解除が最後には落とす）。

**逮捕令状（soc-17）**: 負傷 AE の付与を activeGM が購読し、①チームから離脱 → ②退場（**退場連動には乗せない**＝2026-08-23 裁定）→ ③以後、その負傷 AE が生きている間は登場判定を `forcedFailure`（理由「逮捕令状」を成否バナーに明示・**判定自体は振れる**＝手札交換の権利は残す既存機構）。負傷 AE は次シーンの終了で自動失効し、治療で消せば即座に登場可能になる。
