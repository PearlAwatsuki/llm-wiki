## 設計の中心 — 神業由来の印

神業は**ゴールデンルール「RL の絶対権限」のひとつ下に位置する、非常に強制力の強いルール**である（2026-09-03 ユーザー言語化）。この位置づけの再現がフェーズ17 の設計そのものになる。

挙動を**既存の用途の器で表現する**（Code 決定 2026-09-03・ユーザーは「用途を使わなければならないわけではない、そこは Code の仕事」として一任）。必要なのは、**その用途が神業のものであるという印**である。

**用途を使う理由**:

- **器が二重にならない**。神業が実際に使う設定——対象・射程・使用回数の消費・適用効果——はすべて用途が既に持つ。射程は飾りではなく、《神の御言葉》＝中距離まで・《死の舞踏》＝近距離まで・《とどめの一撃》＝至近は対象外、と効果文に書かれていて実際に効く。神業専用の器を作ると同じものが2つになる（§4.3）。
- **複数の使い方をする神業がある**。《制裁》は社会ダメージの付与と治癒の両方ができ、《暴露》も同じ。1アイテム1挙動ではないため、挙動をアイテム側の欄に置くと表現できない。用途が複数持てる器であることがそのまま効く。

**ただし用途は前提条件にしない**（同 Code 決定）。神業は**用途が0件でも機能する**——ロールすれば使用回数を消費し、神業書式のカード（効果文＋条件）が出る。これで《天罰》《脱出》《真実》《超越品》《電脳神》のように「宣言して卓が裁定する」神業は用途の投入ゼロで完成する。打ち消し・防御・ダメージ・干渉・派生といった**固有の挙動だけ**が、用途を作ってフラグを立てて初めて乗る。

- **印の出どころ**: 用途の親アイテムが `miracle` 型であること。専用フィールドは設けない（判定条件を二重に持たない）。**用途が0件でも印は立つ**——印はアイテムの型から来るのであって用途からではない。
- **印は結果へ運ばれる**: 起動文脈 → チャットカードのフラグ → ダメージのペイロード → 付与された効果 → ダメージ由来の状態。運ばれなければ、後段は「これは神業由来だ」と知りようがない。
- **印が効く場所**（下位のルールを受け付けない）:

| # | 場所 | 神業由来のとき |
|---|---|---|
| 1 | ダメージ算出 | 防御力・受け値・軽減 AE・報酬点軽減を通さない |
| 2 | リアクション | 対決の入口を出さない（避けられない） |
| 3 | 治療・回復 | 神業由来の状態は通常の回復用途では除去できない |
| 4 | 打ち消し・防御 | 神業由来のものは、神業でのみ打ち消せる・防げる |

神業を止められるのは神業と RL の裁定だけである。

## 確定した設計判断

ユーザー明示裁定と Code 提案採用を区別して記す。

0. **挙動は用途で表現し、用途は前提条件にしない**（Code 決定 2026-09-03。理由は上記「設計の中心」）。
1. **用途タイプは新設しない**（Code 決定・ユーザーは Code へ一任 2026-09-03）。打ち消し・防御は「神業を使ってから対象のカードの該当箇所をクリックする」動きで、既存の「判定を修正」「ダメージを修正」と同型のため、**宣言用途のフラグ**で表す。用途タイプは「技能クリック以外から起動して、使える技能を識別する必要がある行動」に付けるものであり、神業は常に神業アイテム自身から起動するので識別が要らない。
2. **打ち消しの実装形**（ユーザー裁定 2026-09-02）: **判定に対しては失敗させる／宣言に対しては効果の適用をキャンセルする**の2つで実現する。判定を丸ごと無かったことにする形はルール上可能だが実装しない。
3. **防御神業は打ち消しと別動作**（ユーザー言語化 2026-09-02）: 適用そのものを防ぐ。範囲は《難攻不落》＝一回の攻撃や神業まるごと（**範囲攻撃なら全員分**）、《守護神》《友情》＝**選んだ1人だけ**。
4. **悪影響の機械判別は不要**（ユーザー指摘 2026-09-03）: 何を防ぐか・何を解除するかは**使用者が選ぶ**。効果の符号や付与元から悪影響を導く機構は作らない（検討していた案A/案Bとも撤回）。
5. **ダメージを与える神業は、算出を経ず結果を直接指定する**（Code の読み・効果文が根拠）。《制裁》の「社会戦ダメージチャートの中から好きなものを選ぶこと」が示すとおり、これらは値を計算せず結果を選ぶ。［完全死亡］［精神崩壊］も同様で、任意ダメージのときだけチャートの行を選ぶ。軽減・リアクションの経路に最初から乗せない（印の効き先1・2）。
6. **派生神業の対応表はデータとして持たない**（ユーザー指摘 2026-09-03）: 《万能道具》の〈フォルム〉→神業の対応は効果文に書かれており、**使用者が辞典の神業から選ぶ**形にすれば機械可読な表が要らない。選択肢を絞らないのは「組み合わせの可否はユーザーが決める」既定方針にも沿う。《突然変異》も同じ経路。**〈フォルム〉からの自動導出はしない**（2026-09-03 ユーザー確認＝手動で選ぶ以上、〈フォルム〉を読む必要はない）。
7. **破壊は既存機構を踏襲**（ユーザー指摘 2026-09-03）: アウトフィットは `isDestroyed`、トループの壊滅は `heads.value`。新しい破壊機構は作らない。
8. **旧起動経路 `_onUseMiracle` を撤去する**（ユーザー指示 2026-09-03）。シートの神業ボタンを唯一の起動関数 `_activateItemCheck` へ寄せる。旧経路は用途システム・チャットカード統一・アイテムロール規範のいずれよりも前の実装で、素の HTML カードを出し、消費を自前で行い、万能神業をワールド直下のアイテムから選ばせていた。
9. **`isKill` / `isDefence` / `isAll` は撤去せず、設定 UI を与える**（Code の撤回 2026-09-02）。読み手が無いのは機能が未実装だからであり、キル神業・防御神業・万能神業はルール上の実在する区分。神業シートに設定欄が無い現状も併せて解消する。
10. **ウツワ《神意》・ミギウデ《半身》は実装対象外**（ユーザー裁定 2026-09-03）。公式からニューロカード用のデータが配布されておらず実装できない。どちらも既存神業と同効果になる型で、《万能道具》《突然変異》と同じ経路に乗るため後から足せる。

## スコープ

**含む**

| # | 内容 |
|---|---|
| 1 | 神業由来の印と、その伝播（起動文脈→カード→ダメージ→効果→状態） |
| 2 | 起動の一本化（旧経路の撤去・神業書式の宣言カード・残回数ゲート） |
| 3 | 打ち消し（《チャイ》《平和》） |
| 4 | 防御（《難攻不落》《守護神》《友情》） |
| 5 | ダメージ・即死・社会ダメージを与える神業（《神の御言葉》《死の舞踏》《とどめの一撃》《暴露》《制裁》） |
| 6 | 神業に干渉する神業（《ファイト！》《プリーズ！》） |
| 7 | 派生神業（《万能道具》《突然変異》）とアクト内の神業使用ログ |
| 8 | `isKill` / `isDefence` / `isAll` の設定 UI と挙動 |

**含まない**

- 《天罰》《電脳神》《超越品》の効果の自動化。宣言枠のみで、効果は RL 裁定（効果文が「特に制限はない」「RL は判断に迷うようであれば他の神業1発分を目安に」と明示）。
- 《神出鬼没》の入れ替え。**入れ替わっていたという事実を宣言するだけで、システムが動かすものは何もない**（2026-09-03 ユーザー指摘＝Code はダメージの機械的な付け替えと誤読していた）。宣言だけの神業として扱う。
- 神業の宣言タイミングのゲート。「いつでも宣言可能」であり、システムは制限しない。
- 効果文のコードへの焼き込み。神業 Item はユーザー投入のまま（→ [Miracle_Effects.md](../Game_Rules/Miracle_Effects.md) は開発用の写し）。
- ウツワ《神意》・ミギウデ《半身》（上記の設計判断10）。
