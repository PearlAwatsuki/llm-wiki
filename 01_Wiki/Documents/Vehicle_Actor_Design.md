# ヴィークルアクター設計案

2026-09-13 作成・同日更新。**ユーザーの「この形で一度実装を始めてください」により基本設計を承認・初回実装着手。実装済みの範囲と未確定事項は末尾に記録する。以下の設計案は完成済み機能の一覧ではない。**

## 今回確認されたルールと対象範囲（2026-09-13 ユーザー指示）

- ヴィークル自体への攻撃はアウトフィットの破壊の試みとして扱う。通常攻撃による車両の損傷処理は設けず、アウトフィットを破壊可能な効果だけが意味を持つ。
- 通常車両では、搭乗中の乗員キャラクターを個別にターゲットできる機能が必要。
- ドローンの遠隔操縦は今回の実装対象に含む。ドローンへの通常の直接ターゲットは、その搭乗者（遠隔操縦者）への攻撃・ダメージにつなぐ。ドローン自体の破壊を目的とする効果は別経路にする。
- ドローン登場時のダメージは適用時に精神ダメージとなる。このドローン搭乗時の変換に限った自動化がユーザーから提案された。自動化の採用・細かな条件は設計案として下記に整理する。
- ドローンで登場中はゴースト登場中である。ドローンを介さないゴーストは、他のキャラクターへ干渉できず、他のキャラクターからも干渉されない。ゴーストとしてシーンで行動するにはドローンへの登場が必要（同日ユーザー補足）。既存 `Appearance_Check.md` にある会話の扱いは、判定・攻撃等の干渉と区別する。
- ゴースト本人のコマを半透明表示から完全非表示へ戻すことがユーザーから提案され、基本設計の承認を受けて実装した。PLには本人を非表示、RLには管理用トークンを不可視状態として残す。
- 準備済みヴィークルがあるキャラクターのシーン登場時は、最初からそのヴィークルに登場した状態で車両のコマを配置することがユーザーから提案された。以下の「登場時の初期配置」に具体化する。

## 目的と既存実装

乗員のコマで車両を代用せず、ヴィークルのコマを移動・選択しながら操縦者と同乗者の行動を扱う。

- 現在の Actor 型は cast / guest / troop / extra。Item.vehicle は性能・改造・オプション・準備状態を持つ。
- `Outfits.md` の既存裁定では準備済みヴィークルで搭乗を判定し、搭乗関係の保存は不要としていた。今回の依頼はこの設計を再検討するもの。過去の裁定を無言で上書きしない。
- `aggregateDefence` は所持品の準備済みヴィークルを防御力に加算する。`item-activation.mjs` の requiresVehicle / vehicleRef と `attack-flow.mjs` の操縦リアクションも、実行者の所持品から準備車両を探す。
- 既存裁定には「同乗者も車両と同時に移動」「同乗者への攻撃のドッジは操縦者が行う」がある。代理リアクションの仕組みは既に存在する。
- `miracle-flow.mjs` には車両への攻撃を操縦者への攻撃として扱い、同乗は手動とする前提がある。
- エリア盤面・移動計測が現在のコードにある。今回の位置連携はこれと通常盤面の両方を対象にする。

## 1. 責務と正本

**Actor.vehicle を新設し、既存 Item.vehicle と参照で結ぶ案を推奨する。**

| 対象 | 担当する情報 |
|---|---|
| ヴィークルアウトフィット | 性能、改造、オプション、既存の破壊等の状態、取得・常備化の計算 |
| ヴィークルアクター | 参照先、車両の表示名・画像、乗員関係、専用シート |
| ヴィークルトークン | 盤面上の位置・向き・大きさ・視界設定 |
| 操縦者・同乗者 | 技能、能力、手札を使う主体、CS・AR、本人への効果・損傷 |

性能はコピー同期せず、参照先アウトフィットの改造・AE込みの実効値を読む。購入経験点等の二重計上を起こさない。車両アクターの作成はアウトフィットの取得・譲渡ではない。

まずキャラクターが所有する車両から作成できるようにする。持ち主のいない車両は専用アクター内に正本の Item.vehicle を1つ持つ方式を候補とし、外部参照との併用は禁止する。外部参照の所有者と現在の操縦者は分ける。他人の車の操縦を実装対象にするかは要確認。

## 2. 作成とシート

- アウトフィットの車両行から「車両アクターを作成／開く」。同じ実物から重複生成しない。別車両を作る場合はアウトフィットも別実物にする。
- ヴィークルオプションを独立した車両として作成しない。分類・装備先を確認する。
- シートは「概要・性能」「乗員」を基本構成にする。搭載兵器の表示は設けない（2026-09-14ユーザー指示）。既存TNXの数値表とアイコン操作を再利用する。
- 乗員行は名前、役割（操縦者／同乗者）、操縦方式（現地／遠隔）、シートを開く、ターゲット、降車または遠隔操縦終了、操縦交代。搭乗はキャラクターまたは盤面のトークンのドロップから行う。
- 車両のコマから乗員一覧を開き、通常のターゲット操作と同様に乗員を選択・解除する。複数選択と選択中の表示を備える。攻撃側PLが車両シートの編集権限を持たなくても使えるようにし、非公開の乗員情報は既存の公開・秘匿条件に従う。
- 移動判定や搭載装備の使用は、実行者を明示して既存の用途を起動する。車両の攻撃力だけを根拠に新しい通常攻撃を与えない。
- キャラクターの戦闘タブ／HUDには車両名と役割を表示し、車両シートへ移動できるようにする。

## 3. 搭乗と準備の連携

「操縦して物理的に搭乗」「同乗」「ドローンを遠隔操縦」を区別する。同乗者に車両アイテムの複製を配布しない。ドローン準備時は遠隔操縦関係とドローン登場の状態を解決し、操縦者の肉体を車両へ移動する処理には入れない。

| 操作 | 提案する結果 |
|---|---|
| 紐づく車両を準備 | そのキャラクターの操縦搭乗を成立させる。別の操縦者がいれば交代手続きへ |
| 車両シートから操縦搭乗 | 準備条件・部位を確認して、準備と操縦者の設定をまとめて行う |
| 同乗 | 同乗者として追加。操縦者の準備状態を変えない |
| 操縦者が準備解除／降車 | 操縦関係を解除。同乗者を自動降車させるかは別途確定 |
| 操縦交代 | 旧操縦者の解除と新操縦者の準備をまとめて処理。交代失敗時に途中状態を残さない |
| 乗り換え | 旧車からの降車と新車への搭乗をまとめて処理 |

一人の同一実体は同時に複数車両へ物理的に搭乗できず、一台の操縦者は一人を基本案とする。通常の乗員上限は操縦者を含む。遠隔操縦に物理搭乗の排他・定員消費をそのまま適用しない。物理搭乗と遠隔操縦の併用、複数ドローン操縦の可否、定員の「なし」、定員超過の例外、トループの人数の数え方は未確定。

準備を変更するすべての経路（携帯解除・オプション連動・AE・削除を含む）が同じ整合性チェックを通るようにする。相互の更新フックで無限に同期する方式は採らず、搭乗／準備の操作を共通処理へ集約する。

他人の所有品を準備する場合、現在の「自分の所持品の isPrepared」だけでは操縦者の部位・効果を表現できない。実装対象なら外部車両を操縦者の実効装備として解決し、所有者への誤適用を防ぐ設計まで含める。

### 登場時の初期配置（ユーザー提案を採用する設計案）

準備済みヴィークルを登場時の配置方法へ反映する。本人のコマを先に作ってから搭乗操作で置き換える必要はなく、登場の成立時に搭乗関係と車両配置をまとめて整える。

| 登場時の状態 | 初期配置と関係 |
|---|---|
| 通常登場・通常車両を準備済み | その車両に操縦搭乗した状態で、車両コマを配置。本人のコマは表示しない |
| ドローンを準備してドローンで登場 | ゴースト登場・遠隔操縦関係を成立させ、ドローンコマを配置。本人のコマは表示しない |
| 通常登場・準備済み車両なし | 従来どおり本人のコマを配置 |
| ゴースト登場・ドローンなし | 登場状態のみ成立させ、本人のコマは表示しない。通常車両の準備だけでは干渉経路を作らない |

- 判定登場は成功後に配置し、準備を理由に判定を省略・成功扱いにしない。RLの手動登場、シーン開始時の指定登場も、登場成立後の同じ配置処理を通す。
- 登場操作では「車両Vで登場」「ドローンDで登場（ゴースト）」が分かる表示にする。ドローンでの登場を通常登場として記帳しない。準備を変えただけで、未登場のキャラクターをシーンに登場させない。
- 車両アクターが未作成なら、正本アウトフィットから必要時に作成・紐づけする案。既存の紐づきと現在のシーンで有効な配置があれば再利用し、重複生成や既存車両の勝手な移動をしない。
- 参照切れ・破壊済み等の利用不可・準備候補の競合・別操縦者との競合は、配置前に解決する。本人のコマで黙って代用したり、他者の操縦関係を上書きしたりしない。更新失敗後も同じ登場要求を再処理して整合性を回復できるようにする。
- 登場の記帳先はキャラクター。車両を別キャラクターとして登場回数・経験点に加算しない。
- 同乗者は車両の準備だけから推測しない。同乗先が指定されている場合は、その人自身の登場成立後に同乗関係へ反映する。操縦者の登場だけで未登場の同乗者をまとめて登場させない。
- 前シーンの準備状態が維持されていれば、次シーンでも登場成立時に同じ規則を適用する。前シーンの搭乗名簿だけで登場を継承させない。

## 4. コマとシーン

- 物理搭乗中の位置の基準は車両トークン。同乗者から攻撃するときも射程の起点は車両位置として解決する案。
- ドローン登場中は操縦者の `isGhost` を前提とする。盤面にはドローンを表示し、ゴースト本人のコマは表示・ターゲット・距離計測の対象にしない。本人の肉体を同じシーンに別の攻撃対象として用意しない。遠隔操縦終了で肉体をドローン付近に配置しない。
- 通常表示は車両を代表コマにし、乗員は車両シートから選ぶ。キャラクターの戦闘参加・AR・登場状態は維持する。
- 搭乗中は本人トークンを配置せず、車両トークンだけを置く（2026-09-14ユーザー承認による変更）。搭乗に伴う本人トークン削除は退場と扱わない。戦闘参加者は削除前に本人Actorへ参照を切り替えて維持する。
- 降車は車両付近の配置先を指定し、乗員コマを再表示する。以前の遠い位置へ戻さない。通常移動で乗員だけが離れないようにする。
- 車両だけ移動しても乗員の有効位置が追随する。移動判定の成否・可能段階数と、実際の配置操作は区別する。
- 同一FVTT Scene内のTNXシーン切替にも対応し、車両の登場と乗員の登場判定・記帳を混同しない。搭乗で自動的に登場成功にはしない。
- 同一Actorの複数トークン、非リンクNPC、トークン削除、別Sceneへの移動を考慮する。初期の通常運用は一実物一配置とし、同じ車の同時複数配置は検出して扱いを明示する。

### ゴースト表示と干渉の連携案

| 登場状態 | 盤面の表示 | シーン内の干渉 |
|---|---|---|
| 通常登場 | 本人、または物理搭乗先の車両 | 通常の対象解決 |
| ゴースト登場・有効なドローンなし | 本人のコマは非表示 | 他者への干渉・他者からの干渉とも不可 |
| ゴースト登場・ドローンあり | ドローンのみ | ドローン経由で行動・被攻撃を解決 |

現行の半透明化は本体コミット `e8ae5dc`（ゴースト登場のコマを不可視から半透明表示へ変更）。`appearance-state.mjs` に描画時の半透明化、canvasReadyでのhidden解除、新規トークンのhidden=false、ゴースト切替時のhidden解除がある。表示を戻す際はこれらを一緒に見直す。

本人のコマを見せないことと、ルール上の対象・行動候補から除外することを別々に実装する。不透明度だけではターゲットや範囲選択、直接のActor参照を防げない。通常のPL操作では、対象解決と用途実行の双方で登場状態・有効なドローン経路を確認する。ドローンなしのゴーストに対する干渉を、乗員ターゲット機能からも作らせない。

登場記帳・ゴースト状態・HUD／登場一覧はActorで維持する。2026-09-14の変更により、搭乗に伴う本人トークン削除には登場同期用オプションを付け、通常の削除による退場連動から除外する。遠隔操縦終了後も肉体トークンは新規生成しない。

ドローン操縦の開始・終了とゴースト登場の開始・終了も区別する。ドローンを失っただけで本人を通常登場させたり自動退場させたりしない案とし、「ゴースト登場は継続・干渉経路なし」を表せるようにする。破壊による追加の結果は別途確定する。`isGhost` が持つ既存のCS修正等の意味は維持する。

## 5. 戦闘と効果

車両アクターには独自の手札・CS・ARを新設せず、乗員が行動する案。車両のコマを戦闘登録して独立した手番を増やさない。トラッカーの乗員を選ぶと車両位置を示し、車両HUDでは行動する乗員を切り替える。

攻撃対象、リアクション実行者、位置の参照先を分ける。同乗者が対象ならその人の対象行を維持し、操縦者を代理リアクション候補として解決する。車両をターゲットしただけで乗員全員に攻撃を適用しない。範囲攻撃では乗員の対象選択と重複除外が必要。

防御力は既存の加算裁定を土台に、同乗者の外部参照にも適用できる共通処理へ広げる案。操縦者の所持品由来と搭乗関係由来で同じ車両を二重加算しない。制御値修正、準備条件つき用途、オプション、使用回数、搭載兵器の弾薬も同じ正本を読む。

### 対象の解決

| 選択と効果 | 解決する対象 | 処理 |
|---|---|---|
| 通常車両の乗員を通常攻撃 | 選択したキャラクター | 車両位置で攻撃・リアクション・本人へのダメージ適用 |
| 通常車両そのものを通常攻撃 | 有効な通常攻撃対象として扱わない | 乗員を選ぶ導線を提示し、操縦者へ暗黙に付け替えない |
| ドローンを通常攻撃 | そのドローンの遠隔操縦者 | ドローン位置で判定し、操縦者へダメージ適用 |
| 車両／ドローンへアウトフィット破壊可能な効果 | 紐づく正本Item | 効果の対象条件を検証し、既存のアウトフィット破壊処理へ |

破壊経路は、使用する効果のアウトフィット破壊能力に基づいて選ぶ。ターゲットUIの切替だけで通常攻撃に破壊能力を与えない。無操縦ドローンの通常攻撃先は自動補完せず、ルール確認が必要な状態として扱う。

乗員ターゲットはキャラクター参照と車両位置の参照を組にする。乗員の個別コマが非表示・未配置でも選択できるよう、既存のトークンだけを読む対象解決処理へこの選択を統合する。チャットには「乗員B（車両V）」または「ドローンD → 操縦者A」を表示する。

### ドローン経由ダメージの自動変換案

既存 `damage-flow.mjs` は「元の系統で算出・軽減した最終値を別の系統で適用」する `applyCategory` を持つ。この分離を利用し、ドローン経由の対象行では**適用系統を精神にする**。攻撃そのものを精神攻撃へ変更せず、元の攻撃系統・属性・算出過程を残す。

現状の `applyCat` は適用操作全体で共通なので、通常乗員とドローンを同時に攻撃した場合のため、対象行ごとに適用系統と変換理由を保持する設計へ広げる。プレビュー・適用・チャット記録を同じ値に揃える。

- 変換条件は「ゴースト登場中で、有効なドローン登場の対象経路を通って受けたダメージ」。通常車両の同乗者には、この自動変換を掛けない案。ドローンを介さずゴースト本人を攻撃する経路は作らない。
- 攻撃対象確定時のドローン・操縦者・登場経路を記録し、適用前の交代や操縦終了で過去の攻撃を別人に付け替えない。不整合は明示する。
- ドローン自体への破壊効果では操縦者へのダメージ転送・精神への変換を行わない。破壊に伴う追加結果は別途ルールを確定する。
- 自動変換と既存の手動系統変更が競合するときの扱い、カバーリングで対象が変わったとき、直接・神業・派生ダメージへの適用範囲は未確定。
- 同じドローン経路を重複選択しても二重適用しない。ゴースト本人の別ターゲットは作らない。複数ドローン操縦を許す場合の同時被攻撃は、その可否を確定してから扱いを決める。

独自HPや車両用損傷表は設けない。神業の自分判定・代理回避・対象破壊も、この対象経路を参照するよう見直す。

## 6. データ構造の候補（フィールド未確定）

| 保存先 | フィールド案 | 意味 |
|---|---|---|
| Actor.vehicle.system | outfitUuid: string | 正本ItemのUUID。内蔵方式なら自身の埋め込みItemを指す |
| Actor.vehicle.system | crew: 配列 | `{ actorUuid, tokenUuid, role, operationMode }`。role は driver / passenger、operationMode は onboard / remote。remote は操縦者用。tokenUuid は本人の肉体の配置参照であり、ドローン位置で上書きしない |
| 攻撃・ダメージの対象行 | 対象経路 | キャラクターUUID、車両Actor／Token UUID、経路（通常／乗員／ドローン経由）、元の系統、適用系統、変換理由。具体的なキー名は既存対象スキーマとの統合時に確定 |
| Tokenのシステムflag | 搭乗表示の復元情報 | 専用表示制御の方式が決まってから必要な値だけ確定 |

搭乗関係の保存は車両側に集約し、キャラクターの「搭乗中の車両」は逆引きする。actorUuid は本人、tokenUuid は盤面上の実体を区別する参照で、未配置なら空。非リンクNPCは合成ActorのUUIDを含めて解決し、別個体と混同しない。

準備は既存Item、乗員は車両Actorという複数ドキュメントの更新になる。権限のある実行側に処理を集約し、事前検証・重複要求防止・失敗時の回復・再読み込み時の整合性確認を用意する。PL要求では実行者と対象の権限を検証し、他人の車両や乗員を自由に変更できる入口にしない。既存ソケット基盤を利用する。

外部Itemの更新時には参照車両と乗員の派生値・開いている画面を更新する。参照解決は循環依存を避ける。過去のチャットには当時の対象・実行者・車両参照と表示名を残し、後の操縦交代で過去の判定を別人に付け替えない。

## 7. 互換性と異常時

- 保存済みの既存車両を一括でアクター化しない。既存の準備状態は読み続け、登場時に必要な車両アクターを作成・紐づけする案。紐づけ後は搭乗関係を優先し、旧来の準備参照と二重適用しない。
- 既存 `vehicleRef.itemId` を一括破壊しない。外部参照が必要なら旧IDを読む互換性を保ってUUID等を追加する。空の自動解決も搭乗先へ対応させる。
- 車両アクター削除で元の購入品を削除しない。元Item削除時は参照切れを明示し、再紐づけ／搭乗解除を可能にする。古い性能を黙って使い続けない。
- アクター／Item複製・輸出入時は内部参照を付け替え、乗員関係をそのまま複製しない。車両破壊・操縦不能・参照切れを一つの状態にまとめない。

2. Actor型、専用シート、Itemとの紐づけ、性能参照、参照切れ対応。

完了確認は「操縦者Aと同乗者Bが搭乗→車両移動→Bの攻撃と被攻撃→Aの代理リアクション→操縦交代→降車」の一連の運用で行う。防御の二重加算なし、車両による手番増加なし、弾薬・回数の二重消費なしを確認する。別PL同士の操作、RL不在、更新競合、参照削除、再読込、非リンクNPC、シーン切替も検証対象。

初期配置は「通常車両／ドローンを準備して登場→最初から車両のみ配置・搭乗状態成立」を確認する。登場判定失敗では配置されないこと、未作成車両は一度だけ生成されること、配置済み車両は再利用されること、未登場の同乗者を巻き込まないこと、登場の記帳が一人分だけであることも確認する。

ドローンの確認は「ゴースト登場（本人非表示・相互干渉不可）→ドローンで登場→ドローンへの通常攻撃→操縦者への精神ダメージ適用→ドローンへの破壊効果→遠隔操縦終了」を追加する。通常乗員との混在攻撃でドローン側だけ精神適用になること、本人が通常登場しないこと、対象重複や途中の交代で二重適用・誤転送が生じないことも確認する。再読込で本人のコマが再表示されず、非表示への切替が退場記帳を起こさないことも確認する。
