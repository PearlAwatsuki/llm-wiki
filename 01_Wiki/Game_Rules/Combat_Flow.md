# カット進行（戦闘進行）

TNX の戦闘進行に関するルール解釈の正本。フェーズ8 後の設計議論で言語化・確定（2026-06-19）。

TNX では戦闘を**カット進行**と呼び、他システムの「ラウンド」に当たる単位を**カット**と呼ぶ。カット進行は独立した1つのシーンの中で行われる。

## プロセスの流れ

```
カット進行の開始
  → セットアッププロセス
  → イニシアチブプロセス → メインプロセス → イニシアチブプロセス → メインプロセス → …
  → （行動可能者がいなくなったらイニシアチブプロセスで確認）
  → クリンナッププロセス
  → セットアッププロセス → …（次カット）…  → クリンナッププロセス
  → カット進行の終了
```

セットアップ〜クリンナップで**1カット**。カット進行の終了が宣言されるまでカットを繰り返す。

## 1. カット進行の開始

独立した1つのシーンとして、通常のシーン開始と同じ処理で開始する（シーン開始処理は [シナリオ進行] 側で定義。本書では触れない）。

## 2. 戦闘準備プロセス

武器の準備など事前確認を行う場。明確なプロセスというより準備の場で、技能判定など**明確に1行動を消費する行動は行えない**。RL は不意打ち等の状況で「何も行えない」とすることもできるが、基本的には必要な準備は認めるべき。

## 3. セットアッププロセス

カットの本格的な開始。

- カットに新規登場するキャラクターがいればここで**登場判定**を行う（通常は前シーンからの流れで切り替わるためイレギュラー）。
- タイミングが「セットアッププロセス」の行動をここで行う。複数いる場合は **CS順**。
- **CS が等しい場合の優先順位**: ① CSベースが高い順 ② ゲスト→キャスト→トループの順 ③ キャスト同士の話し合い（オンラインでは実質省略されうる）④ RL の左隣から右回り（FVTT では**ユーザー順**で代替）。
- セットアッププロセスの最後に **CSカレント**を決定する（= CS ＋ セットアッププロセスで行った行動による CSカレント修正）。

## 4. イニシアチブプロセス

- カット参加者のうち、**CSカレントが最も高く、AR が1以上**のキャラクターを確認する。そのキャラクターが直後にメインプロセスを行う。
- タイミングが「イニシアチブプロセス」の行動をここで行う（複数なら CSカレント順）。
- **待機**: 直後にメインプロセスを行えるキャラクターは「待機」を宣言できる。待機すると**CSカレントが1**になり、メインプロセスを行う者を確認し直す。
- 最も CSカレントが高い者が何らかの理由でメインプロセスを行えない場合、このタイミングで **AR を −1** する。

## 5. メインプロセス

アクションを行う。順序は **ムーブ → マイナー → メジャー**。メインプロセス終了時、**メジャーアクションを行ったキャラクターの AR を −1 し、CSカレントを 0 にする**（アウトフィットやスタイル技能の効果で変更されない）。

### a. ムーブアクション

マイナーアクションの直前に行える。

- 距離は **至近 / 近 / 中 / 遠 / 超遠** の5段階。通常1回のムーブで**1段階**移動（近の敵に近づいて至近に、または遠ざかって中に）。
- 至近距離にある状態を**エンゲージ**と呼ぶ。
- 通常ムーブに判定は不要。RL が障害物等で必要と判断すれば〈運動〉判定/対決（ヴィークル搭乗時は〈操縦〉）。
- **封鎖状態**: エンゲージから離れる移動を妨害できる状態。妨害時は〈運動〉判定同士の対決（移動側勝利で移動成功、妨害側勝利で移動阻止）。
- ヴィークル搭乗時は **SF（スピードファクター）の値分**の段階移動（SF3 なら遠の敵に一気に近づける）。

### b. マイナーアクション

判定を必要としない簡単な行動。メジャーの直前に行える。基本、**1回のメジャーにつき1回**。例: しまったアウトフィットを使用可能に準備する、タイミングがマイナーのスタイル技能を1つ使用、マイナーで使えるアウトフィットを1つ使用、等。

### c. メジャーアクション

メインプロセスの主行動。行うと **AR を1消費**。物理攻撃・精神攻撃、タイミングがメジャーの特技、メジャーで使えるアウトフィットの使用など。メジャーアクションに対しては妨害として**リアクション**が行える。

攻撃の場合、達成値の算出/比べ合いで差分値を算出し、攻撃側が敗北ならその時点で攻撃終了。勝利時のダメージ算出の詳細順序は [Damage_Rules.md](Damage_Rules.md#算出の適用順序メジャーアクション内) を参照。

### d. オートアクション

**いつでも、宣言を行うだけで可能**なアクション（メインプロセスに限らない）。タイミングが「オートアクション」のスタイル技能、オートアクション可能と解説にあるアウトフィット、その他 RL がオートアクションで行えると判断した行動が行える。

## 6. クリンナッププロセス

カット終了に伴う処理。以下の順で行う：

1. 継続ダメージの処理
2. スタイル技能・アウトフィットによる「カット中」効果の終了（**バッドステータスの回復もここ**）
3. 継続する効果の確認
4. クリンナッププロセスで使えるスタイル技能・アウトフィットの使用
5. **アクションランクの回復**
6. RL によるカットの終了宣言と、次カットに続くかの宣言

## コンバットスピード（CS）

3層構造で管理される：

| 層 | 決定タイミング | 内容 |
|---|---|---|
| **CSベース** | 常時（派生値） | `(理性 + 感情 + 生命) ÷ 2（端数切り捨て） + 修正`。修正には「常時／常に」能力値・CS を変える効果を含む |
| **CS** | プレアクトに決定 | 初期値は CSベースと同じ。アクト中に CS を変える効果で変化。**アクト中に能力値が変化しても CS は再計算されない**。CS を変えるアウトフィットが故障・破壊された場合は CS のみ変化し CSカレントは不変 |
| **CSカレント** | カット中、セットアッププロセスの最後 | `CS ＋ セットアッププロセスの行動による修正`。メインプロセス終了で 0、待機で 1 になる |

**表示の原則（2026-07-02 ユーザー確定）**: シート上は常に**単一の「CS」**とだけ表示する。ベース／CS／カレントの
3層は**内部データ**であり、「今表示されている CS がどの層か」は**自動で制御**する——
**カット（開始済み戦闘）進行中＝カレント／それ以外＝CS**（ベースは編集モードの内部参照のみ）。
カット開始時（および開始済みカットへの参加時）に**カレントへ CS 実効値を自動セット**する
（「セットアップ末に決定・初期値は CS」の近似。以後のセットアップ修正・メジャー後 0・待機 1 の
自動管理はフェーズ13）。initiative も表示中の値を読む（カット開始直後＝CS 相当・以後カレント）。

**手動修正の位置づけ（2026-07-02 ユーザー確定）**: CS への修正は**基本的にすべて AE で解決**されるもので、
手動ではあまり行われない。ただし完全自動のみにはせず、**編集モードでの手入力修正を例外的な直接介入**として
残す（**閲覧モードに手動の増減操作は設けない**）。また、CSベースへの修正・CS・CSカレントの**入力を同格の
横並びで提示するのは誤り**——3層は同格のパラメータではなく、決定の連鎖（ベース→決定→CS→カット→カレント）
である（UI はこの構造を反映すること）。

**実装表現の原則（2026-07-02 ユーザー確定）**: 3層とも「**決定値（再計算不可）＋修正値（ライブ）**」で表現する。
**修正値以外の値は全て再計算不可**（CSベースの能力値項＝プレアクト時点の実効値を焼き込み・以後追従しない。
CS＝プレアクト決定・CSカレント＝セットアップ末決定）。**修正値はセッション中も普通に加減算される**
（freeMod・タップの CS 修正・AE の常時修正・セットアップ行動修正）。**「読み飛ばし」（ゴースト登場中の
フラグ ON 修正・未準備アイテムの AE 修正）＝修正項が条件付きで外れること**であり、決定値には触れないため
「再計算なし」と矛盾しない（→ [Outfits.md](Outfits.md)「タップの CS 修正」）。

## アクションランク（AR）

行動権。メジャーアクションで1消費、イニシアチブプロセスで行動不能なら −1、クリンナッププロセスで回復。AR が 0 のキャラクターはメインプロセスを行えない。

基準値と回復の詳細（2026-07-03 言語化・フェーズ11 の戦闘タブ AR 表示に伴う）:

- **基準値はほぼ変動しない**。変動源は基本的に、非常に高額なアウトフィットの効果による増強のみ（＝まれ）。
- **クリンナッププロセスの回復は、必ず最大値（基準値）まで戻る全回復**。
- **シーン進行中（カット進行外）は AR を消費できない**（※ユーザー解釈 2026-07-03。原文の明示でなく解釈である旨を保持）。
- **基準の「1」の性質**（※ユーザー解釈 2026-07-03・YES/NO と言い切れない領域）: AR はキャラクター作成で決まる常設ステータスではなく、**「カット進行のシーン開始時に 1 付与される」**形がルール上正しそう、との解釈。キャラクター固有の基準値入力ではなく、付与ルール（定数1）＋増強修正として扱うのが忠実。
- **非戦闘時（カット進行外）の AR 表示は「なし」**（2026-07-03 実機確認時のユーザー裁定）: 付与型のためカット進行外は AR の値自体を持たない。シートはカット進行中のみ現在AR を数値表示する。
- 分身の AR は 1 で固定（→ [Troops.md](Troops.md)）。

## カット数指定の持続時間

持続時間が「カット数」で指定されている効果を、**シーン進行中（カット進行外）に使用した場合、持続時間は1シーン**となる。
