# ダメージルール

TNX のダメージ算出・適用に関するルール解釈の正本。フェーズ8 後の設計議論で言語化・確定（2026-06-19）。

ダメージは **HP の数値減算ではなく、ダメージ値でチャートを引き、該当する効果（負傷＋バッドステータス）を受ける**方式。効果は累積する（合算されない）。チャートは**肉体（物理）／精神／社会**の3系統、各 0〜21。

> **用語（2026-07-08 ユーザー指示）**: チャートの参照位置を指す「段」「参照段」は**公式に無い Code の造語であり全廃**（ユーザーは一度も口にしていない）。**UI には一切使用しない**。開発記録・コード内部で参照位置に名前が要る場合は「チャート参照値」と言い換える。

> **§4.1 境界（ユーザー確定 2026-06-23・確定済み。再確認不要）**: ダメージチャートの **負傷名・段→効果の対応・付与する条件（BS/戦闘不能等のメカニクス）はコード/compendium に同梱する**（効果名・効果値・実効果は構造的でゲームメカニクスのため）。**同梱しない＝ユーザー入力にするのは「効果文（プロセ＝創作的記述テキスト）」のみ**。この判断はプロジェクトオーナーかつルール権威であるユーザーの明示決定であり、§4 の確認義務は履行済み。Code はこれを前提に実装し、境界を蒸し返さない。

## ダメージ算出の共通構造

```
攻撃側合計 = ダメージカード + 攻撃力 + ダメージ修正
算出後ダメージ = max(0, 攻撃側合計 − 恒久軽減)（スタン/説得ならここで 10 超は 10 に戻す＝ダメージ算出の一番最後）
最終ダメージ = max(0, 算出後ダメージ − 事後軽減・適用時の軽減)
チャート参照値 = min(最終ダメージ, 21)
```

> **10 上限の位置（2026-07-16 ユーザー裁定で是正）**: 事後軽減（ダメージ軽減技能 `modifyDamage`）**以外**の**恒久軽減（防御力・受け値によるものを含む）は全て「ダメージ算出時」に適用**し、**スタン/説得の処理（10 超なら 10）はダメージ算出の一番最後**＝恒久軽減を引いた**後**に掛かる。事後軽減・適用時の手動の状況軽減／社会の報酬点は算出の外＝キャップ後の値に効く（Code 導出）。旧記述「攻撃側合計をこの時点で 10 上限（防御側の軽減より前・cap-before-mitigate）」は、防御力・受け値が適用段階にあった当時（2026-07-15）のフェーズ区分を前提とした記録であり、防御力・受け値が算出内へ移った現在は誤り。**現行 `computeDamage` は先キャップのまま＝要是正（KI-024）**。

- **ダメージカード**: **命中判定のカードとは別**。命中確定後に攻撃側が**新たにカードを出して**決める（N◎VA カード数字: 絵札=10, A=11。ジョーカーはワイルドカード＝従来どおり）。判定と同じく**カードを出すことがトリガー**であり、値が自動で確定することはない（ダイスロールを使用するシステムと考え方は同じ＝2026-07-08 ユーザー）。
  - **ダメージカードは判定ではない**: 判定関連のルール（山札の絵札=ファンブル・A の21固定など）は**適用されない**。カードの数字（絵札=10・A=11）は判定のルールというより **N◎VA 全体に通底する規約**（2026-07-08 ユーザー確定）。
  - **複数枚出せる場合があり、値は合算**（2026-07-08 ユーザー確定）。カブキ〈ラッキーストライク〉など、特殊な技能による攻撃判定で使用される。枚数・可否の検証はシステムは行わない（技能を強制しない方針と同じ）。
  - ※本行の旧記述「攻撃の命中判定で出したカードの数字（getCardCheckValue と同一）」は Code の**誤記録**（2026-07-08 ユーザー訂正）。下の適用順序 1.「ダメージカードを出す」が正しく、旧記述を根拠にした自動確定実装は誤りだった。
- **攻撃力**: 武器の攻撃力（物理のみ。精神・社会は攻撃力を持たない）。
  - **複数武器の攻撃力合算（2026-07-09 ユーザー確定）**: 複数武器の攻撃力を合算できる能力が存在するため、攻撃には **2 個目以降の武器も使用できる**。合算時の**ダメージ種別が別々の場合は、そのいずれかから選ぶ**（同一/単一なら自動）。実装: 攻撃用途の `weaponRefs`（配列。武器＋ヴィークルを参照可）＝合計が攻撃力・種別は `damageType` 選択で解決。FA（フルオート）は主武器＝先頭からのみ取る（合算しない・Code 既定。要調整なら見直し）。純ロジック `combineWeaponAttack`（テスト済）。
- **ダメージ修正**: 攻撃力上昇・コンボしたスタイル技能・ダメージ増加/軽減技能・各種バフ。算出式に加減算で乗る。※用途タイプ `damageBoost`/`damageReduce` は**廃止**（2026-07-11 ユーザー確定）。
  - **ダメージ修正技能（用途フラグ `modifyDamage`・2026-07-11 ユーザー提案＝旧 `boostDamage` を置換）**: 増加（正）と軽減（負）を一本の機構で表す。用途の**攻撃セクション**の攻撃モードラジオで「**ダメージを修正**」を選び（「攻撃に使う」と排他）、修正値は同セクションの**ダメージ修正（式）**（`damageBonusSelf` 流用・`@card`/`@item.self`/`@target.*` 等参照可。**空なら適用時に手入力**）。**使用は必ずアイテムロール（技能クリック）**——使用で「**ダメージクリック待ち**」モードに入り（再使用でキャンセル）、**ダメージ・チャットカードのダメージ（攻撃側合計）をクリック**すると修正値がそのダメージへ適用される（判定の事後修正＝達成値クリックと同じ操作系。`TnxCheckFlow` のクリック待ち機構を共用・kind="modifyDamage"）。**有効なのはダメージ算出後〜適用前**（適用済みカードは警告）。消費は使用時にプロンプト→クリック適用の確定時に反映。修正はフラグ `mods` に積まれ、台帳に「事後修正（技能名）」行として攻撃側合計へ合算（ライブ描画）。「タイミング：ダメージ算出」の増加技能は**カードが出た直後にクリック**して表す（旧 boostDamage の待ち受け登録方式は廃止）。**宣言（declaration）用途にも設定できる**（バフ宣言・2026-07-12 ユーザー確定。〈ダメージ〉fieldset のチェックボックス・挙動は同一）＝「算出直前に使用」も先に使用→カードが出たらクリックで表せる（クリック待ちは算出フローを跨いで持続・加算は線形）。フラグ更新は非作者なら damageUpdate ソケット委譲の既存経路に乗るため、**防御側が自分の軽減技能で他者のダメージカードを修正できる**。
  - **攻撃用途のダメージ修正（`usage.damageBonuses`・行の配列・2026-07-10 ユーザー確定）**: 判定ボーナスと対で、**攻撃用途自体がダメージへ加算する式の行**（`{formula, source}`）。ダメージ算出時に各行を評価し攻撃側合計へ加算、台帳に**供給元名つき**で「ダメージ修正（供給元名）」と表示。攻撃に**組み合わせた**技能のダメージ増加はこの行で表す（単独使用の増加/軽減技能は上の `modifyDamage` で表す＝2026-07-11 置換で整理）。
  - **式で参照できる値（2026-07-10 ユーザー要望「AE で参照できる値は式でも参照できるべき」）**: ダメージ修正の式は、`@system.*`（アクター＝AE の `system.*`）・**`@item.<識別キー>.system.*`（アクターの任意アイテムを識別キーで参照・system 全体。例「選んだ武器の攻撃力」＝`@item.<武器の識別キー>.system.attack.value`）**・`@diff`/`@achievement`・`@card` を参照できる（`buildFormulaData`）。
  - **供給元（source）＝台帳の帰属表示専用**（識別キーを保存・表示は逆引きした現在のアイテム名。式の参照とは独立）。供給元＝組み合わせスタイル技能＋使用武器（一般技能除外・グループ表示）。純ロジック `evaluateBonusRows`。
- **軽減**: 防御力・受け値。**AE を介さず直接引く**（D&D 踏襲。ダメージ修正の AE とは別系統）。
- 21 で頭打ちなのは**チャート参照値**であり、軽減は丸める前の生ダメージに効く（例: 35ダメージを15軽減 → 参照値20。5軽減 → 30 → 参照値21）。

## 算出の適用順序（メジャーアクション内）

攻撃が命中（対決勝利または無リアクション）した後、ダメージは以下の順で確定する：

1. **ダメージカードを出す**（N◎VA カード数字：絵札=10, A=11）
2. **武器・特技などの修正**を加える（攻撃側の基本修正）
3. **ダメージを上昇させる特技**の使用（攻撃側）
4. **防具・特技など防御側の修正**を差し引く（防御力。種別 S/P/I に対応。X は対応防御力なしで軽減されない）
   - **スタン/説得を宣言していれば、ここまでの値が 10 超なら 10 に戻す**（＝**ダメージ算出の一番最後**・恒久軽減の後。2026-07-16 ユーザー裁定で位置を是正——旧注記「攻撃側合計を 10 上限＝防御側の軽減より前」は防御力が適用段階にあった当時の区分を前提とした記録で誤り）
5. **ダメージを軽減させる特技**の使用（防御側。**他人からの軽減もここ**＝事後軽減。キャップ後の値に効く）
6. **ダメージチャートを参照**する

2〜3 が攻撃側の加算、4〜5 が防御側の減算。防御力・受け値は AE を介さず直接引く（→ 軽減の項）。リアクション（ドッジ/パリー）の対決は 1 の前（命中判定）で解決済み。3・5 の増加/軽減特技は用途フラグ `modifyDamage`（→ ダメージ修正技能の項。攻撃側合計クリックで適用＝算出後〜適用前）か、軽減ダイアログの手動欄で表す。

**表示（2026-07-16 ユーザー確定）**: 防御力・受け値（4）は**ダメージ算出の一部**なので、ダメージカードを出した時点で**各キャラクター行に「防御力・受け値を引いた後の最終ダメージ」を表示**する（＝算出済みの値）。**攻撃側合計はレジャーに残す**（攻撃側の事後増強＝3/`modifyDamage` の可能性があるため）。適用時のダイアログは縮小し、**防御力・受け値は自動確定（編集不可）**、そこで入れるのは**手動の状況軽減**と**社会の報酬点軽減**だけ（物理/精神で追加が無ければ実質確認のみ）。「ダメージを軽減させる特技」（5・`modifyDamage`）による事後修正は従来どおり別系統で有効（攻撃側合計クリックで算出後〜適用前に効く）。

### 派生ダメージ（チャート効果が別のダメージを発生させる場合・2026-07-09 ユーザー言語化）

- 特定のダメージチャートの効果が**別のダメージを発生させる**場合（例: 社会ダメージチャート 9番「強迫」で発生する山札1枚の精神ダメージ、社会 19番「暗殺」の肉体ダメージ）、**この派生したダメージ（チャート参照）は何かの効果で軽減することはできない**（直接ダメージを発生させたような扱いになる＝防御力・受け値・報酬点等の軽減を一切通さない）。
- つまり派生ダメージは「カードを引く→そのままチャート参照→適用」であり、軽減ダイアログを挟まない。

## 物理攻撃

攻撃側が防御側に物理的ダメージを与える。カット進行中の行動。

1. **命中判定**: 〈白兵〉または〈射撃〉（白兵武器→白兵攻撃、射撃武器→射撃攻撃）。基本**メジャーアクション**。対象は武器の**射程内**にいること。目標値は、対象がリアクションしなければ**制御値**（出したカードのスートに対応する制御値）、リアクションすれば **[対決]**（対象のリアクション判定の達成値）。
2. **防御（リアクション）**: ドッジ／パリーの2種。
   - **ドッジ**: 〈回避〉（ヴィークル搭乗時は種別に応じた〈操縦〉）。勝利で攻撃無効。
   - **パリー**: 〈白兵〉。勝利で攻撃無効。さらに**判定が成立さえしていれば**（敗北でも）、使用武器の**受け値を防御力に加算**できる（ダメージ種別に依らない）。代償に**メインプロセス終了時に AR −1**。AR 0 では行えない。※実装（2026-07-12 ユーザー確定）: AR−1 の専用自動化は廃止し、**用途の消費先設定「AR を消費」**（consumeTargets type=`actionRank`）に一本化——パリー技能の用途に設定して表す。**カット進行外は AR を消費できないため原則使用不可**（残量 0 扱いの原則ブロック。AR 0 も同様＝チェックを外せば卓裁定で実行可）。
3. **肉体ダメージ算出**: `[ダメージカード + 攻撃力] − ダメージ種別に対応した防御力`（＋各種ダメージ修正）。
4. **適用**: 肉体ダメージチャートを参照。

**特殊**:
- **フルオート射撃（FA・2026-07-09〜10 ユーザー確定・実装済み）**: 一部の射撃武器が可能（解説に `FAn` 表記）。**FA は自動加算しない**——攻撃に使った FA 可能武器ごとに、**ダメージ算出ダイアログで「FA射撃する」を任意選択**し、選んだ武器の n を合算してダメージに加える（複数武器合算で両方 FA 可能なら、両方 FA すれば両方の n が乗る）。FA 射撃すると**その武器の残弾が空になる**（弾倉交換＝リロードが必要）。実装: 攻撃カードは faOptions を持ち回り（FA 可武器一覧）、ダイアログのチェックで確定。純ロジック `combineWeaponAttack` が faOptions を返す。
- **残弾・リロード（射撃武器・搭載兵器・2026-07-09〜10 ユーザー確定・実装済み）**: 武器の残弾は `-`（概念なし）/数字（装弾数＝**FA以外用**）/任意（有無だけ＝**FA武器用**）の3モード（DataModel `weapon.system.ammo = {mode, value, current}`。`current` = 現在残弾・null=満タン/あり・0=空）。**数字は通常（非FA）射撃で1減り、任意は FA 射撃で空になる**（数字=FA射撃以外用・2026-07-10 ユーザー確定）。空（0）の準備済み武器は、戦闘タブの**マイナー欄に「リロード（武器名）」が合成アクション**として出て、実行で満タンに戻る（`current=null`）。**自動給弾の FA 武器は「isFullAuto=true かつ残弾=`-`」で表現**（残弾を追跡しなければ FA しても空にならない＝専用フラグは持たない）。→ [Outfits.md](Outfits.md)「残弾・リロード」。
- **スタン攻撃**: 気絶を狙う攻撃（峰打ち等）。**可能と明記された物理攻撃**（能力として持つもの）で行う。宣言は**攻撃の対象を決定するとき**。対象は**単体※**（単体固定・効果等で変更不可）。**ダメージ算出の一番最後（恒久軽減＝防御力・受け値を引いた後）に 10 を超えていたら 10 に戻す**（事後軽減・適用時の軽減より前。2026-07-16 裁定で位置を是正）。
  - **可否は武器依存（2026-07-15 ユーザー確定・(ii)）**: スタンできるかは**武器の「スタン可能」フラグ**（アウトフィット）で決まる。用途の `canStun` も残すが、用途で立てるのは**スタイル技能の効果でスタン可能になる場合のみ**。実効可否＝**物理攻撃かつ〔使用武器のいずれかがスタン可能 ∨ 生身 ∨ 用途.canStun〕**。実効可否のとき、**攻撃の判定ダイアログに既定オフの「スタン攻撃として実行」インラインチェック**が出る（宣言＝対象決定時。独立確認ダイアログにはしない＝非宣言ユーザーの手数ゼロ）。
  - **算出とカード**: 宣言は 攻撃カード→ダメージカード へ引き継がれ、キャップの正位置は**恒久軽減を引いた後（ダメージ算出の一番最後）**（2026-07-16 裁定）。現行 `computeDamage` は攻撃側合計を先に 10 上限にしてから軽減する 2026-07-15 当時の形のまま＝**要是正（KI-024）**。ダメージカードに「スタン／説得（10上限）: N → 10」を表示。**適用時の再確認ダイアログは廃止**（経緯 → [Audit_and_Review](../../02_System/Audit_and_Review.md)）。
  - **対象**: Foundry のターゲット（レティクル）を使い、未ターゲット時の選択は**必ずレティクルを付与**する。スタン／説得の**単体※**は、複数対象実装下でも**先頭（＝単体）対象で成立**する。

### 複数対象への一括（2026-07-15 実装）

攻撃対象は `game.user.targets`（レティクル）**全体**を取り込む（未ターゲット時のドロップダウン選択は 1 体をレティクル付与）。以降、命中判定・リアクション・ダメージを全対象へ一括処理する。

- **命中判定は全対象で共有**: カードプレイ（判定）は 1 回。攻撃カードは **D&D 風の対象リスト**を保持し、対象ごとに `制御値`（出したスートに対応）と**リアクション結果**（達成値・命中/回避/未応答）を行表示する。攻撃側合計に効く**対象依存の値（`@target.*`・対象バフ AE）は共有されるため、先頭の命中対象で近似**する。
- **リアクションは対象ごと**: 攻撃投稿時に対象ごとの**個別リアクションカード**を出す（表示は **GM＋対象所有者に whisper**）。カードはドッジ／パリー／リアクションなしのボタンを持ち、操作後に**制御値／達成値を表示して判定結果カードのように振る舞い**、結果確定で **whisper が解除され全体公開**される。判定結果は攻撃カードの対象リストへも反映される。
- **ダメージは 1 ボタン＝1 ダイアログ**: ダメージカードは命中した全対象を保持し、**適用ボタンは 1 つ**。押下で対象ごとの軽減入力を**まとめた 1 ダイアログ**（各対象のプレビュー付き）を開き、確定で**全対象へ一括適用**する（対象ごとの適用ボタンは廃止＝まどろっこしさの排除）。

## 精神攻撃

悪口・洗脳・催眠等で精神を攻撃する。攻撃側／防御側の呼称は物理と同じ。

1. **命中判定**: 〈心理〉。デフォルト射程は「近」（スタイル技能で変更されうる）。対象は**コミュニケーション可能な状態**であること（AI 搭載機器・付喪神など意思があれば対象可。睡眠中・意思疎通不能な相手は不可）。他は物理と同じ。
2. **防御**: 〈自我〉。勝利で無効。
3. **算出**: 防御力の適用なし。`[ダメージカード + ダメージ修正]`。精神攻撃はデフォルト攻撃力を持たない。
4. **適用**: 精神ダメージチャートを参照。

**特殊**:
- **説得**: 精神版の同種オプション（スタンと**効果は似るが別メカニクス**。種別変更で一方が他方に化けるものではない）。**精神攻撃なら常に可能**（スタンと違い能力ゲート無し）。ダメージ算出の一番最後（恒久軽減の後）に 10 超なら 10。チャート 10 では戦闘不能の代わりに「説得に応じる」形。実装＝攻撃の判定ダイアログの**「説得として実行」インラインチェック**（精神攻撃なら常時表示・既定オフ）。宣言・キャップ・適用はスタンと同一。**説得成立時は精神チャートの BS（負傷）は通常どおり付与するが、効果タグ＝戦闘不能タグ（incapacitation グループ・支配含む）は付けない**（`applyDamageChartResult` の persuade フラグ→ createActiveEffect カスケードで incapacitation を抑止・2026-07-15 ユーザー確定）。「説得に応じる」は状態や機構を持たないフレーバー。

## 社会攻撃

社会的地位・経済的背景を傷つける。他系統と大きく異なり、**カット進行ではなく舞台裏判定**として行う。

1. **命中判定**: 〈圧力〉。シーンごとの舞台裏判定でのみ行える（基本シーン1回）。
2. **防御**: 〈信用〉。勝利で無効。
3. **算出**: 攻撃力なし。`[ダメージカード + ダメージ修正]`。リアクションの〈信用〉判定が成立していれば**報酬点による軽減**が可能（適用時に**防御側に別途ダイアログを出して**入力する＝2026-07-08 ユーザー指示）。
4. **適用**: 社会ダメージチャートを参照。

社会ダメージの効果は「次シーンの会話を盗聴される」等、社会的に不利にする特殊なものが多い。チャート 21 のキャラロストは、**適用タイミングがセッション終了後**である点が肉体・精神と異なる（人知れず葬られる／処刑される等の演出）。

## ダメージ種別と防御力

- ダメージ種別 **S/P/I/X**（斬/貫/衝/装甲無視）は**肉体ダメージ内の種別**。肉体/精神/社会の系統とは別軸。
- **防御力＝装甲**（同義）。S/P/I それぞれに設定され、攻撃のダメージ種別に対応する防御力を引く（`armor.defence` の S/P/I 別）。
- **X（装甲無視）**: 正確には「防御無視」ではなく、**対応する防御力が存在しないため軽減されない**。

## 別のダメージとして適用（2026-07-16 ユーザー確定・実装済み）

算出したダメージを、**元の系統とは別の系統（肉体/精神/社会）のダメージチャートに適用**できる。「〈スタイル名〉の効果で、与えたダメージを別系統として扱う」等を表現する。

- **差し替えるのは系統（＝参照するダメージチャート）のみ**。ダメージ種別（S/P/I/X）や値の算出式は変えない。
- **軽減は元の系統のまま行う**。肉体ダメージなら**防具（防御力）の軽減も含めたすべての軽減を通常どおり行い、その軽減後の最終値**を、選んだ系統のチャートへ適用する（＝「元系統でフル軽減 → 軽減後の値を別系統チャートへ流す」）。値は再計算せずそのまま保持する。
- **どの攻撃でも常に選べる**（RL 裁量。用途フラグ等のゲートは設けない）。システムは可否を制限しない。
- 実装: ダメージカードの「ダメージ適用」に加えて、展開式の**「別のダメージとして適用」**（他系統のチャートへ適用するボタン群）を置く。押すと通常の軽減ダイアログ（軽減は元系統）が開き、確定で**軽減後の値を選んだ系統のチャート**へ適用する（複数対象一括も同じ）。適用済みカードには差し替え先の系統を明示。アクセスは通常の適用と同じ（RL と攻撃者）。
- **説得（精神攻撃のスタン宣言による効果タグ抑止）は、元系統＝精神をそのまま精神チャートに適用したときのみ**有効（別系統として適用する場合は説得の意味論が対応しないため付与しない）。スタンの 10 上限はダメージ算出の一番最後（恒久軽減の後）で掛かるため、別系統として適用しても保持される。

## カバー（2026-07-16 ユーザー確定・実装済み）

**ダメージ算出の直前に、他者へ与えられる予定のダメージを自身へ付け替える**行動（かばう）。固有の技能名「カバーリング」と区別して、行動としては「カバー」と呼ぶ。

- **1体分だけ肩代わり**（命中対象を1体選ぶ）。複数対象攻撃でも「1体分を付け替える」一本で扱う（全対象を集約する挙動は別能力＝作らない）。
- **カバーした側が元々その攻撃の対象でもある場合、2つのダメージが別々に入る**：自分の分（対象として被弾）は**自分のリアクションが乗る**（パリーしていれば受け値が効く）。カバーした分は**自分ではリアクションしていないので受け値は参照しない**。
- **判定が要る**（用途の判定）。ただしカバー系スタイル技能は**目標値「なし」がほとんど**で、その場合は**スート一致で成功**（用途の目標値欄を「なし」にするだけ＝固有ロジックは持たない）。ファンブル/スート不一致でなければ成立。
- **軽減はカバーした側自身の防御力で算出**（付け替えは算出の直前のため、カバーした側に対して算出する）。ただし**受け値は参照しない**（自分ではリアクションしていないため）。
- **どの攻撃でも常に選べる**（用途に「カバー」フラグを立てた技能を持っていれば）。

実装: 用途フラグ `covering`（用途シートの「リアクション」セクションに「カバー」トグル）。**アクセスは攻撃カード**（＝ダメージ算出の直前。ダメージカードを出す前のみ。ダメージカードから触らせるのは「算出後」で時制が合わないため誤り）。起動＝**カバー技能をアイテムロールで使用** → 「カバー待ち受け」 → **攻撃カードの命中対象の行をクリック** → 通常の判定（唯一の起動関数 `_activateItemCheck` に `covering` 文脈）→ 成功で攻撃カードの対象に「カバーの印」を付ける。攻撃者が「ダメージカードを出す」と、印の付いた対象はダメージカード生成時に展開され、**元対象はダメージなし（「「◯」がカバー」表示）・カバーした側の行（受け値なし）で算出**される。カバーした側＝**クリックしたユーザーの割り当てキャラ**（アイテムロール元のキャラ）。ダメージカードを出した後（`damageRolled`）はカバー不可。

## 戦闘不能ダメージ

チャートの結果として生じる、ゲーム処理上重要な状態（チャートの効果文網羅ではなく、システムが扱う中核状態として記録）:

| 状態（肉体／精神） | 内容 | 回復 |
|---|---|---|
| 気絶 / 失神 | 意識喪失。移行判定・メインプロセス不可 | **カット進行終了時に自動回復** |
| 仮死 / 昏睡 | 深刻な状態。シーン終了までに治療・医療保護がなければ完全死亡 | 治療（後述）。回復後は **2シーン後**から行動可 |
| 完全死亡 / 精神崩壊 / 抹殺（社会） | キャラロスト | 受けたシーン内なら神業で回復可能なことが多い。それ以外は不可。社会の抹殺は**セッション終了後**に適用 |

### 特殊タグ［支配］（2026-07-12 ユーザー確定）

特殊な精神ダメージの効果タグ。**支配されたキャラクターは RL 操作になる**——これは自動化せずに効果を運用できる範囲（＝タグは行動ブロックもロスト処理も持たないマーカー。`dominated`）。

- **付与のされ方**: ほとんどは「特定のスタイル技能を組み合わせたとき、［昏睡］［精神崩壊］の**代わりに**［支配］を付与する」形（＝昏睡/精神崩壊が効果に無い精神チャートではあまり意味がない）。また「社会ダメージ［抹殺］を受けたときに**追加で**［支配］を与える」効果もある。
- **実装＝ダメージタグ改変 AE（対象側・チャート適用時評価）**: `damage.replaceTag.<元タグ>`＝値: 新タグ（上書き）／`damage.addTag.<元タグ>`＝値: 追加タグ（追加）。系統を問わず機能する。付与経路は用途の適用効果（対象へ AE 付与）——**適用効果はダメージ適用と同時に自動付与される**（2026-07-12 ユーザー確定＝押し順の順序依存を解消。ダメージ適用の確定時に未適用の効果を先に付与→チャート適用の順で同一クリック内に処理）。
- **解除（ユーザー裁定）**: **上書き由来＝［昏睡］と同じ**（治療可・目標値 20。`replacedFrom` フラグが根拠）。**追加由来＝追加元のチャートの治療で同時に解除**（同じ負傷への紐づき＝woundSource で除去。抹殺と同時に付与された支配は抹殺と同時に解除）。
- チャート項目由来の条件（制御判定での無効/降格）は置換後のタグへ引き継ぐ（無効化条件はダメージ結果の性質として持ち越し＝Code 既定・要調整なら見直し）。

## 治療

- **1シーンに1回**のみの特殊行動。〈医療〉を使用。**社会ダメージは治療不可**（社会ダメージの治療は**専用のスタイル技能か神業のみ**の経路＝2026-07-13 ユーザー確定。実装は用途の回復設定→ [Conditions.md](../Game_Mechanics/Conditions.md)「回復・治療系スタイル技能」）。
- **完全死亡・精神崩壊（とそれを与えるダメージ）は「ダメージ全てを回復する」系のスタイル技能でも治療不可**＝神業のみ（2026-07-13 ユーザー確定。回復用途では通例これらを除外タグに設定する。「抹殺」は未確定＝卓裁定）。
- 通常は戦闘終了後に行う想定（時間がかかるため通常メジャーアクションでは行えない）。ただしメジャー／セットアップ／クリンナップで治療する効果のスタイル技能は存在しうる。
- 目標値: 気絶/失神 = 15、仮死/昏睡 = 20、それ以外 = そのダメージの数値。
- 気絶/失神は治療したそのシーンから行動可、仮死/昏睡は**2シーン後**から行動可。

### 戦闘不能を与えるダメージの制御判定＝無効化はダメージ全体（2026-07-09 ユーザー裁定）

- 戦闘不能を与えるダメージチャート（腹部損傷=気絶・心臓停止=仮死・恐慌=失神・自我危機=昏睡 等）は、**その戦闘不能がダメージそのもの**であり、ルールは「戦闘不能を与えるチャート」と「戦闘不能タグ」を区別していない（同じ戦闘不能タグを複数のチャートが与えても同様）。
- 根拠: 治療目標値が「戦闘不能タグが付いていれば特殊値（気絶/失神=15・仮死/昏睡=20）」で引かれること。もし負傷が戦闘不能と別建てなら目標値は「そのダメージの数値」になるはずだが、実際は戦闘不能レベルで決まる＝負傷の正体が戦闘不能。加えて気絶/失神の「シーン終了で回復」はダメージ側の記述であり、戦闘不能を別タグとして独立させていない。
- 制御判定「無効」は、与える状態が**戦闘不能でも BS でも同様に、ダメージ自体が無効になる**（2026-07-09 ユーザー確定）。腹部損傷（気絶）・恐慌（失神）だけでなく、**恐怖（恐慌 BS）の「感情の制御判定で無効」も、恐慌だけでなく恐怖というダメージ自体が無効**になる。＝制御判定の「無効」はそのダメージへの resist であり、成功すればダメージが起きなかったことになる。
- 実装（本体）: 制御判定成功の帰結を訂正。
  - **無効化**: 付与状態（戦闘不能／BS）に紐づく負傷（woundSource）ごと**ダメージ全体を消滅**させる（従来はタグだけ外して負傷が残っていた＝誤り）。腹部損傷=気絶・恐慌=失神・**恐怖=恐慌**が対象。カスケードで inflicts（戦闘不能・BS 両方）を woundSource で負傷に紐づけ、無効化はそれごと除去。
  - **降格**（仮死→気絶・昏睡→失神）: 降格後の戦闘不能を負傷に紐づけ直す（治療目標値=特殊値・シーン終了回復が正しく効くように）。負傷そのものは残る（表記は名残・機能は正しい）。
- **treatment との違い**: 〈医療〉治療は「負傷＋紐づきの非BS」を除去し **BS は残す**（BS 独立）。制御判定の「無効」はダメージ自体を消すので **BS も含めダメージ全体が消える**。この 2 経路を woundSource の消費側（治療=非BSのみ／無効化=全て）で分岐。（ment-9 動転の notes 制御判定は未機構化）

### 治療で解除される範囲（2026-07-09 ユーザー確定）

- 治療成功で解除されるのは、**その負傷（ダメージチャートの効果）＝負傷本体＋戦闘不能タグ＋そのダメージが発生させている BS 以外の効果すべて**。
- **戦闘不能タグ（気絶/失神/仮死/昏睡）も治療対象に含まれる**。戦闘不能タグは複数のダメージチャートで発生しうるため**タグ化されているだけで、独立した効果ではない**（＝そのダメージチャートの効果の一部）。
- **BS は解除されない**。BS は解除条件が個別に存在する**独立した効果**。ダメージチャートの効果は「**BS を与えるところまで**」であって BS の内容そのものではないため、治療で同時解除はされない（＝ BS は自身の解除条件／解除効果で回復する。[Bad_Status.md](Bad_Status.md)）。
- ※実装（フェーズ12）: 負傷付与時、戦闘不能の inflicts と負傷自身の非 BS 効果は**その負傷に紐づけ**、BS の inflicts は独立させる。治療成功で負傷＋紐づき分をまとめて除去する。**社会ダメージは治療不可**（治療対象に社会の負傷を出さない）。

## チャートの実効果（2026-07-09 ユーザー方針）

**実際にダメージを適用できるようになった以上、チャートの実効果（負傷・BS の挙動）も実装する**（ユーザー明言）。BS・戦闘不能以外に、チャートには具体的な実効果を持つ項目が多く存在する（特に社会）。BS も同様に実効果を実装する。

代表例（実効果がデータ的に表現できるもの）:

- **肉体 7番「腕部損傷」**: 部位「片手持ち」を一時的に**一つ使用不可**にする（適用中、当該部位スロットの**最大値を −1**）。
- 社会チャートの多く（次シーン〈信用〉/報酬点 使用不可、次シーン〈社会〉〈コネ〉ひとつ使用不可、治療するまで〈信用〉使用不可、X ランク化、即座に退場・次シーン登場不可 等）や、肉体 14番（治療まで〈知覚〉−5）、精神 12番（アクションランク −1）・17番（アクションランク 0）なども実効果を持つ。

※効果の発火・失効タイミング（次シーン・治療まで・カット進行終了等）は時間管理＝**フェーズ13/15** に依存する部分がある。**効果の表現（データ構造）とタイミング非依存の即時効果（部位 −1 等）はフェーズ12 で実装**し、タイミング依存の発火／失効は後続フェーズが載せる（＝表現は担当フェーズで確定・発火は各タイミング担当フェーズ、の方針を踏襲）。

> **実装済（2026-07-16）**: 特定技能への効果を持つ 7 負傷（眼部損傷＝〈知覚〉−5、口座凍結／造反／人脈消失＝治療まで使用不可、信用失墜／スキャンダル／信頼喪失＝次シーン使用不可、口座凍結・信用失墜は報酬点も不可）を実装。技能は識別キーで識別・使用不可は判定への警告のみ・社会/コネの「ひとつ」は付与時に選択・次シーンものは休眠（発火は 13/15）。詳細＝[Conditions.md](../Game_Mechanics/Conditions.md)「負傷そのものの直接効果」。腕部損傷（部位 −1）は実装済（[[Conditions]] partSlotMod）。アクションランク（精神 12/17）等は 13 で発火。

## バッドステータスの回復

- バッドステータスごとに回復タイミング・方法は異なるが、**必ずカット進行終了時に全て回復**する。
- マイナーアクション等でバッドステータスを回復する効果のスタイル技能・アウトフィットも存在する。
- バッドステータスは性質上 **ActiveEffect** として表現される（→ 申し送り）。

## トループ級・エキストラのダメージ（チャート不使用の例外）

- **トループ**: ダメージの扱いが完全に異なり、**人数（HP的リソース）がダメージ分減少**する。チャートを参照しない。
- **トループ級キャラクター**: チャートを参照しない点は共通だが形が異なる（例: エニグマの守護霊はエニグマポイントを参照、カゲの分身は1点でも被ダメージで消滅）。
- **エキストラ**: ダメージの概念自体がない。キャスト/ゲストの宣言だけで死亡する。
- トループ／エニグマ／分身の本体ルール（人数・エニグマポイントの決まり方、分身の固定値等）は [Troops.md](Troops.md) が正本（2026-07-03 言語化）。
