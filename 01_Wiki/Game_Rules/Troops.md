# トループ・トループ級キャラクター

トループ級キャラクター（**「トループ」「エニグマ」「分身」の総称**＝2026-07-04 ユーザー確定。トループも含む）に関するルール解釈の正本。フェーズ11-1 の設計議論で言語化（2026-07-03・ユーザー提供）。

基本定義（[Terminology.md](Terminology.md) より）: トループ＝集団を表す NPC。個性を持たない。

**構成**（フェーズ6 設計記録 2026-06-14・[Phase_6_Tasks_Detail.md](../Phases/Phase_6_Tasks_Detail.md)）: スタイル（1つ）・能力値・技能・アウトフィット・状態（コンディション）を持ち、**神業は持たない**。

**判定**（2026-07-03 確定）: トループの判定方法は**キャスト・ゲストと同じ**（能力値実効値＋技能・カードベース）。

**能力値の決定**（2026-07-03 確定）: トループは能力値を**成長させられない**。能力値は**スタイルの基本値＋トループレベル**で決定する（トループレベルは troop のフィールド。**制御値にも同様にトループレベルを加える**＝2026-07-03 ユーザー確定）。

**個人識別データなし**（2026-07-03 確定）: トループは個人を識別するキャラクターではないため、**ハンドル・市民ランク・パーソナルデータを持たない**（シート非表示）。

## 種別と名前の規則（2026-07-03 確定）

troop アクターは**種別ドロップダウン「トループ／エニグマ／分身」**で切り替える（初版のエニグマモードフラグは誤設計として置換）。

| 種別 | リソース | 名前 |
|---|---|---|
| トループ | 人数（heads） | **「(スタイル名)・トループ（(トループレベル)レベル）」で固定**（例: カブトワリ・トループ（2レベル））。自由入力しない |
| エニグマ | エニグマポイント（heads を共用・ラベル切替） | **自由入力**（個体の識別とキャラクター名の自由設定が必要なのはエニグマのみ） |
| 分身 | **管理なし**（1点でも被ダメージで消滅＝人数欄を出さない） | **「(分身元キャラ)の分身」で固定** |

**ワークスを持つトループ**（2026-07-03 確定）: トループは基本的に所属組織（ワークス）を持たないが、ワークスを持つトループは作成可能なため**「ワークスを設定」フラグ**で管理する。フラグ ON かつ組織アイテムありのとき、トループ名は**「(組織名)（(スタイル名)(トループレベル)レベル）」**（例: トキオシティポリス（カブトワリ2レベル））。ワークス形式のレベルも**トループレベル**（2026-07-03 ユーザー確定＝当初文言「スタイルレベル」は取り違え）。**フラグ ON でも組織未設定の間は OFF と同じ挙動**（「フリーランス」表示の不整合回避・ユーザー指定）。所属ブロックはフラグ ON のときだけシートに表示する。

**部署技能による上書き**（2026-07-03 確定）: 部署を表すワークス技能（スタイル技能の**「部署技能」フラグ**・ワークス技能 ON のときのみ設定可）を取得している場合、**所属名（ワークス名）の表示がその技能の名前で上書きされる**。トループではトループ名の組織名部分が置き換わる（例: 『千早グループ（クグツ2レベル）』＋ワークス技能『後方処理課第二班』→『後方処理課第二班（クグツ2レベル）』）。キャスト/ゲストではヘッダーの所属表示が上書きされる（→ [Character_Creation.md](Character_Creation.md)「ワークス技能」）。

## heads（人数）

- heads は**本当に人数を表すパラメータでしかない**。ダメージを受けると人数分減少する（HP 的に機能する。→ [Damage_Rules.md](Damage_Rules.md)「トループ級・エキストラのダメージ」）。
- **敵対キャラクターとして登場するトループ**: RL が**任意に人数を決定**する。
- **トループ取得技能で取得されるトループ**: トループ取得技能を**組み合わせた判定の達成値がそのまま人数**になる。
- **トループ側で自動化すべき点はない**（ユーザー明言 2026-07-03）。人数の決定は RL 入力または判定結果の転記で足りる。

## エニグマ・分身の類型

チャートを参照しない点はトループと共通だが、HP 相当の形が異なる。

### エニグマ（マヤカシの秘儀〈分心〉）

- 人数ではなく**エニグマポイント**が HP に相当する。
- **取得判定の達成値分がそのまま適用される**（＝エニグマポイントになる）点はトループの人数と同じ。
- エニグマは troop アクターの**種別切替**（上記「種別と名前の規則」）として表現し、切り替えたら**人数の代わりにエニグマポイントを HP にする**（リソースの意味・ラベルが切り替わる。2026-07-03 確定・同日「エニグマモード」フラグ案から是正）。

### 分身（カゲの奥義〈分身〉）

- **1点でもダメージを受ければ消滅**する。したがってダメージの管理は不要。
- **ほとんど本体（呼び出したキャラクター）と同一のデータを持つ**。このため分身だけは**スタイルを複数持つ**。
- **トループ級キャラクターなので troop アクターとして作成する**のが正しい（2026-07-03 確定）。
- 本体と異なる点:
  - **AR は 1 で固定**
  - **CS と CSカレントは 0 で固定**
- **使用回数の共有**（※ユーザー解釈 2026-07-03・「ようです」の留保付き）: 分身は**使用回数制限のある能力の残回数を本体（キャスト側）と共有している**ようだ。実現方法は未定のため申し送りとして保持（フェーズ11 では自動化しない）。

## スタイルと共通制約

- **スタイルの数**: 分身を除き、トループとトループ級キャラクターは**スタイルを1つだけ持つ**。分身は本体同様に複数持つ。
  - **シートでも強制する**（2026-07-03 確定）: 種別がトループ／エニグマのときはスタイルのドロップを1つまでに制限（同名再ドロップのレベル上昇も不可＝強さはトループレベルで表す）。スタイルスロット表示も1枠。分身は制限なし。
  - **役割（ペルソナ／キー／シャドウ）の表示・設定も分身のみ**（2026-07-03 確定。トループ／エニグマは個人識別キャラでないため役割を持たない）。
  - **トループ種別では閲覧モードのスタイル概要行を出さない**（名前「(スタイル名)・トループ…」に含まれるため冗長＝2026-07-03 確定。エニグマ・分身は名前にスタイルが含まれないため表示）。
- **神業**: 分身も含め、トループとトループ級キャラクターは**神業を使用できない**。
  - この帰結として、**troop アクターへのスタイルインポート時は神業の自動取得を行わない**（2026-07-03 確定）。
- **トループ取得技能**: トループ／トループ級キャラクター自身が**トループ取得技能を使用することはできない**（入れ子の取得は起きない）。

## トループ取得技能の起動 ＝「NPC取得」用途（2026-07-03 確定・2026-07-04 設計詰め直し中）

トループ取得技能の用途（usage）として、D&D 5e の「召喚」アクティビティに相当する**「NPC取得」用途**を設ける（フェーズ11 実装。usage 基盤への用途タイプ追加＝設計合意の対象）。

- **起動のみ**のもの: 小分類「エキストラ」の**アウトフィットを入手**する（アイテム取得。→下記「エキストラの二重表現」）。
- **起動後に判定**するもの: 判定を行い、**達成値分の人数（トループ）またはエニグマポイント（エニグマ）を持つアクターを取得**する。
- **分身**: 目標値 10。超えたら呼び出せる（人数/ポイントの付与でなく成否で決まる）。
- **モードは用途のモード選択で明示する**（2026-07-04 ユーザー裁定。Code の「参照先がアイテムかアクターかで導出」案は正しい区別でないとして却下）。

### エキストラの二重表現（2026-07-04 ユーザー言語化）

- 小分類「エキストラ」のアウトフィットは「アウトフィットとして表現されるエキストラ」ではなく、**「キャストが取得するためにアウトフィットという形で管理されるエキストラ」**である。
- トループがアウトフィット扱いで取得されないのは、おそらく**データを持てるか持てないかの違い**（エキストラは完全にデータレス→アイテムとして管理できる。トループは能力値・技能等を持つ→アクターでないと表現できない）＝ユーザー解釈。
- したがって正しい表現は**二重表現**: **アウトフィットとしてキャスト／ゲストに所有**されつつ、**エキストラアクターとして場に出られる**（トークンがシーンに出る）。
- 起動のみ（判定なし）の取得の想定: **使用することで派生データとしてエキストラを取得可能なタイプのアウトフィット**（例: 式神符 → 使用で「式神符（エキストラ）」を派生取得）。NPC取得用途では、**アウトフィットとしてのエキストラ取得とエキストラアクターが場に出るのが同時に行われるべき**。
- **エキストラアクターは共有**（2026-07-04 確定）: 基本は同じワールドアクター（のトークン）を使い回す。**自分専用のエキストラが欲しい場合はユーザーが新規アクターを作成して別途紐づける**（システムは複製しない）。

### 事前作成と所有者記録（2026-07-04 ユーザー言語化）

- **トループ／エニグマは、呼び出すトループ級キャラクターを事前に「作成」する必要がある**。キャラクター作成は自動化できないため、**複製機能は不要**（召喚＝事前作成済みアクターを場に出し、人数／ポイントを転記する）。
- **技能やアウトフィットの取得等には呼び出し元キャラクターの経験点を要する**（トループ・エニグマとも）。
- したがって肝要なのは、呼び出し元（技能）側に召喚可能なトループ級キャラの ID を記録する機能ではなく、**トループ級キャラクター側に「自身の所有者であるアクター」を記録する処理**である（経験点の出所の紐づけ）。
- **権限**: トークン配置（および必要ならアクター作成）の権限が要る。**モデルにしている D&D 5e でも、権限が無い場合は召喚用途を使ってもキャラクター配置はできない**——権限委譲の仕組みは作らず、無ければ配置できないだけとする。
- **配置の UX**（2026-07-04・dnd5e 実装を一次情報で確認）: dnd5e の召喚配置は**トークン自体の半透明プレビューがカーソルに追従し、左クリックで確定・右クリックでスキップ**（グリッドスナップ・Shift で解除。`module/canvas/token-placement.mjs` の TokenPlacement）。クロスヘアは出ない（Code の当初発言は誤り）。TNX もこの挙動を踏襲する。
- **分身の成否**: 目標値 10 ＝ 通常判定の規約どおり**達成値 10 以上で成功**（「超えたら」は口語であり、目標値という語の規約が優先）。

### 所有トループの経験点（2026-07-04 ユーザー言語化）

- **経験点算入はフェーズ11-6 の範囲でやる**（ユーザー裁定: EXP 機能は既に出来上がっており、後続フェーズへ回す・フェーズを増やすと開発が複雑になる。今やるべき）。
- **消費対象は「全て」**: プレイヤーが取得するトループは、**プレイヤー（呼び出し元キャスト）の経験点によってしか**スタイル技能の取得・アウトフィットの取得・各技能の成長ができない。特定のキャストに「所有」されているトループが、**無条件取得技能の初期習得を超えるデータを持とうとした場合は全て経験点が消費される**。**スタイル技能の成長（レベル上昇）も当然消費対象**（2026-07-04 明示）。
- **所有者経験点のシート表示**（2026-07-04 ユーザー指示）: トループ取得技能で取得されるトループ級キャラクターのシートには、**取得元キャストの経験点を表示**する（消費可能な残量を所有側シートで確認できるように）。**分身は別**（表示しない）。
- **トループレベル／エニグマレベルの決まり方（2026-07-04 再聴取・ユーザー提供。当初言及を Code が記録し損ねていたもの）**: **トループ・エニグマを取得する技能のレベルが、そのままトループ・エニグマのレベルになる**。したがってレベル自体は独立した経験点消費対象ではない（取得技能のレベル＝所有者自身のスタイル技能として既に経験点計上される）。
- **呼称**: エニグマの場合は「トループレベル」ではなく**「エニグマレベル」**と呼ぶ（heads／エニグマポイントと同様のラベル切替）。
- **計上先は取得元キャストの「消費経験点」**（2026-07-04 明示）: トループ取得技能で取得されるとして作成されたトループ級キャラクターの消費経験点は、**取得元キャストの消費経験点として計上**されなければならない。EXP の権威は User flag だが、**単にユーザーに紐づけるだけでは成立しない**——**誰が取得元アクターなのかが必ず明示されている必要がある**（＝トループ級側の所有者アクター参照が消費計上の前提。参照から取得元キャストを特定し、そのキャストの消費計算に合算した上で、通常どおり User flag と同期する）。
- **ゲスト所有の例外（2026-07-04 ユーザー確定）**: ゲストがトループ取得技能を持っている場合、**そのトループの能力取得に経験点は消費されない**（Code の従前の「帰結」推定と同結論だが、ユーザー明示の確定ルールに格上げ）。
