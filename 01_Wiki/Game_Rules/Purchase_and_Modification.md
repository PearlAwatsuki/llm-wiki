# 購入判定・改造判定

購入判定・改造判定に関するルール解釈の正本。フェーズ8 後の設計議論で言語化（2026-06-20）。フェーズ16（辞典ブラウザ＋購入・改造判定UI・旧17＝2026-08-30 正規化）の設計インプット。

## 購入判定

- アウトフィットの**購入値を目標値**として〈信用〉判定を行う。
- 〈信用〉判定は**カードを出さなくても判定でき**（→ [Check_Rules.md](Check_Rules.md) の信用判定カードなし特例）、その場合の **達成値 = 外界（実効値）＋ 消費報酬点**。
- 結果として、**購入値が外界点以下のアウトフィットはいつでも入手可能**。
- 対象アウトフィットの選択は辞典ブラウザと連携する（フェーズ16）。
- **使用技能は用途タイプ「購入」で表現する**（2026-08-31 ユーザー裁定）: 購入判定を行う効果のスタイル技能が存在するため、「指定技能として扱う」方式でなく**購入用途タイプの追加**を採る。理由（ユーザー言語化）=購入判定は情報収集や登場判定と違い「都度指定されるのではなく、そもそもデフォルトで使用する技能が決まっている」＝物理攻撃などと性格が近い。〈信用〉の購入判定も、購入判定を行うスタイル技能も、同型の購入用途で表現する。
- **プレアクト購入の条件（2026-08-31 ユーザー提供・verbatim 2件）**: 「プレアクト購入はそのキャストの外界以下の購入値を持つアウトフィットを対象に行えます。また、常備化経験点による取得は入手であっても購入ではありません」（後段の原文は「入社であっても」・文脈から「入手」の変換ミスと解釈して記録）＋「常備化経験点が「-」のアイテムはプレアクト購入できません。正しいです」。
  - 成立条件＝**①購入値が値を持つ（「ー」「解説参照」は対象外） ②常備化経験点が値を持つ（「ー」は不可） ③購入値 ≤ そのキャストの外界（実効値）**。
  - **常備化（常備化経験点による取得）は購入ではない**＝概念の区別（入手ではあるが購入の手続きではない・購入のフラグ isPre-play/isCheckAcquired は常備化に適用されない）。この文は常備化経験点欄が購入条件に無関係という意味では**ない**（Code が一度そう誤読して②を撤去→同日 verbatim で復元）。
  - 経緯: Code の当初実装は条件未確認の無条件付与（誤り）→ ①③＋②撤去（②の撤去は誤読）→ 本 verbatim 2件で①②③に確定・即日是正。
- **入手経路の全体像（2026-08-31 ユーザー提供・verbatim）**: 「そもそも、購入値が「-」となっているアウトフィットはプレアクト購入も購入判定による取得もできません。常備化経験点が「-」となっているアウトフィットはアクト中の購入判定による入手だけが経路であり、プレアクト購入も、当然経験点を消費しての取得もできません」。
  - 経路マトリクス（帰結の整理）:

| 購入値 | 常備化経験点 | プレアクト購入 | アクト中の購入判定 | 常備化（経験点消費） |
|---|---|---|---|---|
| あり | あり | 可（外界以下） | 可 | 可 |
| 「ー」 | あり | 不可 | 不可 | 可（唯一の経路） |
| あり | 「ー」 | 不可 | **可（唯一の経路）** | 不可 |
| 「ー」 | 「ー」 | 不可 | 不可 | 不可 |

  - システム側の強制点: 購入経路は各フローのゲート（購入値「ー」=全購入経路不能・常備化経験点「ー」=プレアクト購入不能）と isPre-play トグルの不能化。**素の所持そのもの（ドラッグ付与等）は制限しない**（アイテム管理は RL・卓の裁量）。
- **プレアクト購入の実装形（アクト未開始時のブラウザ購入・2026-08-31 ユーザー指示）**: アクトが開始されていない状態では、辞典ブラウザの購入ボタンは購入判定フローでなく**プレアクト購入**として働く——判定・報酬点を使わない取得（条件=購入値≤外界の確認→付与）で、付与した複製に既存フラグ `isPre-play`（Outfits.md=常備化経験点を支払っていないがプレアクトで購入して所持・経験点消費なし）を立てる。**信用判定経由（技能起点の選択ピッカー）はアクト状態にかかわらず通常の購入判定**。入手区分のフラグ対応: 判定経由（カード判定・カードなし特例・常時入手）＝`isCheckAcquired`／プレアクト購入＝`isPre-play`（どちらも経験点計上なし・計上ありは素の所持=常備化のみ）。
- **変則効果「購入判定を行い、改造されたアウトフィットを入手する」**（改造技能・2026-08-31 ユーザー提示）: 購入用途の任意属性「改造して入手」（既定オフ・データ入力時に設定）で表現する。オンの購入は**成功後・付与直前**に改造項目の選択（対象の分類別改造可能項目から1つ・＋［当該技能レベル］・キャップ等は改造の一般則どおり）が挟まり、付与した複製の改造専用修正フィールドへ書き込む。着地先が 16-4 の成果物のため、16-3 は完了継続ペイロードの席（modSpec）まで・**属性の有効化は 16-4**。

## 改造判定

- 改造対象が属する**大分類または小分類に対応した製作技能**と、改造技能を**組み合わせて**行う。
- アウトフィットごとに効果が適用されるため、**同名効果重複不可の原則（TRPG の大原則）は適用されない**（同一キャラが同名アウトフィットを複数所持していても各々改造できる）。
- **改造の重複規約（2026-08-31 ユーザー提供・verbatim）**: 「改造技能は例外的に、違う項目を改造する分には効果が重複します。同じアウトフィットの別々の項目を同じ改造技能で改造可能です。ただし、すでに改造されている項目は別の改造技能であっても改造できません。これも「同名効果重複不可」の原則の一部です」。
  - 帰結: **1つのアウトフィットの1つの項目に適用できる改造は1回だけ**（技能を問わず）。同一アウトフィットの**別々の項目**へは同じ改造技能で何度でも改造できる（項目違い=別効果）。項目選択 UI は改造済みの項目を不能表示にする。
- **項目が「ー」（なしの状態）のものは改造技能で修正できない**。「解説参照」も同様。
- **技能の目標値に購入値が指定されている場合、購入値が「ー」のアウトフィットは改造できない**。
- **1回の改造判定で改造できる項目は1つまで**。
- **改造の効果はアクト終了で元に戻る**（2026-08-31 ユーザー報告「改造された数値がアクトが終了しても戻りません」を是正＝アクト終了境界で改造行を全除去・故障/破壊/消費アイテムのリセットと同じ着地。ドラッグのマイナーアクション化も同時に解除）。手動解除＝アイテムシートの改造セクションのゴミ箱・アウトフィット行の右クリック「改造を解除」（2026-08-31 ユーザー指示）。
- **項目選択は判定前に行う**（2026-08-31 ユーザー裁定「項目選択は判定前に行います」＝対象選択→項目選択→判定→成功で適用。「改造して入手」の変則効果も同型＝選択→購入判定→成功で改造済み複製を付与）。
- **ドラッグ特殊の実装形**（2026-08-31 ユーザー提案・Code 同意）: ドラッグには使用するための用途が設定されている前提で、**選択したドラッグの用途のタイミングを一時的にマイナーアクションへ上書き**する（改造記録としてドラッグ側に載せ、タイミングの読者=戦闘タブ・記帳が実効タイミングとして解決する）。
- **複数の分類を持つアウトフィットは、両方（すべて）の分類として扱う**（2026-08-30 ユーザー言語化）: そのアウトフィットが持つ**いずれかの分類に対応した製作技能一つ**で改造でき、**全ての分類が指定する改造可能な項目**を修正できる。

### 改造可能な項目（分類別・2026-08-30 ユーザー提供＝本表が正本）

各分類とも「以下の項目から一つを **＋［レベル］**」（［レベル］＝当該改造技能のレベル。ドラッグの行の記述より）。住居（住宅施設）とドラッグのみ形式が異なる。

| 分類 | 改造可能項目 |
|---|---|
| 武器 | 隠匿値（危険値は除く）・攻撃力・受け値・電制 |
| 防具 | 隠匿値（危険値は除く）・防御力（S/P/I 全て）・制御値修正・電制 |
| ヴィークル | 隠匿値（危険値は除く）・攻撃力・防御力（S/P/I 全て）・制御値修正（**最大0**）・乗員・スロット・電制 |
| サイバーウェア（IANUS・全身義体以外） | 隠匿値（危険値は除く）・電制 |
| サイバーウェア（IANUS） | 隠匿値（危険値は除く）・制御値修正・電制 |
| サイバーウェア（全身義体） | 隠匿値（危険値は除く）・防御力（S/P/I 全て）・攻撃力・受け値・電制 |
| トロン（タップ以外） | 隠匿値（危険値は除く）・電制 |
| トロン（タップ） | 隠匿値（危険値は除く）・電制・スロット：ソフトウェア・スロット：ハードウェア・CS |
| 生体装備 | 隠匿値（危険値を除く）・電制 |
| 住居（住宅施設） | **以下のいずれか一つを適用**: 登場判定目標値に＋［レベル］または −［レベル］／セキュリティ（電脳・アナログ全て）に＋［レベル］ |
| 住居（住宅オプション・住宅アクセサリ） | 隠匿値・電制 |
| ドラッグ | **特殊（パラメータ修正ではない）**: 改造技能の使用時に、［レベル］個の所持しているドラッグを選択。選択したドラッグが**マイナーアクションで使用可能**になる |
| その他 | 隠匿値（危険値を除く）・電制 |

- 「防御力（S/P/I 全て）」「セキュリティ（電脳・アナログ全て）」は、1回の改造で該当フィールド全てに適用する。
- 「隠匿値（危険値は除く）」＝隠匿値のみが対象で、対の危険値は改造で変わらない。

### 改造の表現形（2026-08-30 確定）

**改造専用の修正フィールドを新設**する（ユーザー裁定＝Code 推奨案の採用。AE 表現案は不採用・素値の直接書き換えは元より選択肢にない）。素値（辞典原本値）は保ち、アウトフィット側の改造記録を `prepareDerivedData` で実効値に合流させる。

### 複数分類の表現（2026-08-30 確定）

現状のデータ表現（`majorCategory`/`minorCategory` の単一値＋ `isCyber` 等の特徴フラグ）では「複数の分類を持つアウトフィット」を正確に表現できない（ユーザー提起）。以下で確定（2026-08-30 ユーザー裁定）:

- **データ**: 副分類の配列を outfit へ追加（Code 提案採用）。主分類は据え置きで、置き場所（シートのグループ表示・部位/スロット）の権威のまま。
- **UI（ユーザー指定・verbatim）**: 現行の分類入力の右端に**チェックボックス**を追加し、ツールチップで「複数の分類を持つアウトフィット」を表示。チェックを入れると下に**1行目と同じ形式の二つのプルダウン**が出現し、その行の右端に**さらに3行目を追加する追加ボタン**。**3行目以降の右端はゴミ箱の削除ボタン**。
- 分類の判定は**ヘルパー1つに一本化**（主分類＋副分類の集合を返す。Code 提案採用）。
- **isCyber は副分類に完全に統合する**（2026-08-30 ユーザー裁定・verbatim「isCyberは副分類に完全に統合します」）:
  - `isCyber` フィールドは**廃止**。シートの特徴フラグ欄からも撤去し、「主分類サイバーウェア→isCyber 自動セット」機構も撤去する。
  - 既存データは移行する（isCyber=true かつ主分類≠サイバーウェア → 副分類にサイバーウェアを追加。主分類=サイバーウェアの自動セット分は移行不要）。**ユーザー正本データの書き換えを伴うため、実装時に移行の実施を明示報告する。**
  - 帰結（Code 整理）: 「サイバーウェアか」を問う全読者——部位ホスト照合・「※」表示・**電子妨害カウント**——は分類判定ヘルパー経由となる。電子妨害は従来 isCyber 横断を数えていなかったため、**体内武器等（副分類サイバーウェア）が新たにカウント対象になる挙動変化を含む**。
  - 修理対応分類・サービス免疫等の他のルール読者も同様にヘルパー経由へ統一する（Code 提案＝「両方の分類として扱う」原則の帰結）。

### 製作技能の対応分類（2026-08-30 確定）

製作技能はそもそも**分類を指定して取得する**技能である（ユーザー言語化）。一般技能に「**対応分類**」の項目を追加する（社会技能の下位区分 `societyClass` と同じ形＝区分が製作（craft）のときのみ表示・2026-08-30 ユーザー裁定）。

- **大分類サービスの製作技能は存在しない**（サービスとその配下小分類を選択肢から除外）。
- **小分類も選べるようにする**（大分類キー・小分類キーは全体一意＝修理対応分類 `repairableCategories` と同じキー空間）。
