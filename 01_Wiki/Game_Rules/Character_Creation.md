# キャラクター作成

TNX のキャスト作成・成長に関するルール解釈の正本。フェーズ8 後の設計議論で言語化・確定（2026-06-19）。

作成方法は複数あるが、本書は**フルスクラッチ作成**を基準に記述する。

## 作成フロー（フルスクラッチ）

### 1. スタイル選択

- スタイルはキャラクターの**生きざま**を表すデータ（「ジョブ/クラス」より広い概念）。
- **3スロット**を持つ。同じスタイルを複数選んでよい。
- 同一スタイルの重複数を**スタイルレベル**と呼ぶ（重複なし=Lv1、2つ=Lv2、3つ全部同じ=Lv3）。レベルの合計は常に3。
- スタイルレベルは**スタイル技能のレベル上限**や、一部スタイル技能・アウトフィットの**取得条件**で参照される。

データ: `style` Item（`scripts/data/item/style.mjs`）。`level` がスタイルレベル。

### 2. 能力値・制御値の決定

- 各スタイルに**能力値の基本値**と**制御値の基本値**が設定されている（`style` の `reason/passion/life/mundane` 各 `{value, control}`）。
- 3スタイルの基本値を**合計**して能力値・制御値を決める。スタイルレベル2/3のスタイルは、設定値を**レベル分倍化**して計算する。
- スタイルの能力基本値は**最低0**。マイナスは存在せず、特定の効果でマイナスにもできない。

### 3. 神業

- 各スタイルに**神業が1種**設定されている（`style.miracle`）。
- **各アクト1回ずつ**使用できる。スタイルレベルが上がると同じ神業の使用回数が増える（Lv2=2回、Lv3=3回）。
- 1スタイルを Lv3 で持つキャストは、神業1種を3回使える。

→ 使用回数のリセット単位（アクト）は [時間管理] の領域（後述の申し送り）。

### 4. 技能取得

**基本技能（無条件取得・固有名詞でない一般技能）**: 全キャストが下記13技能を必ず**1レベル**で所持する。初期スートが固定されており、初期レベルでの組み合わせ判定に実質的な制限がかかる。

> 医療 / 射撃 / 知覚 / 電脳 / 心理 / 自我 / 交渉 / 運動 / 回避 / 白兵 / 圧力 / 信用 / 隠密

**選択取得（スート自由）**:
- 都市社会に属する技能を1つ
- コネ技能を合計1レベル
- 社会技能を2レベルまで（1技能を2Lv、または1Lv技能を2つ、いずれも可）

データ: `generalSkill` の `generalSkillCategory`（`initialSkill` / `onomasticSkill`）。

### 5. アウトフィット取得

- **無条件取得（取得は任意）**: IANUS と住居1つ。
- **ウェット排他**: IANUS はサイバーウェアのため、「ウェット」（サイバーウェアを一切入れていない状態を表すサービス／バックグラウンド系アウトフィット。ウェットが取得条件のスタイル技能・アウトフィットがある）を取りたい場合は IANUS を取得できない。
- **住居**: 外界値に応じて取得できる選択肢が増減する。種別とエリアが固定の組み合わせで提供されるため、別の組み合わせや特定エリアを選ぶには経験点で取得する。経験点で住居を取った場合、無条件取得の住居は取らなくてよい（2つ以上持つこと自体は可）。

### 6. パーソナルデータ（ライフパス）

- ライフパスは**出自 / 経験 / 邂逅**の3種をそれぞれ1つずつ選ぶ。経歴・背景に当たる。
- 技能習得: 出自＝社会技能1Lv、経験＝国家社会またはコネ1Lv、邂逅＝コネ1Lv。
- 「4. 技能取得」の固有名詞技能枠を新規取得せず、ライフパスで習得した社会・コネを**成長させる**選択も可能。

データ: `lifePath` Item（`lifePathType` = origin/experience/encounter、`skillName` = 習得技能名）。

### 7. 経験点（170点）

経験点170点分で、能力値成長・制御値成長・技能成長・技能取得・アウトフィット取得を行う。経験点は**プレイヤー（User）単位**で管理される（FEAR系の特徴。User flag 保持）。

**作成時上限**（成長分を含む）:

| 対象 | 上限 |
|---|---|
| 能力値 | 10 |
| 制御値 | 16 |
| 技能レベル | 3 |

**経験点コスト**:

| 対象 | コスト |
|---|---|
| 能力値・制御値の成長 | 20点 |
| 能力値を11以上 / 制御値を17以上に成長（作成時は不可） | 40点 |
| 基本技能（無条件取得技能）の成長 | 10点 |
| 固有名詞技能の取得・成長 | 5点 |
| アウトフィット取得 | 常備化経験点（購入値欄の右側の数値）分 |
| スタイル技能 | 種別ごと（下記） |

## スタイル技能

スタイルを所持していることで取得可能になる技能。種別は4つ。

| 種別 | データキー | コスト | 取得数制限 |
|---|---|---|---|
| 特技 | `special` | 10点 | 無制限 |
| 演出特技 | `performance` | 2点 | 無制限（具体的効果を持たない演出用） |
| 秘技 | `secret` | 20点 | スタイルレベル×2個まで |
| 奥義 | `mystery` | 50点 | スタイルレベル個まで |

- **ワークス技能**: スタイルではなく**所属組織（ワークス）**に紐づくスタイル技能。特技のみ存在し、取得・成長はスタイル技能に準じる（`styleSkill.special.works`）。同様に、特定ワークス所属が条件の**ワークス専用装備**も存在する。
  - **部署技能**（2026-07-03 確定・フェーズ11-4）: 部署を表すワークス技能（`special.works.isDepartment`・ワークス技能 ON のときのみ設定可）。取得していると**所属名（ワークス名）の表示がこの技能の名前で上書き**される（トループはトループ名の組織名部分も → [Troops.md](Troops.md)「部署技能による上書き」）。
  - **代用技能はワークス技能・特技に限らない**（2026-07-03 確認。スタイル技能シートの旧「特技専用」セクションは「ワークス技能」「代用技能」「神業の書き換え」に再編し、代用技能は全カテゴリで設定可能）。

データ: `styleSkill` Item。`styleSkillCategory` が種別。

### スタイル技能の特殊取得・自動習得（フェーズ10・2026-06-25 確定）

一部のスタイル技能は、習得時に他の実体を取得したり、特殊な取得条件を持つ。これらをシート上で扱うための機能をフェーズ10 で整備する。

- **習得時の自動取得**: スタイル技能の中には、習得することでトループや武器を取得するものがある。スタイル技能をアクターにインポート（作成）した時、設定された対象を自動取得する。
  - **トループ取得技能**: トループ、または指定された種類のトループ級キャラクターを取得する。マヤカシの秘儀〈分心〉→「エニグマ」、カゲの奥義〈分身〉→「分身」。取得対象は**アクター**。実装は **NPC取得用途**（フェーズ11-6・[Troops.md](Troops.md)「NPC取得」）——取得対象はトループ/エニグマは用途側の取得アクター参照、分身は対象設定なしの直接召喚。※フェーズ10 の技能側 ID 関連付け（autoAcquireActors）は 2026-07-08 廃止（用途側へ一本化）。
  - **武器取得技能**: 取得対象は**アイテム**で、自動生成する。
    - 取得武器には「その武器を使用して判定しなければならない」ものと「取得のみで使用は任意」のものがある → **使用義務フラグ**で区別する。
    - 自動取得武器には、**同カテゴリのスタイル技能から一度取得すれば以後取得されない**ものがある → 「スタイル技能由来の武器」マークと「重複取得不可」フラグを表示し、**識別キーのプレフィックス**で同種を照合して弾く。
- **経験点消費なし取得**: スタイルを取得した時点で自動習得するスタイル技能（例: クロガネは「フォルム」をどれか1つ自動習得）や、2技能セットで片方を取得するともう片方も自動習得するものがある。これらのために「経験点消費なしで取得可」を設け、経験点消費を無効化する。
- **取得数カウントの除外**: 特殊な取得条件・取得方法のスタイル技能のために「秘技の取得数に含まない」「奥義の取得数に含まない」を設ける。取得数は**表示のみ・非強制**（上限は強制しない）で、付いた技能を表示カウントから除外する。
- **他スタイル技能レベルの自動参照**: 模造技能、アヤカシ〈血脈〉と〈血脈（魔性）〉（2技能で対になる種別）などのために、指定したスタイル技能のレベルを参照し、**この技能の「レベル」欄の数値を上書き**する。スートは事後に手動選択する想定。**判定システムは関与せず**、通常通り（上書き後の）レベルを読むだけ。指定方法は、辞典／ワールド直下では**識別キー**、アクターにコピーした時は**ドロップダウン選択**（入力欄がプルダウンに置換）。元々識別キー指定があれば、アクター内の該当識別キーのアイテムを探して自動選択する。

## ワークス（所属組織）

- キャストは**必ず1つ**のワークスを持つ。
- 設定上の所属とデータ上のワークスを使い分けることはできない（一部のワークス技能が「他のワークス技能を取得する」効果を持ち、その場合のみある種の使い分けが生じうる）。
- 技能取得に関わるため、**経験点消費の前まで**に決定しておく（途中追加されたルールのため、フロー上の正確な位置は未定）。

データ: `organization` Item type。

## 技能体系

- **一般技能** = 基本13技能（固有名詞でない・初期スート固定・全員1Lv）＋ **固有名詞技能**（スート自由）。
- **社会技能の下位区分**（国家社会 / 都市社会 / 業界社会 / 団体社会）は、いずれも社会技能の一種。**データには下位区分を持たず「社会技能」一括**で扱う（区分単位バフは対象が有限なため対象技能の列挙で代替でき、`identificationKey` で個別指定も可能。フラグ化は入力負担を増やすため見送り）。
  - 区分タグは設けないことで決着（2026-06-20、フェーズ9 論点3）。区分バフは公式社会技能の identificationKey を列挙して対象指定する。

### 使用可能スートとレベル

- 各技能は**初期スートを1つ**持つ（基本13技能は固定。固有名詞技能は習得時に1つ選択）。
  - 基本13技能の初期スート: ♠ 医療・射撃・知覚・電脳 / ♣ 心理・自我・交渉 / ♥ 運動・回避・白兵 / ♦ 圧力・信用・隠密
- **技能レベル数 ＝ 使用可能スート数**。1レベルにつき1スートが使え、成長時に好きなスートを1つ追加する（最大4で全スート使用可能）。1レベルあれば必ず1スートは使える。
- スタイル技能はレベル上限（3・4 等）により、全スート使用可能にならないことがある。
- 一般技能は特殊効果を持たないため5レベル以上に上げる実利は薄いが、高級なスタイル技能・アウトフィットの取得/発動条件に「特定の一般技能が5レベル以上」等があるため、条件達成目的で上げる場合がある。

データ: `skill-base` の `suits`（4スートのブール）と `level`。true の数 = level に対応する。

### アクション技能

- 定義: **行動の基準になる技能**。攻撃・防御など、何らかの行動を行う技能。
- 戦闘の「アクション」と直接対応するわけではないが、戦闘中の行動を行う技能はアクション技能であることが多い。
- **アクション技能同士は組み合わせ不可**（矛盾する2つの行動を同時に行うことになるため）。判定コンボでは常にベース技能になる（→ [Check_Rules.md](Check_Rules.md) のコンボ規則）。
- 現ルールのアクション技能: 射撃・心理・自我・回避・白兵・圧力・信用、および芸術を除く固有名詞技能。

データ: `skill-base` の `isAction`。

## 能力値・制御値の上限と最終値clamp

- **作成時上限（能力値10 / 制御値16 / 技能Lv3）はシステムで強制しない。** 初期作成状態と成長後状態を区別できないため。上限はユーザーが運用上守る（DataModel に min/max を入れない方針は `style.level` と一貫）。
- **最終実効値は0を下回らない。** 実効値 = `max(0, growth + Σ(スタイル基本値 × レベル) + mod + effectMod + outfitMod)`。clamp は**全修正を合計した最終値**に対して行う（順序非依存）。能力値・制御値の両方に適用。
- あらゆる負方向修正に0の閾値が効く。原文は「修正で能力値/制御値が負になる場合、その技能の効果を全て受けられない」だが、**0clamp として実装する**（ユーザー確定）。
- **増減をセットで持つ技能**（特定能力値を増強する代わりに別の能力値を減少させる技能）で生じる矛盾（clamp によりデメリットが軽減されメリットだけ残る等）は**自動化しない**。キャラクターごとに AE を手動調整（増減を共に1にする等）で対応する。RL判断も伴う領域のため、システムは「最終値が0を下回らない」ことのみ保証する。

## スタイルの役割（ペルソナ / キー / シャドウ）

- 役割は**アクトごと**に設定する（キャラクター作成時には決めない）。
- **ペルソナ** = 表の顔（何で生計を立てている／他人からどう見られるか）。**キー** = キャラクターの本質。**シャドウ** = 本人も気づかない、または隠しているスタイル。
- データ表現: `style` の `isPersona` / `isKey` の2フラグ。**マークなし（両方 false）＝シャドウ**。1スタイルがペルソナかつキー（両 true）の場合、残りは全てシャドウ。シャドウ専用フラグは不要。
- キャストシートのトグルで設定する（スタイルシートを開かずアクトごとに切り替えやすくするため）。
- **キースタイルはキャスト間で重複不可**（同じキーを持つキャストが同一アクトにいる場合は相談してずらす）。現状は手動。
