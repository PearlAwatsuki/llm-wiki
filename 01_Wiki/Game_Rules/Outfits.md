# アウトフィット（装備品）

フェーズ6 設計時（2026-06-12）にユーザーが言語化したルール解釈の記録。
outfitBase 共通フィールドの意味と UI 設計の根拠を定める。一次情報はユーザー。

## 共通パラメータ

### buy — 購入値（略号「購」）

- 購入判定の目標値。購入判定は基本的に「★信用」技能で行う
- 本来は常備化経験点（preserveExp）と合わせて一つのパラメータであり、
  「購：購入値／常備化経験点」の形で表記する
- 値は「なし」「数値」「解説参照」の 3 状態（UI はドロップダウン選択）
  - なし → 「-」表示
  - 数値 → その数値
  - 解説参照 → preserveExp の表示を消し、「購：解説参照」とだけ表記する
- DataModel 表現: `buy: { mode: none/value/reference, value: Number }`

### preserveExp — 常備化経験点

- 常備化（プレアクト時点までの購入）に必要な経験点
- **「なし / 数値」の 2 状態**（フェーズ6-4 で NumberField から {mode,value} に変更。値のない場合は「-」表示）
- DataModel 表現: `preserveExp: { mode: none/value, value: Number }`

### hide — 隠匿値（略号「隠」）

- アウトフィットを発見するための〈知覚〉判定の目標値
- 危険値と合わせて「隠：隠匿値／危険値」の形で表記する
- 値は「なし」「数値」「解説参照」の 3 状態（buy と同じ構造）
- **解説参照でも危険値は別個に設定・表示される**（例: 「隠：解説参照／-1」）
- DataModel 表現: `hide: { mode: none/value/reference, value: Number }`

### appearancePenalty — 危険値

- 携帯していると、全アウトフィットの危険値の合計分が登場判定目標値への修正になる
- **「なし / 数値」の 2 状態**（フェーズ6-4 で NumberField から {mode,value} に変更。値のない場合は「-」表示）
- DataModel 表現: `appearancePenalty: { mode: none/value, value: Number }`

### hack — 電脳制御値（略号「電制」）

- アウトフィットへのハッキングを試みる〈電脳〉判定の目標値
- 「なし / 数値」の 2 状態のみ（解説参照はない。2026-06-12 確認）
- シート表記は略号「電制」を使う（2026-06-12 確認）
- UI は購入値と同様のドロップダウン選択（なし/数値）
- DataModel 表現: `hack: { mode: none/value, value: Number }`

### part — 装備部位

- 一つの部位には基本的に一つのアウトフィットしか装備できない
- 二つ装備可能な部位: 「片手持ち」「片腕」「片足」「指」の 4 つ
  - 「両手持ち」=「片手持ち」×2、「両腕」=「片腕」×2、「両足」=「片足」×2 を消費
- 「籠手」は手系の装備部位（「片手甲」「手の甲」「指」等）を全て埋める排他関係
  （「片手持ち」など“持つ”系は例外）
- 「武器2」のように後置数字が付く場合、その部位のスロットをその数だけ消費する
  （「武器2」は武器スロット 2 つ消費 → スロットが 2 つ以上ある場合のみ装備可）
- 種類が多すぎるため **部位名の UI は自由入力**（ドロップダウンにしない）
- 部位名とスロット数は別フィールドで設定する（2026-06-12 確認）。
  表記はスロット数 1 のとき部位名のみ、0 または 2 以上のとき「武器2」「部位0」のように数値を付す
- **複数部位を占有する場合がある**ため行の追加・削除に対応（2026-06-13 確認）。複数行の連結表記は下記「部位管理」の表示ルールへ移行（2026-06-26）

#### 部位管理（フェーズ10・2026-06-25〜26 確定・ロック）

部位は**ユーザー入力ベースで管理**する（特定部位を持たないキャラ等、部位ルールが多く自動入力に任せきれないため）。公式の「部位」指定（任意系・複数部位・表記ゆれ含む）をすべて、自由入力の値＋数個のフラグで表現する。

##### part 行のスキーマ

各 part 行は **5択の種別（kind）** を起点に、種別連動の入力を持つ。

| kind | 入力・意味 |
|---|---|
| `none`（「-」） | 部位なし（非消費） |
| `bodyPart`（身体部位） | プリセット由来の部位名（`value`）＋消費数（`slots`） |
| `option`（オプション） | 装備先ホストを大分類 `hostMajor`／小分類 `hostMinor`＋除外トグル `hostMinorExclude`／その他特徴 `hostFeature`／アイテム名 `hostName` で指定（＋消費数 `slots`）。アイテム名ありは**名前で完全照合**（旧 outfitName）。大分類サイバーウェア指定は `isCyber=true` のアイテムも拾う（※付き＝サイバーウェア扱いの裁定）。その他特徴は当面 `isLaser`（レーザー武器）のみ。`変異器官` はフラグ未存在のため 10-2 で新造 |
| `reference`（解説参照） | 表示は**常に「解説参照」**（説明タブはルルブ表示を完全踏襲）。下に部位設定欄（`bodyPart`／`option`／`other`／`none`。**解説参照の入れ子は不可**）を持ち、**占有計算には実部位が効く** |
| `other`（その他） | 自由記入（`value`）。占有計算対象外 |

- **任意は部位全体フラグ `partOptional`**（行ごとではない・2026-06-26 修正）。任意系（`任意`／`任意(指)` 等）を表し、**占有数にカウントしない（重複可・無制限）**。括弧内（指 等）は `bodyPart` 行の `value` に入れて部位名として扱う。素の「任意」は行なし／値空で「任意」表示。
- **part 全体に `relation`（`and`／`or`）**: 2行以上のときの結合。`and`＝全部占有、`or`＝択一。装備先は and では自明、**or のときだけ装備先トグル `orChoice`** で選ぶ（占有側のみ・説明タブ表示には影響しない）。
- 旧 `isOption` フラグ・旧 part 種別（slot/outfitName）・restrictCategory は**この5択＋ホスト指定**に吸収（廃止。アウトフィットシートの「性質」→「特性」改名・旧オプションチェック/装備対象は撤去）。
- **既存 part データ（`{value, slots}`）は kind=`other`（自由記入）へ移行**（§4.2＝文字列から種別を推測しない／表示は保たれる）。
- DataModel 表現: `part: ArrayField({ kind, value, slots, hostMajor, hostMinor, hostMinorExclude, hostFeature, hostName, refSubKind })` ＋ 兄弟 `partRelation`（and/or）`partOrChoice`・`partOptional`（任意＝部位全体）。

##### 表示ルール（ルルブ表記に一致させる・実装は純粋関数 `part-helpers.mjs`）

- **身体部位は数字を付けない**（「片手持ち2」とはしない。2占有は専用部位名＝両手持ち がある）。数字は占有計算と**オプション専用**（武器0 等）。
- **and** → 「A+B」 / **or** → 種別で連結子が変わる: 任意でない身体部位「A、もしくはB」／スロット持ちホスト（option）「A／B」。
- **任意（部位全体 `partOptional`）** → 「任意(A、B…)」（連結は「、」）。`other` を含めば内側末尾「など」。素は「任意」。
  - 例: 部位全体=任意＋行〔other・option武器・option防具〕→ **「任意(武器、防具など)」**
- **オプションの部位名（スロット名）**: アイテム名あり→名前（アサルトナーヴス）。なし→スロット名。
  - **大分類レベルでスロットを共有する大分類は大分類名**（小分類/特徴は括弧で絞る）。これは**スロット持ち型から逆算**（`isMajorLevelSlotMajor`）するが、ルルブは経験的に**武器のみ**該当＝`MAJOR_LEVEL_SLOT_MAJORS=["weapon"]`。武器／武器(白兵武器)／武器0(白兵武器)／武器(搭載兵器以外)／武器(レーザー武器)。
  - **それ以外は小分類名**（船舶・タップ・IANUS）。ヴィークルは構造同型でも小分類名（武器が例外。理由不明・ユーザー観測 2026-06-26）。
- 実装: `formatPartDesignation`／`formatOptionLabel`／`computePartOccupancy`／`joinPartDesignations`（Foundry 非依存・28 テスト）。

##### キャスト部位スロット集合・占有

- **キャストが「部位スロット」の集合を持つ**（`partSlots = [{value, count, occupiesOther, targetPart, targetCount}]`）。ゲーム設定で**全アクター共通の初期プリセット**を定義し、新規キャストへ流し込む。キャスト側でも追加／削除できる。プリセットはフェーズ10で設定まで完了。プリセット編集 UI はカード設定アプリ様式（standard-form・number-input-spinner）。
- **「指定部位を複数占有」エイリアス**（`occupiesOther`）: ある部位スロットを「別の指定部位（`targetPart`）を `targetCount` だけ占有する」エイリアスにできる。**両手持ち＝片手持ち×2** 等をこれで表現（占有時、両手持ちは片手持ちを2消費・count は無視）。公式に無い**排他部位**やルール追加にもユーザー設定で対応できる。占有計算はエイリアスを実部位へ展開して数える。
- **プリセットは体部位のみ**。個数は **片手持ち／片腕／片脚／指＝各2**、その他は各1。**両手持ち＝片手持ち2** 等は atomic（`{片手持ち, slots:2}`）で表現。**完全一致照合**（耳≠両耳、腕部≠腕 は別部位）。`下垂体` は `脳下垂体` を正としプリセット不採用（`任意(下垂体)` は非カウントなので衝突しない）。
- **占有 = 準備済みアウトフィットの part を部位ラベルごとに合算**し、キャストの該当スロット count と突き合わせる。
- **スロット非消費は3パターン**で母数から外す: ① `slots===0`（武器0 等）／② 小分類が**住宅アクセサリ**／③ **任意（partOptional・部位全体）**。
- **オプションの占有はホストから導出**（「スロット種別（ホスト名）」例「武器（雷神刀）」）。**分割不可**（単一ホストがまとめて持つ）。タップはソフト/ハード共通名「タップ」を「タップ/ソフトウェア（タップ名）」等で区別。
- **空き/埋まり・超過は表示のみ**（秘技/奥義の取得数表示と同思想）。自動強制・notification はしない。**超過時はシート上で視覚強調（赤等）**。
- §4.1: 部位ラベル集合の同梱は**構造的最小限**（短い機能ラベルの語彙集＝enum 相当）として許容。ラベルのみに留め、解説文・対応表は付けない。プリセットの中身（体部位ラベル・個数）はルール由来のためユーザーが editor で完成させる。

##### UI（D&D 5e「消費(Consumption)」UI を参考・2026-06-26）

- アウトフィットシートの部位設定は**独立 legend（`<fieldset class="tnx-fieldset"><legend>部位</legend>`）に分割**。先頭に `relation`（2行以上のとき表示）＋行追加ボタン。
- **行＝ブロックカード**（D&D の消費ターゲット カード様式）。上段に **種別(kind)｜消費数(slots・? ツールチップ)**、下段に**対象欄**を種別連動で表示。右下に削除。
  - 身体部位→部位、オプション→大分類/小分類＋除外/その他特徴/アイテム名、その他→自由記入、解説参照→入れ子(身体部位/オプション/その他)＋ラベルは常に「解説参照」、`-`→対象欄なし。任意チェックと消費数は `-` 以外で表示。
- **対象欄は文脈連動**（D&D の「目標」流）:
  - **ワールド直下**（辞典・ディレクトリ）＝**自由入力**（datalist 補完）。
  - **キャラクター所属**＝**そのキャラの持ち物/部位からドロップダウン**（身体部位→キャストの partSlots ラベル、オプションのアイテム名→ホスト条件に一致する所有アウトフィット名）。
  - アイテム名は**名前を保持してライブ照合**（UUID キャッシュ不可・都度解決。ドロップダウンは選択補助）。
- **or 装備先トグル**は占有側（キャストの占有パネル）に置き、説明タブ表示には影響させない。

##### 持ち越し（部位表示 UI を組む段で詰める）

- 任意の部位名・消費数の記録の細部、両手持ち等の**体部位表記マッピング**（`{片手持ち, slots:2}`→「両手持ち」表示）。
- 「別種別データを持つアウトフィット（武器＋タップ等）」＝`派生データ`フラグ・`変異器官`フラグ → **10-2（取得時自動取得）に合流**。

### timing — 使用タイミング

- カット進行上の使用タイミング（セットアップ、メジャーなど）が設定されていることがある
- 選択肢はスタイル技能の timing と共通（アクション/プロセスの二段選択を含む。2026-06-12 確認）
- **スタイル技能と違って一つしかあり得ない**（単一値。行追加なし。2026-06-13 確認）

### exclusive — 専用

- 特定のスタイルやワークス専用であることを表す
- 自由記述。自動化はしない（2026-06-12 確認）

### 真偽値フラグ（意味は 2026-06-12 ユーザー確定）

| フラグ | 意味 |
|---|---|
| `isPrepared` | **準備済み**。そのアウトフィットが使用可能な状態にあるかどうか。いわゆる「装備」に近い概念だが、大きさや機能的に身に付けられないアウトフィットにも適用される点が異なる |
| `isCarrying` | **携帯中**。そのアウトフィットを身に着けているかどうか。「所持」しているだけでは携帯中とはいえず、当然準備中ともいえない。キャラクターシートに存在する時点で「所持」は確定しているので所持フラグは存在しない |
| `isCyber` | サイバーウェアかどうか。種別がサイバーウェア以外のアウトフィットでサイバーウェアであるものを識別するのに必要 |
| `isPre-play` | **プレアクト購入**。常備化経験点は支払っていないが、プレアクトで購入して所持しているアイテムであることを表す。true だと所持した際の経験点消費がなくなる（表示名は TNX 用語の「プレアクト購入」とする。2026-06-13 確定） |
| `isOption` | そのアウトフィットが**別のアウトフィットに装備するオプション**であることを表す。装備対象のアウトフィットのスロット数がなければ装備できない（2026-06-12 確認） |

- `isCarrying` はフェーズ6 設計時に必要と判明し追加。**デフォルトは true**（2026-06-13 確定）

## 消費アイテム（isConsumption / quantity）

2026-06-12 ユーザー確定。weapon の旧 isthrow（投射武器）を全種別に一般化して置き換えた。

- `isConsumption` が true のアイテムは個数（quantity）を持ち、アイテム名の右に「×数字」で表示する
  （この数値入力は number-input-spinner を**使わない**例外）
- 消費で現在個数（value）を減らし、0 になるとそのセッション中は使用不可。セッションが終われば復活する
- 常備化経験点は個数分（max 基準）必要で、**消費しても経験点は復活しない**
- DataModel 表現: `quantity: { value: 現在個数, max: 常備化個数 }`（initial 1/1）

## 武器（weapon）固有パラメータ（2026-06-12 確定）

- **attack — 攻撃力（略号「攻」）**: ダメージ種別 + 値で「攻：I+4」のように表記。
  ダメージ種別は S（Slashing=斬撃）/ P（Piercing=貫通）/ I（Impact=衝撃）/
  X（エクストラ=装甲無視）の 4 種から**単一選択**（ドロップダウン。2026-06-13 確定）。
  「攻撃値」というパラメータ名は存在しない（シートでは「攻撃力」1 行で種別 + 値を扱う）
- **guardValue — 受け値（略号「受」）**: パリィをして判定に失敗した際にダメージから引かれる値
  （パリィは白兵判定で、成功すればその時点でダメージ無効）
- **range — 射程（略号「射」）**: 最低射程(min)は なし/至近/近/中/遠/超遠、最長射程(max)は なし/近/中/遠/超遠
  （最長から「至近」を除く。「なし」「武器」はいずれの選択肢にもない。フェーズ6-4 で min/max 選択肢を分離）。
  最低射程が「なし」のとき射程なし。最低=最長なら単点表記、異なれば「近～超遠」表記
- **isLaser**: レーザー兵器。レーザー兵器からの攻撃を受けない防具があるための識別フラグ
- **isFullAuto + FAValue**: フルオート射撃可能な武器。FAn の n（FAValue）をダメージに加算できる。
  フルオート射撃を行うと弾倉が空になり、マイナーアクションで交換が必要
- **attackArea — 攻撃範囲**: 「-/範囲/範囲（選択）/シーン/シーン（選択）」の 5 択。
  設定時、判定アイテムで武器攻撃の用途を設定するときに範囲を上書きできる（「-」は上書きしない）
- ~~**isBiological**~~: フェーズ6-4 で削除。生体装備はカテゴリ「生体装備」で識別する方針に変更。
  weapon の isBiological は 6-2 で outfitBase へ一般化されたが、6-4 でカテゴリ判定に置き換え除去。
- 概要表記順: **購/隠/攻/受/射/ス/電制/部位**（ス = スロット）

## 防具（armor）・サイバーウェア（cyborg）（2026-06-12 確定）

- **defence — 防御値（略号「防」）**: S/P/I の 3 値を「**防(S／P／I)：5／4／6**」のように並記
  （(S／P／I) の部分を省略してはならない。2026-06-13 確定）
- **controlMod — 制御値修正（略号「制」）**: ヴィークル等で出てくる場合も同じ意味
- 防具の概要表記順: **購/隠/防/制/電制/部位**
- **cyborg（全身義体）**: 概要表記順は **購/隠/防/攻/受/電制/部位**。
  武器や防具として使えるというより**生身にこれらのデータが付く**意味。
  防御力は防具と加算されるが、攻撃力と受け値は攻撃・パリィに義体を直接使う宣言をしないと
  適用されない。他に武器を持っていても加算されない（その武器を使った攻撃・パリィとはみなされないため）

## IANUS・トロン・タップ（2026-06-13 確定）

- **IANUS の概要表記順**: **購/隠/ス/表/深/無/制/部位**（**電制はない** — 編集欄も置かない）。
  表/深/無 = 意識スロット（表層意識/深層意識/無意識）の数、制 = 制御値修正
- **IANUSオプション**: オプションで唯一、装備対象アイテム（IANUS）とカテゴリが違う
  **一般アウトフィット（general）**
- **トロンの概要表記順**: **購/隠/ス/電制/部位**
- **タップの概要表記順**: **購/隠/ソ/ハ/CS/電制/部位**（ソ/ハ = ソフトウェア/ハードウェアスロット数）
- **combatSpeedMod（略号 CS）**: 制御値修正と同様、準備していることで CS（戦闘速度）に修正が
  かかるパラメータ
- **cycle — サイクル数（略号「サ」）**: タップの処理能力を表す数値。ハッキングの FS 判定に使用する
  （判定連携はフェーズ7-8。概要表記には含めない）

## ヴィークル（vehicle）（2026-06-13 確定）

- **speedFactor — 移動力（略号 SF）**: 数字分の段階移動ができる。キャラクターの通常移動が
  一段階移動なので、SF1 のヴィークルは戦闘移動としては生身と同程度
- **passenger — 乗員**: 操縦者を含む、そのヴィークルに乗れる人数。ヴィークルに登場している
  キャラクターはヴィークルの移動と同時に移動する
- ヴィークルは attack（攻）・defence（防）も持つ。概要表記順は **購/隠/攻/SF/防/制/乗員/ス/電制/部位**

## 住宅施設（residence）・住宅エリア（housingArea）（2026-06-13 確定）

- **住宅エリアは厳密にはアウトフィットではない**。住宅施設は取得時に必ず住宅エリアと
  組み合わせて取得する（組み合わせは自由）。データが分けて書かれているため便宜上アイテムとして
  実装するが、アウトフィットシートではなく専用シート（説明 + 修正値）とする
- **住宅エリアの持つ修正値**（住宅施設の対応値への修正）: 購入値 / 常備化経験点 /
  登場判定目標値 / 電脳セキュリティ / アナログセキュリティ / スロット
  （フェーズ6-4 で隠匿値修正を削除。住宅施設の hide は住宅エリアを加算しない）
- **住宅施設の持つ値**: 登場判定目標値（登）/ 電脳セキュリティ / アナログセキュリティ。
  実効値（住宅施設 + 住宅エリアの修正）の算出はフェーズ6-6 で扱う
- **appearanceTarget — 登場判定目標値（登）**: その住宅施設を舞台としたシーンの登場判定目標値となる
- **セキュリティ値（セ）**: 電脳セキュリティ（電）とアナログセキュリティ（ア）の 2 種。
  突破に必要な技能が異なる。表記は「セ(電／ア)」
- **area — エリア（セキュリティ・ランク）**: 住宅エリアが供給する。なし/レッド/グリーン/ホワイト/サンクチュアリ
- **住宅エリアの供給値**: エリア（ランク）+ 修正値 7 種（購入値/常備化経験点/隠匿値/登場判定目標値/
  電脳セキュリティ/アナログセキュリティ/スロット）。住宅施設の基本値に加算した実効値を説明タブに表示する
- **住宅エリアの設定方法**: 住宅施設シートに (a) 住宅エリア辞典（compendium `housing-areas`）からの
  ドロップダウン、(b) アイテムのドロップ の 2 方式。(b) で設定した場合 (a) は無効化。
  住宅エリアはアウトフィットでないためアクターシートへのドロップは弾く（2026-06-13 確定）
- 住宅施設の概要表記順は **購/隠/登場/セ(電／ア)/ス/部位**。
  **危険値と電制がない**（特に危険値は他種別では隠匿値とセットだが住宅施設にはない。隠は隠匿値のみ表記）
- **住宅オプション・住宅アクセサリは一般アウトフィット（general）**。住宅オプションはスロットを
  消費するが、住宅アクセサリはスロット数に関係なくいくつでも準備できる（準備可能数の扱いは 6-6）

## コンバイナー（combiner）（2026-06-13 確定。合成表示は未実装）

- 指定された特徴を持つ**二つのアウトフィットを組み合わせて一つのアウトフィットとして扱う**
- コンバイン後の見た目はどちらか片方のものとなる
- **部位**はコンバイン元両方の指定部位を全て占有する
- **分類**もコンバイン元両方を引き継ぎ、二つの分類を同時に持つ
- **電制**はどちらか高い方
- **隠匿値**は「隠：X(Y)」の形。X = 見た目に設定したアウトフィットの隠匿値、
  Y = コンバイナー本体の隠匿値。Y を目標値に〈知覚〉判定を行うとコンバイン元両方のアウトフィットがわかる
- その他のパラメータ: 両方にあればどちらか好きな方、片方にしかなければそのまま適用
- **コンバイナー本体のパラメータは完全に一般アウトフィットのもの**
- コンバイン条件は**ルール上は選択を制限するが、実装上は自由選択**（条件が細かく将来のコンバイナー
  追加で選択肢追加が必要になるため。2026-06-13 確定）
- アクターへのインポート時は**一つのアイテムとしてインポート**（元アイテムも展開可能にしつつ）。
  名前は「見た目のアイテム名（コンバイン）」形式 → フェーズ6-6（キャストシート）で実装
- 実装状況（2026-06-13）: combine{source1, source2, appearance} に再設計。元二つのドロップ指定・
  見た目ラジオ・**コンバインプレビュー**（名称/分類=両方/電制=高い方/隠=X(Y)/部位=両方占有）を実装。
  **両方にあるパラメータの取捨選択 UI（ラジオ/チェックボックス）とアクター一体インポートは未実装**
  （param 選択の対象範囲を確認後に拡張）

## スロット（extensible）（2026-06-12 確定）

- 装備される側のスロットに名前は基本的にない（一律「スロット」）
- 例外: IANUS の**意識スロット**は「表層意識」「深層意識」「無意識」の 3 種（通常スロットとは別に持つ）、
  タップは**ソフトウェアスロット**・**ハードウェアスロット**のみ名前があり呼び分ける
- **スロットを持つアイテム側はスロット数のみを設定する**（装備状態は持たない）
- オプションを装備した状態で取得されることはないため、装備連携はシート上で用意すれば十分
- 部位「アイテム名」のオプションは、スロットがないアイテムに装備される特殊例。対象アウトフィット
  （スロットなし）を準備している時に限り、対象1つにつき1個だけ準備可能。part エントリ種別
  `outfitName` として表現し、準備済みアウトフィットへ名前照合する（フェーズ10。上記「部位管理」参照）
- DataModel 表現: `slots[]: { kind: normal/surface/deep/unconscious/software/hardware, count }`。
  型ごとの既定プール: weapon/tron/vehicle/residence = normal のみ、ianus = normal + 意識 3 種、
  tap = software + hardware
