# アウトフィット（装備品）

フェーズ6 設計時（2026-06-12）にユーザーが言語化したルール解釈の記録。
outfitBase 共通フィールドの意味と UI 設計の根拠を定める。一次情報はユーザー。

## 共通パラメータ

### buy — 購入値（略号「購」）

- 購入判定の目標値。購入判定は基本的に「★信用」技能で行う
- 本来は常備化経験点（preserveExp）と合わせて一つのパラメータであり、
  「購：購入値／常備化経験点」の形で表記する
- 値は「なし」「数値」「解説参照」の 3 状態（UI はドロップダウン選択）
  - なし → 「-」表示
  - 数値 → その数値
  - 解説参照 → preserveExp の表示を消し、「購：解説参照」とだけ表記する
- DataModel 表現: `buy: { mode: none/value/reference, value: Number }`

### preserveExp — 常備化経験点

- 常備化（プレアクト時点までの購入）に必要な経験点
- 購入値と違って**必ず数値が入る**（NumberField）

### hide — 隠匿値（略号「隠」）

- アウトフィットを発見するための〈知覚〉判定の目標値
- 危険値と合わせて「隠：隠匿値／危険値」の形で表記する
- 値は「なし」「数値」「解説参照」の 3 状態（buy と同じ構造）
- **解説参照でも危険値は別個に設定・表示される**（例: 「隠：解説参照／-1」）
- DataModel 表現: `hide: { mode: none/value/reference, value: Number }`

### appearancePenalty — 危険値

- 携帯していると、全アウトフィットの危険値の合計分が登場判定目標値への修正になる
- **必ず数値が入る**（NumberField）

### hack — 電脳制御値（略号「電制」）

- アウトフィットへのハッキングを試みる〈電脳〉判定の目標値
- 「なし / 数値」の 2 状態のみ（解説参照はない。2026-06-12 確認）
- シート表記は略号「電制」を使う（2026-06-12 確認）
- UI は購入値と同様のドロップダウン選択（なし/数値）
- DataModel 表現: `hack: { mode: none/value, value: Number }`

### part — 装備部位

- 一つの部位には基本的に一つのアウトフィットしか装備できない
- 二つ装備可能な部位: 「片手持ち」「片腕」「片足」「指」の 4 つ
  - 「両手持ち」=「片手持ち」×2、「両腕」=「片腕」×2、「両足」=「片足」×2 を消費
- 「籠手」は手系の装備部位（「片手甲」「手の甲」「指」等）を全て埋める排他関係
  （「片手持ち」など“持つ”系は例外）
- 「武器2」のように後置数字が付く場合、その部位のスロットをその数だけ消費する
  （「武器2」は武器スロット 2 つ消費 → スロットが 2 つ以上ある場合のみ装備可）
- 種類が多すぎるため **部位名の UI は自由入力**（ドロップダウンにしない）
- 部位名とスロット数は別フィールドで設定する（2026-06-12 確認）。
  表記はスロット数 1 のとき部位名のみ、0 または 2 以上のとき「武器2」「部位0」のように数値を付す
- DataModel 表現: `part: { value: String, slots: Number(initial 1, min 0) }`

### timing — 使用タイミング

- カット進行上の使用タイミング（セットアップ、メジャーなど）が設定されていることがある
- 選択肢はスタイル技能の timing と共通（アクション/プロセスの二段選択を含む。2026-06-12 確認）

### exclusive — 専用

- 特定のスタイルやワークス専用であることを表す
- 自由記述。自動化はしない（2026-06-12 確認）

### 真偽値フラグ（意味は 2026-06-12 ユーザー確定）

| フラグ | 意味 |
|---|---|
| `isPrepared` | **準備済み**。そのアウトフィットが使用可能な状態にあるかどうか。いわゆる「装備」に近い概念だが、大きさや機能的に身に付けられないアウトフィットにも適用される点が異なる |
| `isCarrying` | **携帯中**。そのアウトフィットを身に着けているかどうか。「所持」しているだけでは携帯中とはいえず、当然準備中ともいえない。キャラクターシートに存在する時点で「所持」は確定しているので所持フラグは存在しない |
| `isCyber` | サイバーウェアかどうか。種別がサイバーウェア以外のアウトフィットでサイバーウェアであるものを識別するのに必要 |
| `isPre-play` | **プレアクト購入**。常備化経験点は支払っていないが、プレアクトで購入して所持しているアイテムであることを表す。true だと所持した際の経験点消費がなくなる（表示名は TNX 用語の「プレアクト購入」とする。2026-06-13 確定） |
| `isOption` | そのアウトフィットが**別のアウトフィットに装備するオプション**であることを表す。装備対象のアウトフィットのスロット数がなければ装備できない（2026-06-12 確認） |

- `isCarrying` はフェーズ6 設計時に必要と判明し追加。**デフォルトは true**（2026-06-13 確定）

## 消費アイテム（isConsumption / quantity）

2026-06-12 ユーザー確定。weapon の旧 isthrow（投射武器）を全種別に一般化して置き換えた。

- `isConsumption` が true のアイテムは個数（quantity）を持ち、アイテム名の右に「×数字」で表示する
  （この数値入力は number-input-spinner を**使わない**例外）
- 消費で現在個数（value）を減らし、0 になるとそのセッション中は使用不可。セッションが終われば復活する
- 常備化経験点は個数分（max 基準）必要で、**消費しても経験点は復活しない**
- DataModel 表現: `quantity: { value: 現在個数, max: 常備化個数 }`（initial 1/1）

## 武器（weapon）固有パラメータ（2026-06-12 確定）

- **attack — 攻撃力（略号「攻」）**: ダメージ種別 + 値で「攻：I+4」のように表記。
  ダメージ種別は S（Slashing=斬撃）/ P（Piercing=貫通）/ I（Impact=衝撃）/
  X（エクストラ=装甲無視）の 4 種から**単一選択**（ドロップダウン。2026-06-13 確定）。
  「攻撃値」というパラメータ名は存在しない（シートでは「攻撃力」1 行で種別 + 値を扱う）
- **guardValue — 受け値（略号「受」）**: パリィをして判定に失敗した際にダメージから引かれる値
  （パリィは白兵判定で、成功すればその時点でダメージ無効）
- **range — 射程（略号「射」）**: 至近/近/中/遠/超遠の 5 種のみ（「なし」「武器」はない）。
  最低と最大を設定でき、同値なら単一表記、異なる場合は「近～超遠」のように範囲表記
- **isLaser**: レーザー兵器。レーザー兵器からの攻撃を受けない防具があるための識別フラグ
- **isFullAuto + FAValue**: フルオート射撃可能な武器。FAn の n（FAValue）をダメージに加算できる。
  フルオート射撃を行うと弾倉が空になり、マイナーアクションで交換が必要
- **attackArea — 攻撃範囲**: 「-/範囲/範囲（選択）/シーン/シーン（選択）」の 5 択。
  設定時、判定アイテムで武器攻撃の用途を設定するときに範囲を上書きできる（「-」は上書きしない）
- **isBiological**: 生体武器・生体装備。武器・防具のどちらでもない生体装備があるため、
  isConsumption 同様 outfitBase へ一般化（全種別が持つ）
- 概要表記順: **購/隠/攻/受/射/ス/電制/部位**（ス = スロット）

## 防具（armor）・サイバーウェア（cyborg）（2026-06-12 確定）

- **defence — 防御値（略号「防」）**: S/P/I の 3 値を「**防(S／P／I)：5／4／6**」のように並記
  （(S／P／I) の部分を省略してはならない。2026-06-13 確定）
- **controlMod — 制御値修正（略号「制」）**: ヴィークル等で出てくる場合も同じ意味
- 防具の概要表記順: **購/隠/防/制/電制/部位**
- **cyborg（全身義体）**: 概要表記順は **購/隠/防/攻/受/電制/部位**。
  武器や防具として使えるというより**生身にこれらのデータが付く**意味。
  防御力は防具と加算されるが、攻撃力と受け値は攻撃・パリィに義体を直接使う宣言をしないと
  適用されない。他に武器を持っていても加算されない（その武器を使った攻撃・パリィとはみなされないため）

## スロット（extensible）（2026-06-12 確定）

- 装備される側のスロットに名前は基本的にない（一律「スロット」）
- 例外: IANUS の**意識スロット**は「表層意識」「深層意識」「無意識」の 3 種（通常スロットとは別に持つ）、
  タップは**ソフトウェアスロット**・**ハードウェアスロット**のみ名前があり呼び分ける
- **スロットを持つアイテム側はスロット数のみを設定する**（装備状態は持たない）
- オプションを装備した状態で取得されることはないため、装備連携はシート上で用意すれば十分
- 部位「アイテム名」のオプションは、スロットがないアイテム（ただし基本的にスロットがないアイテムのみ）
  にも装備される可能性がある → キャストシート実装時（6-6）に検討
- DataModel 表現: `slots[]: { kind: normal/surface/deep/unconscious/software/hardware, count }`。
  型ごとの既定プール: weapon/tron/vehicle/residence = normal のみ、ianus = normal + 意識 3 種、
  tap = software + hardware
