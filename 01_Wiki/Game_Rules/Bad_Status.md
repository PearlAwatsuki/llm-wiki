# バッドステータス（BS / 状態異常）

バッドステータスに関するルール解釈の正本。フェーズ8 後の設計議論で言語化（2026-06-20）。フェーズ9（ActiveEffect）の状態異常実装の設計インプット。

バッドステータス（BS）は **ActiveEffect として表現される状態異常**。ダメージチャートの結果やスタイル技能で付与される。「この効果は BS として扱う」スタイル技能もあり、それらも BS 解除効果で解除できる。

## 共通ルール

- BS は**カット進行が終了するか、シーンが変われば全て解除**される。
- ただし、**ダメージによって発生し「治療するまで回復しない」と明記された BS** は、ダメージが治療されるか**アクト終了まで**回復しない。
- **重複可能と明記されていない限り、同じ BS が同じキャラクターに複数発生しない**。

### ダメージ由来 BS と治療の関係（2026-07-09 ユーザー言語化）

- **ダメージで発生した BS は、（負傷を）治療しても解除されない**。その **BS 自身の解除条件**（回復タイミング）を満たすか、**BS を解除する効果のスタイル技能・アウトフィットを使用する**必要がある。＝治療（〈医療〉判定）が回復させるのは**負傷そのもの**であって、負傷が付与した BS ではない。
- **例外**: ダメージによって受けた BS は、**例外的に「ダメージを治療するまで回復しない」場合がある**。具体的には、**肉体ダメージチャート 12番・17番／精神ダメージチャート 15番／社会ダメージチャート 16番・18番**。これらは効果元であるダメージが治療されるまで回復できない（通常の回復タイミング＝カット進行終了・シーン変更では回復しない）。
  - ※コード上はこれらの inflicts に `duration: "治療まで"` が付与されており（damage-chart.mjs）、ユーザー指定リストと一致することを確認済み（2026-07-09）。回復の発火／治療連動の実行は時間管理＝**フェーズ15**。
- **BS の回復 ≠ ダメージの治療（2026-07-09 ユーザー言語化・不変条件）**: 「治療まで回復しない」以外の BS はダメージ治療前でも回復可能だが、**BS を回復してもダメージ（負傷）は治療されない**（BS の回復は BS しか対象にしない）。逆に、負傷を治療しても BS は残る（上記）。この 2 方向は独立。
  - 3 経路の切り分け（実装。負傷が付与した状態は全て `woundSource` で負傷に紐づく）:
    | 経路 | 除去対象 |
    |---|---|
    | **BS の回復**（BS 自身の解除・解除効果・15 の自動回復） | **その BS のみ**。woundSource を辿って負傷を消してはならない |
    | **〈医療〉治療** | 負傷＋紐づきの**非BS**（戦闘不能等）。BS は残す |
    | **制御判定の「無効」**（例: 精神8 恐怖＝恐慌の「感情の制御判定で無効」） | 負傷＋紐づき**全て（BS 含む）**＝ダメージ自体が無効（[Damage_Rules.md](Damage_Rules.md)） |
  - ※精神8 恐怖で「ダメージも BS も無効」になるのは制御判定の「無効」がダメージ自体を resist するためで、通常の BS 回復では BS しか消えない（負傷は残る）。

## BS 一覧

### 恐慌
- 効果: リアクション不可。
- 回復: そのキャラクターのメインプロセスの**直前**。

### 邪毒（強度 n）
- 表記: `[BS：邪毒n]`。
- 効果: クリンナッププロセスのたびに、山札から1枚引いて「**出た数字 + n**」点の肉体ダメージ。
- 回復: アウトフィット/スタイル技能で回復、または自分のメインプロセスでマイナー・メジャー両アクションを放棄。

### 重圧（能力値）
- 表記: `[BS：重圧(生命)]` のように対象能力値を記す。
- 効果: 指定された能力値を使う判定が行えない（**制御判定は可**）。能力値指定がない場合は、受ける際に山札1枚を引き、そのスートに対応する能力値に重圧。
- 回復: マイナーアクションの使用で全回復。**「全回復」＝そのとき受けている重圧が全て回復する**（2026-08-29 ユーザー裁定。1つずつではない）。
- バッジ表示（シート）: 対象能力値は**スート記号（括弧なし）**で示す（例 `重圧♥`＝生命。2026-07-19 ユーザー確定＝能力値名だと能力値の値と紛らわしいため。♠理性/♣感情/♥生命/♦外界）。

### 衰弱
- 効果: 受ける際に RL が山札1枚を引き、対応スートの制御値をカードの数字分減少。
- 表記 `[BS：衰弱(-数字)]`: 全制御値を「-数字」する。
- 重複: `[BS：衰弱]` 同士、`[BS：衰弱(-数字)]` 同士、両者間、いずれも**重複する**。
- 回復: シーン終了時に自動回復。
- バッジ表示（シート）: スート引き版は `衰弱♥-9` のように**スート記号＋数字（括弧なし）**（2026-07-19 ユーザー確定。旧「（生命の制御値 -9）」はバッジ幅に収まらず、能力値名は能力値の値と紛らわしい）。全制御値版は `衰弱-9`。

### 捕縛
- 効果: 与えたキャラが対象の武器1つを選び、対象はその武器で攻撃できない。**武器ごとに複数付与可能**。
- 回復: 自分のメインプロセスでメジャーアクションを放棄で全回復。**「全回復」＝そのとき受けている捕縛が全て回復する**（2026-08-29 ユーザー裁定）。

### 酩酊（小 / 大）
- 効果: 小はあらゆる判定の達成値と全制御値が **-2**、大は **-5**。
- `[BS：酩酊(小)]` と `[BS：酩酊(大)]` は別 BS で、**効果は重複する**。
- 回復: 小はクリンナッププロセスで回復。大はクリンナッププロセスで**小に変換**（さらにもう1度クリンナップで完全回復）。

### 萎縮
- 効果: 受ける際に萎縮対象キャラを指定（**対象ごとに別 BS**）。萎縮対象を含む攻撃判定の達成値 -5。
- 回復: メインプロセス終了時に自動回復。**その BS を受けている本人のメインプロセス**の終了時（2026-08-29 ユーザー裁定。Time_Management の「メインプロセス中」効果＝誰のかを問わない、とは主語が異なる）。

### 憎悪
- 効果: 受ける際に憎悪対象キャラを指定（**対象ごとに別 BS**）。攻撃時に憎悪対象を対象に含まない場合、その判定の達成値 -5。複数の憎悪を受けても**このペナルティは重複しない**。
- 回復: メインプロセス終了時に自動回復。**その BS を受けている本人のメインプロセス**の終了時（2026-08-29 ユーザー裁定）。

### 狼狽
- 効果: ムーブアクション不可。メジャーアクションの達成値 **-10**。
- 回復: **マイナーアクションの使用**（重圧と同型）。
- ※本項は **Code の記録漏れの補填**（2026-08-29）。ユーザーから伝えられていた内容が `conditions.mjs` のコード内コメント（「ムーブ不可＋メジャー達成値-10(回復=マイナー)」）にだけ残り、正本に記録されていなかった。フェーズ15-4 で「記載が無い」として回復ボタンを出さない判断をしかけたが、**記載が無いのではなく記録していなかった**のが正しい。

### 電子妨害（強度 n）
- 表記: `[BS：電子妨害n]`（n は正整数）。**n が違っても別 BS 扱いせず重複しない**。
- 効果: 対象が持つカテゴリ「武器 / アーマーギア / サイバーウェア / トロン / サイコアプリ」のアウトフィットのうち、電制が **n 以下**のものの個数を数える。
  - ウェットでない場合: 全判定にその個数分のマイナス修正（**上限 10**）。
  - ウェットで該当が1個以上: 全判定に -1。
  - 条件に該当する全身義体・ヴィークルを準備、または該当タップでゴースト登場中: 全判定に **-10**。
- 回復: クリンナッププロセスで回復。

## 行動を支払って回復する BS（2026-08-29 ユーザー裁定・フェーズ15 設計）

重圧・捕縛・邪毒は、時間の境界ではなく**アクションを支払うこと**で回復する。ルール上の位置づけと、システムでの扱いを分けて記す。

- **放棄は「行動の放棄というアクションを行ったもの」とみなす**（ユーザー verbatim 相当）。メジャーアクションの放棄＝**アクションランクの消費**。したがって通常のメジャー行使と同じ記帳に乗り、プロセス終了時に AR−1＋CS カレント 0 が適用される（→ [Combat_Flow](Combat_Flow.md) の一般則）。マイナーの使用・放棄は AR に影響しない。
- **放棄はその BS を回復するための支払いであって、メインプロセス単位の共有された事実ではない。** 捕縛のために放棄したメジャーは邪毒には効かない（「あくまでも『特定の BS を回復するために放棄』」）。
- **邪毒の宣言は一度**——マイナーを放棄する時点でメジャーの放棄まで宣言するのが正しい挙動。二段階に分けない。
- **回復は「全て」**——重圧・捕縛はボタン1つで、その時点で受けている分が全部回復する。

| BS | 支払い | 回復する範囲 |
|---|---|---|
| 重圧 | マイナーアクションの使用 | 受けている重圧を全て |
| 狼狽 | マイナーアクションの使用 | 狼狽 |
| 捕縛 | メジャーアクションの放棄 | 受けている捕縛を全て |
| 邪毒 | マイナー・メジャー両アクションの放棄（一度の宣言） | 邪毒 |

**UI の置き場**: 主経路は**キャラクターシートの戦闘タブ**（状態を編集する操作ではなく、アクションを支払う操作であるため。CS・AR・タイミング別の起動チップと同じ面に属する）。状態バッジのコンテキストメニューにも条件成立時に出してよい。**1 BS 種別 = 1 ボタン**で、押した時点で支払いと回復の両方が済む。

**帰結**: いずれも「自分のメインプロセスで」行うものなので、カット進行外のシーンではこれらを手動回復できない（メインプロセスも AR という原資も存在しないため）。その場合はシーンが変わるまで残る——BS の全解除（カット進行終了・シーン変更）が最後には落とす。

## 設計メモ（フェーズ9 ActiveEffect）

BS の性質を分類すると、AE の器の設計に効く：

- **派生値修正型**（重圧=能力値判定不可、衰弱=制御値減、酩酊=達成値/制御値減、萎縮/憎悪=達成値減、電子妨害=判定修正）→ 派生値計算に反映。
- **行動制限型**（恐慌=リアクション不可、捕縛=特定武器の攻撃不可）。
- **継続ダメージ型**（邪毒=クリンナップごとに肉体ダメージ）。
- **重複・強度**: 衰弱／酩酊(小・大)／捕縛(武器ごと)／萎縮・憎悪(対象ごと)は重複する。邪毒n／電子妨害n は強度を持つ（電子妨害は n 違いでも重複しない）。
- **回復タイミングが多様**: メインプロセス直前/終了時・クリンナップ・シーン終了・マイナー/メジャー放棄・治療まで・アクト終了 → [Time_Management.md](Time_Management.md) の時間単位と連携。
