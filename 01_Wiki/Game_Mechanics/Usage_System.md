# usage (用途) システム

## リアクション用途の統合と技能の行動資格（2026-11-20）

本節は今回のユーザー確定仕様を記録する。旧「用途タイプがリアクション資格を表す」「対決手段と用途タイプが1対1」という記述は歴史的判断として残し、現行動作には本節を適用する。用途システム、および技能定義・用途固有設定・実効値の分離方針は維持する。

- 用途の保存タイプは `reaction` 一種類。既存の用途エントリは合併しない。攻撃3種類や他の用途タイプは変更しない。
- 一般・スタイル技能共通の `system.actionQualifications` に6資格を保存する。`dodge` / `parry` / `mentalReaction` / `socialReaction` / `moveBlockReaction` / `escapeBlockReaction` は用途タイプではなく行動資格の識別子。
- 資格が空で、リアクション用途を持つアクション技能は汎用リアクションを表す。用途なし・非アクション技能の空資格は汎用ではない。名前による既定資格補完はしない。
- ベースは必ずアクション技能。アクションのスタイル技能をベースにする構成と、一般アクション技能に非アクションのスタイル技能を加える構成を区別する。追加資格は実参加した判定だけに適用し、ベース技能へ保存しない。
- `resolveReactionQualification` が実際の構成を検証する。`findReactionCombination` は既存の `resolveUsageSkills` による必須・選択・代用技能の解決を使い、同じ資格関数で候補を検算する。所持技能に合法な組み合わせがあればベース単体に資格がなくても候補に残す。ダイアログで既存の組み合わせ追加機能を使い、手札・山札・切り札の消費前に不足理由を通知する。
- 手段はカード上で先に選択する。用途・技能選択後の手段再選択はしない。パリー受け値と対決結果は引き続き `reaction.mode` から処理する。成立したパリーは対決に敗れても受け値を適用する。本人・代理・複数リアクションと受動有利は既存の解決処理を維持する。
- 対決手段は独立レジストリ `REACTION_METHOD_LABELS` の7種類を維持する。技能名・技能名※・不可マスク・下地の行・不可無視・合算時の重複吸収は維持する。その他は資格制限のない別入口であり、汎用資格と同義ではない。オープン入口は全手段を対象にする。
- 操縦時の対決を操縦技能※に置換する既存処理を維持する。移動妨害のヴィークル条件は選択手段から判定する。保存済み `requiresVehicle` と参照は用途固有条件として残す。
- リアクション起動はリアクション用途を対象にする（その他の自由選択を除く）。一件自動・複数選択・非表示除外・直接ID指定を維持する。統合用途にも既存のパリー武器・受け値編集欄を出す。
- 設定タブには有効資格の要約と編集アイコンを置き、一般・スタイル共通の選択ダイアログで正式名称6項目を編集する。特性フラグを移動・改名しない。空選択の確定とキャンセルを区別する。

### AEの判定分類（2026-11-21 ユーザー訂正）

用途タイプの統合は、リアクションの判定分類やAEの適用条件の統合を意味しない。UIの `mode` を実際の分類と同一視しない。`reactionCheckTypes` は能動側の `usageType`（旧カードは攻撃 `category` も参照）と選択済み手段から解決する。

| 能動側の行動／選択済み手段 | 維持するAEキー |
| --- | --- |
| 精神攻撃へのリアクション | `check.mentalReaction` |
| 社会攻撃へのリアクション | `check.socialReaction` |
| 移動妨害へのリアクション | `check.moveBlockReaction` |
| 離脱妨害へのリアクション | `check.escapeBlockReaction` |
| ドッジ／パリー | `check.dodge` / `check.parry` |
| リアクション判定全般（その他・オープンを含む） | `check.reaction` |

能動側情報をリアクション文脈へ保持し、旧カードの再判定は能動側カードから補う。通常の修正評価と「次の1回の判定まで」の失効判定は同じ分類を使う。既存AEのキーを書き換えない。複数の対決手段が表示されることを理由にAEを無効化する案、および対決欄が一種類のときだけ適用する案は採用しない（開発中の誤った前提として撤回）。

### データ移行

`UsageTemplate.migrateData` の先頭で `migrateReactionUsages` を適用する。実際のmixin順序は Base → Usage → SkillBase であり、用途の旧タイプを失う前に資格を抽出する。資格未設定の技能で、旧個別タイプを重複なく取り込み、旧 `reaction` が一件でもあれば資格を空にする。資格が既に存在すれば空配列を含めて尊重する。

個々の用途のタイプのみを `reaction` に変更し、ID・名前・AE参照・消費・武器参照・修正・組み合わせ・非表示・対決の旧識別子を保つ。繰り返し移行は冪等。旧正準名移行も新形式の資格を上書きしない。辞典の軽量索引は資格と用途を読み込み、文書を更新せず同じ互換規則で解釈する。

これは用途設定の来歴確認とは別の移行。`settingsVersion: 0` の値は引き続き保全し、来歴を確認した用途だけ個別移行する。既存の `settingsBackup` 原本も変更しない。バックアップからの個別復元時は設定値を戻し、旧リアクションタイプだけ現形式へ変換する。技能本体の現在の資格は復元操作で上書きしない。

### 検証・実機確認

自動テストはケースA/B、追加技能の不足・削除・資格変更、単独非アクションの拒否、汎用とその他、技能名・※・不可、オープン、移動・離脱、操縦置換、必須・選択・代用・共通スート、用途の自動／複数／直接選択、キャンセル、資格編集、実行文脈、mixin順序、移行の保全・冪等性を検証する。既存の防御・パリー・技能チェーン・用途設定移行テストも継続する。

Foundry実機では一般／スタイル技能の表示と保存、ワールド・辞典・アクター所持技能の再読込、複数クライアントのカード操作、ヴィークル準備変更、本人／代理パリーのダメージ軽減を確認する。DOM・モック連携テストとFoundry実機検証を区別する。

## 現行方針：技能定義・用途固有設定・実効値の分離（2026-11-15）

**ユーザー確定・本体 `6c159b6`**。技能などのアイテムは能力の定義、用途は定義を具体的な行動・効果へ構成した独立したインスタンス。用途固有の入力を保存し、技能由来の修正・条件・許可・ダメージ種別候補は参加技能から導出する。旧来の「親技能の値を用途の同じ欄へ複写・同期する」扱いは、この範囲では置き換えられた。以下の旧設計の記録は経緯として読み、現行の保存責務は本節を優先する。

| 層 | 正本・責務 |
| --- | --- |
| 技能定義 | 技能アイテムの `system`。別の用途の設定は読み取らない |
| 用途固有設定 | `settingsVersion: 1` の用途自身の各フィールド。技能由来値の保存先にしない |
| 実効値 | `resolveUsageSettings(usage, parent, getItem)` の `effective`。`local`・`contributions`・`diagnostics` を分けて返す。保存用途を変更しない純粋関数 |

親・ベース・組み合わせのアイテムIDの和集合を参加技能として解決し、重複参加を除く。エディタと実行・再判定が同じ関数を使用する。エディタの入力欄は用途固有設定、技能由来の修正と実効設定は読取専用表示。再判定には `usageSettingsInput` を引き継ぎ、実効行を再び用途固有行として加算しない。

- **修正行の来歴**: 実効行の `origin.kind` は `usage` / `skill`。技能行はアイテムID・定義元フィールド、用途行は元の配列・位置を識別する。保存済みの `source` は帰属表示用であり、自動生成の証拠ではない。同じ供給元・同じ式の手動行も削除しない。
- **合成**: 判定・ダメージの式は用途自身・用途の追加行・技能由来行を保持して既存の式評価と重複制御へ渡す。対象条件と「重複可」は各式に付随したまま維持する。ヴィークル準備要求は一つでもあれば必要。許可は用途固有分と適用可能な技能分の和集合。割り込みのAR消費は、許可する供給元の一つでも消費ありなら消費する（現行規則を維持するとユーザー確認）。ダメージ種別は候補の和集合とし、用途の明示選択を優先する。
- **保存境界**: 表示時の技能同期、必須コンボ補完、パリー武器の保存は行わない。初期補完は新規作成時、構成の補完は明示的な編集時に行う。技能の作成・更新・削除フックは開いている用途エディタを再描画するだけで、用途を書き換えない。
- **変更しない範囲**: 対象・射程・タイミング・対決・消費・AE参照・用途タイプの決定、式の数値評価・重複採否のルール。従来の作成時／ボタンによる発動パラメータの自動入力を、技能変更への全面的なライブ追従へ拡張しない。

### 既存用途の診断・個別移行・復元

旧形式（バージョン未設定または0）は保存値を保全して「要確認」と表示し、技能変更による自動同期を停止する。新規用途と確認して移行した用途から新方式を適用する。`skillSettingsSync`、式の一致、`source` の一致から元の来歴を推測しない。

1. `diagnoseUsageSettings` は診断のみで保存しない。
2. 「設定の来歴を確認して移行」では、各値・各修正行について「用途固有として保持」(`keep`) または「技能から導出」(`skill`) を明示的に選ぶ。保持分と現在の技能分は両方適用される。未選択やキャンセル・閉じる操作では保存しない。
3. `migrateUsageSettings` は確認済みの決定を適用し、移行前の用途全体を `settingsBackup` に保存する。確認中の変更競合は中止する。
4. 「移行前の用途全体を復元」は、確認後にバックアップへ戻す。移行後の編集も戻る。復元のキャンセル・閉じる操作では何も変更しない。

過去の上書きで既に失われた値は、このバックアップでは復元できない。必要なら過去のワールドバックアップと照合する。一括自動移行は行わない。

詳細な実装対応は [設計文書](../../../docs/usage-settings-resolution.md)、判断の経緯は [設計レビュー](../../02_System/Design_Review_Entries.md)、HTML修正と検証は [監査記録](../../02_System/Audit_and_Review.md) を参照。

`UsageTemplate` (`scripts/data/item/common/usage.mjs`):

```javascript
actions: ArrayField(SchemaField({
    _id:         StringField,           // ランダム ID (randomID())。インデックス参照を廃止
    type:        StringField,           // 種別（作成時固定。下記参照）
    name:        StringField,
    description: StringField,
    settingsVersion: NumberField,      // 1=用途固有入力を分離。0/未設定=旧形式・要確認
    settingsBackup: ObjectField,       // 明示的移行直前の用途全体（未移行時null）

    timing: SchemaField({
        value:       StringField,       // "blank" | "action" | "process" | "reaction" | "other" | ...
        actionName:  StringField,       // timing.value === "action" の場合のサブ選択肢
        processName: StringField,       // timing.value === "process" の場合のサブ選択肢
        timingOther: StringField,       // timing.value === "other" の場合の自由入力
    }),
    hideInCombatTab: BooleanField,      // 戦闘タブに表示しない（2026-07-20）: 戦闘タブ「タイミングごとの使用技能・アウトフィット」の再表示から除外する。表示のみの設定で、起動・判定・タイミングの意味には一切影響しない

    // 対象・射程・目標値（スタイル技能と同形の flat フィールド。発動タブで設定）
    target:        StringField,         // "blank" | "self" | "single" | "team" | ...
    targetOther:   StringField,         // target === "other" の自由入力
    isFixedTarget: BooleanField,        // 変更不可（※）: AE による対象変更を抑止（実機能はフェーズ13）
    cannotTargetSelf: BooleanField,     // 自身に適用できない（2026-07-18）: 自動セルフ解決を抑止（→対象選択ダイアログ・候補から自分除外）。自分をターゲット中の起動は「ターゲットが間違っています」で中止
    range:        StringField,          // "blank" | "close" | "short" | ... | "weapon"
    rangeMax:     StringField,          // 最長射程（2026-07-16）: "none"=単点。range が物理射程のとき「近～遠」等の幅の上限
    rangeOther:   StringField,
    isFixedRange: BooleanField,         // 変更不可（※）
    targetValue:       StringField,     // "blank" | "number" | "control" | "total" | ...
    targetValueNumber: NumberField,
    targetValueOther:  StringField,

    isUnopposable: BooleanField,        // 対決不可: 対象がこの判定に対決できない（実機能はフェーズ13、現状は保持のみ）

    effects: ArrayField(SchemaField({
        itemId:   StringField,          // 効果が乗るアイテム（空=親／組み合わせ技能／使用武器・2026-07-10）
        effectId: StringField,          // この用途使用時に付与する ActiveEffect の id
    })),

    // 判定/攻撃の修正値（2026-07-10）
    checkBonuses:    ArrayField(SchemaField({ formula, source, stackable })),  // 保存値は用途固有の追加行
    checkBonusSelf:  StringField,       // 用途自身の判定修正値（専用欄・@item.*=保持元アウトフィット（技能は@skill.<key>.*））
    damageBonuses:   ArrayField(SchemaField({ formula, source, stackable, targetCondition })),  // 用途固有の行・攻撃用
    damageBonusSelf: StringField,       // 用途自身のダメージ修正値（専用欄・attack のみ）

    baseSkillRef: SchemaField({
        itemId: StringField,            // ベース技能の Item ID。generalSkill 新規作成時に親 ID で自動設定
    }),

    skillRefs: ArrayField(SchemaField({
        itemId: StringField,            // 組み合わせ技能（ベース技能は含まない）の Item ID
    })),

    // attack タイプのみ
    weaponRef: SchemaField({ itemId: StringField }),
    damageType: StringField,            // "S" | "P" | "I"

    // check(攻撃)のみ
    damageCategory: StringField,        // 攻撃系統 "physical" | "mental" | "social"

    // modification タイプのみ
    modifiableParams: ArrayField(StringField),
}))
```

### タイプ（type）値域

> **一本化（2026-07-13）**: タイプは `check`/`declaration` のみ（→ [Check_Rules](../Game_Rules/Check_Rules.md)「用途タイプ」）。改造は廃止（check へ移行・機能未実装）・NPC取得はフラグ化（設定 UI は効果タブの〈NPC取得〉fieldset へ移動。設定できるのはトループ取得技能とアウトフィット＝旧作成ゲートの移管。OFF で設定リセット）。

| type | 説明 |
|---|---|
| `check` | 判定（攻撃・回復・NPC取得等はフラグ/設定として載る） |
| `declaration` | 宣言（神業を含む。修正系・スート変更・回復・NPC取得を設定可） |

- `controlCheck` は独立した判定種別であり、usage タイプには含まない（timing で区別）
- 神業（miracle）は**神業専用の用途タイプ5種**（宣言・即死・防御・社会戦・破壊＝`miracleDeclaration`/`miracleKill`/`miracleDefence`/`miracleSocial`/`miracleDestroy`・kind=miracle・実行形式はすべて宣言）で表す（フェーズ17-2・2026-09-03 ユーザー提案。17-1 時点の「新設しない」は撤回）。用途作成ダイアログは親が神業ならこの5種だけ、神業以外には出さない（`usageTypeLabelsFor`/`defaultUsageTypeFor`）。**例外は独自効果型の神業書き換え技能**（フェーズ17-7・`{miracleOwnEffect: true}`）——その用途は技能自身の使い方ではなく、書き換えた神業の効果そのものになるため、神業と同じ5種を出す。神業タイプの用途シートは**タイミング・目標値・対決・「適用される効果」を出さない**（適用される効果の削除＝2026-09-07 ユーザー指示。神業の効果は効果文と神業専用の設定〈宣言の効果・即死・防御・社会戦・破壊〉が正であり、ActiveEffect では持たない）。神業であることは用途の親アイテムの型から導く印（起動文脈 `miracle`→カードのフラグ・付与コピーの `fromMiracle`）で運ぶ。**用途が0件でも機能**（残回数ゲート→使用回数の消費→神業カード）。**消費先が空の神業用途は自身の使用回数×1を実行時に既定消費する**（「消費は消費先の設定からのみ」の例外＝使用＝回数消費が神業の定義に含まれるため。保存はしない）
- タイプは作成時固定（UI 上で切り替え不可）

### タイミング / 対象の "-"（blank）の意味

`timing.value = "blank"` / `target = "blank"` は「指定なし」= **どのタイミング・対象とも組み合わせ可能**を意味する（自由タイミング・自由対象）。空欄でも判定は正常に起動できる。

> **対象欄の実効化（2026-07-18 ユーザー確定・2026-07-19 実装＝本体 `fc95cc8`）**: 従来読まれていなかった「対象」欄が、**対象解決とカード形式の決定表**（対象×対決・`usage-target-plan.mjs`）で挙動を決めるようになった——「-」「解説参照」「その他」＝対象要求なし（対決ありならオープンリアクション）・「自身」＝常時自動セルフ・「単体」＝非対決のみ自動セルフ/対決ありは選択ダイアログ・チーム/範囲等＝対決ありのみダイアログ。旧「対象を参照しないレティクル解決」（回復/修理の「自分を対象に続行」確認・適用効果のノーターゲット確認・攻撃対象ダイアログの「（対象なし）」）は全廃。値が実態とずれている既存用途は設定の見直しが必要。正本は [Combat_Flow.md](../Game_Rules/Combat_Flow.md)「対象解決とカード形式の一般化」。

- **タブ（3構成、2026-06-20 改編）**: 基本 / 発動 / 効果

## スタイル技能の「技能」欄(comboSkill)の意味（2026-06-28 ユーザー言語化／解決は下記「組み合わせ解決」で実装済み）

スタイル技能の「技能」欄(`comboSkill`)は、その技能が組み合わせる相手（指定技能）を表す。値の種類と意味：

- **なし**: 単体で使用できる（が、他技能との組み合わせも可能）。
- **単独**: 他技能と組み合わせできない。ただし効果文で「他技能と組み合わせできない」と書く技能（＝`noCombo`）と異なり、「［技能：単独］とも組み合わせ可能」とされる技能が時折あるため、**単独からの組み合わせ不可の自動化は非推奨**。
- **宣言**: 宣言のみで使用、判定を行わない＝組み合わせも無い。
- **ドッジ**: ドッジ判定と組み合わせ可能。基本は〈回避〉だが「この判定でドッジを行える」技能もあるため、ドッジでありさえすれば技能は問わない。
- **パリー**: 組み合わせ先がパリーである以外はドッジと同じ。
- **技能名**: 特定の技能を指定（identificationKey で格納・辞典カスケードで選択）。
- **任意**: 任意の一般技能と組み合わせる（組み合わせの中に一般技能を1つ以上含む必要がある）。

### カテゴリ全体指定（whole-category）

「技能」欄は単一技能名でなく**カテゴリ全体**を指定することがある。単一技能名でないので**ベース自動固定はしない**が、**ベース／組み合わせ技能選択の絞り込み対象**になる。

- **固有名詞技能のカテゴリ全体**（〈社会〉〈芸術〉等）: カスケードの各小分類リスト（社会/操縦/製作/芸術/コネ）の**先頭**に「カテゴリ全体」エントリを置く（ユーザー入力で表現可能）。
- **スタイル技能の例外的カテゴリ全体**（コードにハードコード）: 〈元力〉＝識別キープレフィックス `element_`（バサラ）、〈血脈〉＝`bloodline_`（アヤカシ）。スタイル選択（P2b）後、**そのスタイルの技能リストに該当プレフィックスの技能があれば、そのスタイルのリスト先頭**に置く（リスト全体の先頭ではない）。

### 組み合わせ解決（2026-06-29 実装済み）

解決は**判定起動時でなく用途設定時**に行い、結果（baseSkillRef/skillRefs）を保存する。判定起動は解決済みの用途を使う（ルール解釈は [Audit_and_Review.md](../../02_System/Audit_and_Review.md)）。純関数は `scripts/module/skill-chain-resolution.mjs`、用途エディタ配線は `scripts/module/tnx-usage-sheet.mjs`。

- **技能チェーン**: 「技能」が単一技能名 X を指す間 X を辿る（例 S(技能:守護天使)→守護天使(技能:心理)→心理）。「&」結合（両方必須）も単一名と同様に自動固定対象。「、」結合（いずれか1つ）は候補制限で扱う。
- **ベース**: チェーン（起点＋足した組み合わせ技能の連鎖）全体に**アクション技能があればそれがベース**（アクション技能の「技能」(組み合わせ相手)も辿る）。無ければ末端がベース。&全員非アクションは手動。**アクション技能はベース欄以外に絶対入らない**（コンボから一律除外）／**アクション同士は組み合わせ不可**（参加が2つ以上になる追加はブロック）。
- **ベース自動固定はハードロックでなく候補制限**: 単一技能名（カテゴリ全体は対象外）は「指定技能＋その代用」候補から選択（本体優先で既定・候補が増えれば選べる）。
- **代用**: 各段で本体優先・無ければ代用で解決（代替先プロパティは引かない＝自前のスート・報酬点フラグ）。代用がアクションの代替ならベース候補。
- **スート**: 連鎖全体の積（共通スート無し＝判定不可）。候補絞り込みは共通スート。
- **個数制限**: 組み合わせ技能数 ≤ ベース技能のレベル（ベース込みで level+1）。追加時に連れ込み分＋アクション連れ込みでのベース入れ替わりを反映して事前ブロック。ベース変更での超過はトリムダイアログで調整（必須は外せない・取り消しで元のベースへ）。
- **無視する指定技能（`ignoreComboSkills`・2026-07-10 ユーザー確定）**: **用途側の設定**として辞典識別キーのリスト（`ArrayField(StringField)`）を持つ。ここに設定した技能（例〈射撃〉）を指定「技能」とするスタイル技能は、**その指定技能の自動追加をスキップして単体で組み合わせに入る**（＝連鎖の必須を引き込まない・指定技能がアクションでも「アクション同士」で弾かれない）。`resolveUsageSkills(root, skillItems, seedComboIds, ignoreComboKeys)` の第4引数（識別キー集合）で seed 連鎖の必須から除外（seed 自身は常に参加・**起点＝用途の親自身の連鎖には適用しない**＝ベース決定の根幹）。
  - **表現するルール**: 〈技能AⅡ〉系の効果——「技能：〈心理〉で射撃攻撃を行う〈技能A〉」の攻撃に、本来は組めない**技能：〈射撃〉のスタイル技能**を、**〈射撃〉を連れてこずに**組み込めるようにする。**組み込んだ技能の「組み合わせた攻撃への」効果（判定＋/ダメージ＋等）は乗るが、〈射撃〉自体は判定に入らないため〈射撃〉へのボーナスは乗らない。** ※技能一致でのブロックは元々存在せず、実在するブロックは「指定技能がアクション技能同士」のみ（既存）。
  - UI: 参加技能 fieldset に「無視する指定技能」リスト（辞典技能の即時追加セレクト＋行削除。保存＝識別キー・表示＝逆引き名）。**一度設定すれば、以後この用途への技能追加は何も聞かれず単体参加になる。** 削除時は指定技能（アクション）が引き込まれてアクション重複になる場合は拒否（先に該当の組み合わせ技能を外す）。auto-fill（`deriveUsageAutoFill`）も同設定を反映し必須補完で再追加しない。
  - **却下された設計（再発防止の記録）**: ①参加技能の行ごとの「指定技能を無視」トグル——**追加自体が「アクション同士」で弾かれるため、必要な場面でトグルに到達できない**（ユーザー指摘で発覚）。②追加時の確認ダイアログ——組み合わせのたびに毎回聞くのは誤り。**正: 用途側の永続設定**。
- comboSkill / confrontation の技能名表示は識別キーから**都度逆引き**（`tnx-skill-utils.mjs`・保持名キャッシュなし）。
