# コンディション（BS・戦闘不能）の ActiveEffect 表現（フェーズ9-4 設計・確定）

ダメージや技能で付与される**状態（condition）**を ActiveEffect として表現するモデル。バッドステータス（[Bad_Status.md](../Game_Rules/Bad_Status.md)）と戦闘不能ダメージ状態（[Damage_Rules.md](../Game_Rules/Damage_Rules.md) §戦闘不能ダメージ）を同一モデルで扱う。AE 適用の土台は [Active_Effects.md](Active_Effects.md)（v2）。

> **ステータス**: 設計確定（2026-06-22、ユーザー承認）。付与 UI は Foundry 標準のステータスエフェクト（`CONFIG.statusEffects` / トークン HUD）。

---

## 0. 大原則（condition は自己完結する実体）

D&D と違い TNX の BS は**効果が一意固定でなく、効果値がインスタンスごとに可変**（邪毒n・衰弱-n・電子妨害n・重圧の対象能力値・萎縮/憎悪の対象…）。よって「定義が効果を固定所有するレジストリ」では不足。一方、効果値を**汎用の変更（changes）タブ**で設定すると、アイテムバフと区別がつかず condition の意味が失われる。

このため condition は次の二層で表す。**設定はすべて condition 自身に閉じる**。

| 層 | 中身 | 置き場所 |
|---|---|---|
| **同一性** | status id / `conditionKind` / 回復トリガ / 除去可否 / 「BS扱い」 | condition 定義（貼付で確定） |
| **効果値（可変）** | -n / 強度 n / 対象 ability・UUID 等 | **condition 専用フラグ**（詳細タブで設定） |

- **condition は汎用 changes タブを使わない。** 効果値は**詳細タブの condition 専用フィールド**（重複可と同じ場所）または貼付時ダイアログで設定し、`flags.tokyo-nova-axleration` に保持する。
- **効果はコードが `conditionKind` ＋効果値フラグを読んで適用**する（changes 経由でない）。これにより condition（status＋値フィールド）が**設定の唯一の出所**となり、手打ち changes で replicate できず、アイテムバフ（v2・changes 手打ち）と完全に住み分く。
- **アイテムバフ（v2）と condition は別系統**:
  - アイテムバフ … 変更タブで `key+mode+value` を手打ち（自由・Active_Effects v2）。
  - condition … status で貼り、詳細タブの専用欄で効果値を設定、適用はコード（kind 駆動）。
- 重複は既存の重複可フラグ（`stackable`）。**重複明記の BS のみ true**。非重複は最大採用（強度違いは最大 n）。
- 効果文はルール本文を焼き込まず**ユーザー入力**（AE の description を流用、§4.1）。

## 1. condition のフラグ・スキーマ（`flags.tokyo-nova-axleration`）

既存の `effectId` / `stackable` に加える:

- `conditionKind`（string）… condition の種別。コードの適用分岐・回復・表示・除去判定の鍵。
- `magnitude`（number）… 可変の効果量（酩酊 2/5・衰弱 n・邪毒 n・電子妨害 n 等）。kind ごとに意味づけ。
- `targetAbility`（"reason"|"passion"|"life"|"mundane"）… 重圧の対象能力値。
- `targetUuid`（string）… 萎縮/憎悪の対象キャラ。
- `targetMode`（"include"|"exclude"）… 対象を含む時/含まない時に -5（萎縮=include / 憎悪=exclude）。
- `durationUnit`（enum）… 回復トリガ（mainProcessStart / mainProcessEnd / cleanup / sceneEnd / cutEnd / treated / actEnd 等）。9-4 はフラグ保持のみ。発火は 13/14/15。

status id（`CONFIG.statusEffects`）が condition の一意性を担い、`conditionKind` がコード分岐を担う（同義になる想定でよいが、id は Foundry 連携・kind は適用ロジックの鍵として分ける）。

## 2. 詳細タブ UI（condition 専用フィールド）

`renderActiveEffectConfig` フック（重複可チェックボックスと同じ）で、AE が condition（`conditionKind` を持つ）のとき詳細タブに kind 別フィールドを出す:

- 数値修正型（酩酊・衰弱）: 「効果量」欄（`magnitude`）
- 強度型（邪毒・電子妨害）: 「強度 n」欄（`magnitude`）
- 重圧: 能力値ドロップダウン（`targetAbility`）
- 萎縮・憎悪: 対象選択（`targetUuid` ＋ `targetMode` は kind で固定）
- 共通: 回復トリガ（`durationUnit`）／重複可（`stackable`）

## 3. 効果分類（4型）と適用ロジック

適用はアイテムバフと同じ**2注入点**（[Active_Effects.md](Active_Effects.md) §1）に condition 用コードを追加する。

### ① 数値修正型 — コードが派生値／判定に加算
酩酊・衰弱。`conditionKind`＋`magnitude` を読み、対象へ -magnitude。
- 酩酊(小/大) = 全（上方）判定の達成値 -magnitude ＋ 全制御値 -magnitude。
- 衰弱(-n) = 全制御値 -magnitude。
- 制御判定への達成値ペナルティは無し（論点1: 上方判定のみ）。

### ② 行動制限型 — kind による遮断（数値でない）
恐慌・重圧・捕縛・気絶/失神/仮死/昏睡。消費側が active condition を見て遮断/警告。
- 重圧 = `targetAbility` を使う上方判定を不可（スート→能力値一致の技能判定＋能力値判定。制御は可）。**9-4 で判定時に配線**。
- 捕縛 = 指定武器（識別キー）で攻撃不可。**9-4 で攻撃判定時に配線**（対象武器の保持方法は実装時詳細）。
- 恐慌（リアクション不可）・気絶等（メインプロセス不可）は **13 申し送り**。

### ③ 計算型 — kind＋強度をコードが算出（実装済み `computeJammingPenalty`）
電子妨害n。**準備中(`isPrepared`)**のアウトフィットを `category∈{武器・アーマーギア・サイバーウェア・トロン・サイコアプリ}` かつ電制(hack)≤`magnitude` で数え（上限10）、全（上方）判定にマイナス。
- **−10**: 電制≤n の **全身義体(`fullCyborg`)・ヴィークル**を準備、または該当**タップ(`tap`)で `isGhost` 登場中**。
- **ウェット**（準備中アウトフィットに**ウェットの識別キー** `WET_IDENT_KEY` あり）かつ該当1個以上 → **−1**。ウェットは専用フィールドでなく **「ウェット」アウトフィットを識別キーで検出**（新フィールド不要）。実キーは辞典＝フェーズ17 で確定。
- 強度違いは最大 n（非重複）。

### ④ 継続ダメージ型 — kind＋強度（発火は後続）
邪毒n。`magnitude=n` を保持。実発火（クリンナップごとに山札1枚＋n の肉体ダメージ）は**カット進行(13)＋ダメージ算出(12)**。9-4 は器のみ。

### 条件付き攻撃判定デバフ（萎縮・憎悪）
攻撃判定時（〈白兵〉〈射撃〉〈心理〉〈圧力〉を識別キーで検出）に `game.user.targets` を読み、`targetUuid` と照合して達成値 -5（`targetMode`）。戦闘(13)非依存。

## 4. BS 一覧の kind 割り当て

| BS | 型 | 効果値フラグ | 重複 |
|---|---|---|---|
| 恐慌 | ② | （なし） | 非 |
| 邪毒 | ④ | magnitude=n | 非（最大n） |
| 重圧 | ② | targetAbility | 非 |
| 衰弱 / 衰弱(-n) | ① | magnitude=n（全制御値 -n） | **重複** |
| 捕縛 | ② | 対象武器（識別キー） | **武器ごと** |
| 酩酊(小/大) | ① | magnitude=2/5 | 小大別・**重複** |
| 萎縮 | ①+対象 | targetUuid・targetMode=include | **対象ごと** |
| 憎悪 | ①+対象 | targetUuid・targetMode=exclude | 対象ごと存在・ペナルティ非重複 |
| 電子妨害 | ③ | magnitude=n | 非（n違いも非重複） |

## 5. 戦闘不能ダメージ状態

| 状態 | 型 | 効果 | 回復（発火は15/13） |
|---|---|---|---|
| 気絶 / 失神 | ② | メインプロセス不可（移行判定も） | カット進行終了 |
| 仮死 / 昏睡 | ②＋終端予約 | メインプロセス不可＋「シーン終了までに未治療→完全死亡」 | 治療(目標値20)→2シーン後 |
| 完全死亡 / 精神崩壊 / 抹殺(社会) | 終端マーカー | キャラロスト（社会はセッション終了後） | 原則不可（神業等） |

「この効果は BS として扱う」スタイル技能効果も `conditionKind` を持たせ、BS 解除で解除可能にする。

### 回復モデル（設計確定 2026-06-24・実装は発火フェーズ）

回復は **単一の回復機能を、受動（時間単位の進行で失効）と能動（マイナー/メジャー放棄等の行動消費）の両方で走らせる**（ユーザー確定）。`durationUnit` 等のフラグ設計と回復の**発火実装は、効果が実機で確認できるようになってから**（カット進行=13・時間管理=15 等が載った時点でまとめる）。フェーズ9 では条件の器・効果値・適用ロジックまで（回復は未実装）。

## 6. 5論点 裁定（2026-06-21）

1. `check`系の「あらゆる判定」は**上方判定のみ**。制御判定は「制御判定」を指定した効果のみ対象。
2. 重圧 = 指定能力値を使う判定が不可（そのままの意味。制御は可）。
3. 萎縮/憎悪 = 対象 UUID ＋ `game.user.targets` 照合で **9-4 完結**（戦闘13不要）。
4. 重複明記なしの BS は全て非重複。強度違いは最大 n。
5. 効果値は **condition 自身の専用フィールド**で設定（汎用 changes でなく）。付与 UI は既存ステータスエフェクト。

## 7. 9-4 スコープ / 申し送り

**9-4 で実装**: condition フラグスキーマ＋詳細タブ UI（kind 別効果値）／kind 別適用（①数値・②重圧捕縛の遮断・③電子妨害算出・萎縮憎悪の対象照合）／11 BS＋戦闘不能の `CONFIG.statusEffects` 定義・kind 割り当て／持続単位フラグ（基盤のみ）／効果文ユーザー入力。

**申し送り**: ダメージ算出本体→12 ／ チャート参照→付与トリガ→12 ／ 邪毒・恐慌・メインプロセス不可の発火→13 ／ 回復タイミングの発火→15 ／ 仮死昏睡の死亡確定→15。

## 8. カード決定型 BS のドロー機構（設計確定 2026-06-23・**メカニクス実装済み 2026-06-23**）

効果が**カードを引いて決まる** BS のドロー機構。`condition-resolution.mjs`／`condition-resolution-core.mjs` に実装。**実機検証はダメージ判定＝フェーズ12 が前提のため未検証**（メカニクスのみ・修正は12）。

**実装済み（9-4 でのメカニクス）**: 状態カスケード（`inflicts`→別状態を status のみ・hideFromList で自動付与・多重防止・循環なし）／ダメージ由来 AE のリスト非表示（`effects-sheet-mixin` 除外・技能由来は表示）／衰弱・重圧のカードドロー（BS受付チャット→山札ドロー→スート→対象能力値・N◎VA値→magnitude、ジョーカーはダイアログで引き直し/ワイルドカード、ドロー主体=衰弱RL/重圧受けたキャラ。**トークン右クリック「ステータス効果の設定」からの付与もバッジのみ**（2026-07-11: CONFIG.statusEffects の flags に hideFromList を追加＝ダメージ適用と同様、シートのアクティブエフェクト一覧に行を出さない）。**受付チャットは全体公開**＝2026-07-11 修正: 従来の whisper を撤去——**個人送信チャットは判定要求の任意選択以外に存在させない**(ユーザー確定・postConditionOutcome の whisper サポートも削除)。同日、ドローが `deck.draw(discard)` と逆向きで**捨て札から引こうとして失敗するバグ**を修正=正 `discard.draw(deck)`・表向き化して再取得。さらに**スート未正規化**（Foundry 標準デッキは複数形 "spades" 等）で対応能力値・制御値が「？」になる不具合を修正=純関数 `normalizeSuit`（tnx-check-engine）を判定フローと共用・正規化不能はジョーカー扱いでワイルドカード指定へ）／controlNegate（制御判定で無効/降格。**2026-07-08 本式化済み**＝判定要求カード標準機構＋通常の制御判定フロー・完了継続で結果適用。簡易ドロー方式は全廃）／`applyDamageChartResult`（ダメージ値→負傷状態の付与入口）／純粋ロジックは単体テスト（conditionNeedsDraw/drawResultFlags/negateOutcome）。

**12 以降で修正/発火**: ダメージ算出本体（カード＋攻撃力−軽減）→12 ／ 制御判定の本式化→**12 で完了**（2026-07-08。checkRequest 標準カード＋TnxCheckFlow＝手札/山札・失敗する権利、ctx.controlNegate 完了継続で無効/降格/継続を適用。本体 `62e35dc`）／ block 系（恐慌=リアクション・気絶=メインプロセス・捕縛=攻撃武器・狼狽=ムーブ/メジャー）の発火→13 ／ 萎縮憎悪の発火→12 ／ 邪毒・回復タイミング→13/15。

### 対象 BS（正本 Bad_Status.md に照合）
- **衰弱（数字なし）**: 「受ける際に RL が山札1枚を引き、対応スートの制御値をカードの数字分減少」→ スート＝対象能力値（その1つの制御値）、数字＝`magnitude`。
- **重圧（能力値指定なし）**: 「能力値指定がない場合は…山札1枚を引き、そのスートに対応する能力値に重圧」→ スート＝対象能力値のみ（数字なし）。能力値が**指定される**場合は引かず手動指定（現状の abilityField 維持）。
- **除外**: 邪毒のクリンナップ毎ドローは**効果決定でなく継続ダメージの発火**＝フェーズ13（別系統）。衰弱(-数字)/萎縮/憎悪/電子妨害は引かない。

### 確定仕様（ユーザー 2026-06-23）
- **数値**: N◎VA 値（絵札=10・A=11）で**統一・例外なし**（`getCardCheckValue` と同一）。
- **ドロー主体は BS で異なる**: **重圧＝受けたキャラクター（プレイヤー）**、**衰弱＝RL（GM）** が引く。
- **自動ドローしない**。付与時に**「BS受付状態」**（判定の pending と同様の待機状態）へ入り、適切な主体がドローして確定する。発火タイミングは付与時。
- **ジョーカー**: 明記なし。ダイアログで (a) 引き直し / (b) 引いた本人がワイルドカードとして**スート＋数字を任意決定**、のいずれかを選べるようにする。
- **山札が空**のケースは考慮しない。
- ドローしたカードは**捨て札へ**（消費）。結果は `flags.tokyo-nova-axleration.conditions[<kind>]`（targetAbility ＋ 衰弱は magnitude）へ書き込み、**チャットに記録**（例「衰弱: ♥7 → 生命の制御値 −7」）。
- **効果決定カードは1枚に一本化（2026-07-12 ユーザー指示）**: 「山札を引く」ボタンのカードと結果のカードを分けず、同一カードの状態領域を `conditionDraw` フラグからライブ描画する（未解決=ボタン／解決後=引いたカード+効果表示に置換。checkRequest・攻撃カードと同型）。結果には引いたカード（スート・数字・ワイルドカード指定）も明示。フラグ更新は非作者なら GM へ委譲（checkModify=自スコープフラグ限定の汎用パッチ委譲を流用）。

### 実装メモ（既存インフラ）
- 山札/捨て札: `TnxActionHandler.getActiveDeck()` / `getActiveDiscardPile()`。スート→能力値: `SUIT_TO_ABILITY`。数値: `getCardCheckValue`。
- 「BS受付状態」は判定の pending（`TnxCheckFlow.context`・HUD 表示・RL 要求フロー）と同型を流用しうる。主体振り分け（プレイヤー/GM）は RL 要求フローと同様。

## 特殊タグ［支配］（dominated・2026-07-12 ユーザー確定）

- **支配されたキャラクターは RL 操作になる**＝自動化せずに運用できる範囲。タグは type なしのマーカー（行動ブロック・ロスト処理なし・戦闘不能グループ・非重複）。
- 付与＝**ダメージタグ改変 AE**（対象側・inflicts カスケードで評価・`applyDamageTagMods` 純関数）: `damage.replaceTag.<元タグ>`（置換・例 昏睡/精神崩壊→支配）／`damage.addTag.<元タグ>`（追加・例 抹殺に支配）。負傷由来の付与のみ対象（手動付与の状態には効かない）。
- 解除（ユーザー裁定）: 上書き由来＝［昏睡］と同じ（治療目標値 20・`replacedFrom` が根拠・treatment-flow が参照）。追加由来＝追加元チャートの治療/無効化で同時解除（woundSource 紐づき・目標値には関与しない）。
- 適用効果はダメージ適用と**同時に自動付与**される（2026-07-12・押し順の順序依存なし）。
- 正本: [Damage_Rules.md](../Game_Rules/Damage_Rules.md)「特殊タグ［支配］」


## 回復・治療系スタイル技能（用途の回復設定・2026-07-13 ユーザー確定）

BS・戦闘不能・負傷を除去する回復・治療系スタイル技能の表現。数も種類も多いため**用途の設定でフレキシブルに構成**する（AE キーではない＝回復は能動的な行動でありアイテムロール原則に乗せる。回復判定へのバフは既存の `check.*`/`check.all` がそのまま効く）。

- **範囲（`recoveryTargets`）**: 大分類（BS／戦闘不能／負傷・肉体／負傷・精神／負傷・社会）→小分類（個別タグ・空＝グループ全体）の行。複数行は OR。「BS：捕縛すべて」＝捕縛1行＋該当すべて、「BS すべて」＝BS 全体行＋該当すべて、「ダメージすべて治療」＝負傷グループ行＋該当すべて。
- **除外（`recoveryExcludes`）**: 指定した**ダメージ効果タグ自身＋そのタグを与える負傷**を除外（「指定タグを含むもの以外すべて」＝ユーザー確定）。**通例は「完全死亡」「精神崩壊」を除外**（ダメージ全回復系の技能でも治療不可＝神業のみ）。**「抹殺」は神業以外で治療不可の可能性があるが性質が大きく違うため未確定**＝技能ごとの設定・卓裁定（システムはハードコードで強制しない＝技能を強制しない方針）。
- **回復数**: N 個（使用時に対象の状態一覧から選択）または「該当すべて」。
- **目標値**: 回復判定の式 `recoveryTargetFormula`＝`@condition.magnitude`（選択した状態の強度・複数選択時は最大）・`@condition.woundValue`（負傷のダメージ値・同）を参照可。空なら用途の目標値設定。
- **フロー**: アイテムロール→対象解決（ターゲット1体・無ければ確認して自分）→**対象が現在受けている状態から回復対象を選択**→宣言用途＝消費適用して即除去／check 用途＝判定（`ctx.recovery` 完了継続・成功で除去・失敗はそのまま・目標値なしは達成値報告のみ＝適用は卓裁定）。
- **除去の意味論（既存規約の流用）**: BS/戦闘不能＝その効果のみ（woundSource は辿らない＝BS を回復してもダメージは治療されない）。負傷＝治療と同じ範囲（負傷＋紐づき戦闘不能＋非BS。BS は残る）。除去権限が無ければ treatmentApply ソケットで GM 委譲。
- **社会負傷の治療**は専用スタイル技能か神業のみの経路（〈医療〉不可）＝範囲に「負傷（社会）」を設定した用途がその専用技能。
- 実装: `recovery-flow.mjs`（フロー）・`conditions.mjs`（純関数 `recoveryKindMatches`/`recoveryKindExcluded`・テスト付き）。継続処理のため再判定の対象外。
