# コンディション（BS・戦闘不能）の ActiveEffect 表現（フェーズ9-4 設計・確定）

> **表記規約（2026-09-05 ユーザー指示）**: **戦闘不能のタグは必ず ［］ でくくって表示する**——［完全死亡］［精神崩壊］［抹殺］［気絶］［失神］［仮死］［昏睡］［行動不可］［支配］。ルールブックの表記に合わせる。BS と負傷（ダメージそのもの）は名前のまま（文中では 「」 でくくる既存の書式）。**実装は `conditions.mjs` の `conditionDisplayName(kind, {quote})` が単一の出どころ**で、状態を名前で出す箇所（カード・付与した効果の名前・`CONFIG.statusEffects`・用途シートの選択肢・回復候補・チャート本文・選択ダイアログ）は必ずこれを通す（本体 `7ed80fc`）。

ダメージや技能で付与される**状態（condition）**を ActiveEffect として表現するモデル。バッドステータス（[Bad_Status.md](../Game_Rules/Bad_Status.md)）と戦闘不能ダメージ状態（[Damage_Rules.md](../Game_Rules/Damage_Rules.md) §戦闘不能ダメージ）を同一モデルで扱う。AE 適用の土台は [Active_Effects.md](Active_Effects.md)（v2）。

> **ステータス**: 設計確定（2026-06-22、ユーザー承認）。付与 UI は Foundry 標準のステータスエフェクト（`CONFIG.statusEffects` / トークン HUD）。

## 0. 大原則（condition は自己完結する実体）

D&D と違い TNX の BS は**効果が一意固定でなく、効果値がインスタンスごとに可変**（邪毒n・衰弱-n・電子妨害n・重圧の対象能力値・萎縮/憎悪の対象…）。よって「定義が効果を固定所有するレジストリ」では不足。一方、効果値を**汎用の変更（changes）タブ**で設定すると、アイテムバフと区別がつかず condition の意味が失われる。

このため condition は次の二層で表す。**設定はすべて condition 自身に閉じる**。

| 層 | 中身 | 置き場所 |
|---|---|---|
| **同一性** | status id / `conditionKind` / 回復トリガ / 除去可否 / 「BS扱い」 | condition 定義（貼付で確定） |
| **効果値（可変）** | -n / 強度 n / 対象 ability・UUID 等 | **condition 専用フラグ**（詳細タブで設定） |

- **condition は汎用 changes タブを使わない。** 効果値は**詳細タブの condition 専用フィールド**（重複可と同じ場所）または貼付時ダイアログで設定し、`flags.tokyo-nova-axleration` に保持する。
- **効果はコードが `conditionKind` ＋効果値フラグを読んで適用**する（changes 経由でない）。これにより condition（status＋値フィールド）が**設定の唯一の出所**となり、手打ち changes で replicate できず、アイテムバフ（v2・changes 手打ち）と完全に住み分く。
- **アイテムバフ（v2）と condition は別系統**:
  - アイテムバフ … 変更タブで `key+mode+value` を手打ち（自由・Active_Effects v2）。
  - condition … status で貼り、詳細タブの専用欄で効果値を設定、適用はコード（kind 駆動）。
- 重複は既存の重複可フラグ（`stackable`）。**重複明記の BS のみ true**。非重複は最大採用（強度違いは最大 n）。
- 効果文はルール本文を焼き込まず**ユーザー入力**（AE の description を流用、§4.1）。

## 1. condition のフラグ・スキーマ（`flags.tokyo-nova-axleration`）

既存の `effectId` / `stackable` に加える:

- `conditionKind`（string）… condition の種別。コードの適用分岐・回復・表示・除去判定の鍵。
- `magnitude`（number）… 可変の効果量（酩酊 2/5・衰弱 n・邪毒 n・電子妨害 n 等）。kind ごとに意味づけ。
- `targetAbility`（"reason"|"passion"|"life"|"mundane"）… 重圧の対象能力値。
- `targetUuid`（string）… 萎縮/憎悪の対象キャラ。
- `targetMode`（"include"|"exclude"）… 対象を含む時/含まない時に -5（萎縮=include / 憎悪=exclude）。
- `durationUnit`（enum）… 回復トリガ（mainProcessStart / mainProcessEnd / cleanup / sceneEnd / cutEnd / treated / actEnd 等）。9-4 はフラグ保持のみ。発火は 13/14/15。

status id（`CONFIG.statusEffects`）が condition の一意性を担い、`conditionKind` がコード分岐を担う（同義になる想定でよいが、id は Foundry 連携・kind は適用ロジックの鍵として分ける）。

## 2. 詳細タブ UI（condition 専用フィールド）

`renderActiveEffectConfig` フック（重複可チェックボックスと同じ）で、AE が condition（`conditionKind` を持つ）のとき詳細タブに kind 別フィールドを出す:

- 数値修正型（酩酊・衰弱）: 「効果量」欄（`magnitude`）
- 強度型（邪毒・電子妨害）: 「強度 n」欄（`magnitude`）
- 重圧: 能力値ドロップダウン（`targetAbility`）
- 萎縮・憎悪: 対象選択（`targetUuid` ＋ `targetMode` は kind で固定）
- 共通: 回復トリガ（`durationUnit`）／重複可（`stackable`）

## 3. 効果分類（4型）と適用ロジック

適用はアイテムバフと同じ**2注入点**（[Active_Effects.md](Active_Effects.md) §1）に condition 用コードを追加する。

### ① 数値修正型 — コードが派生値／判定に加算
酩酊・衰弱。`conditionKind`＋`magnitude` を読み、対象へ -magnitude。
- 酩酊(小/大) = 全（上方）判定の達成値 -magnitude ＋ 全制御値 -magnitude。
- 衰弱(-n) = 全制御値 -magnitude。
- 制御判定への達成値ペナルティは無し（論点1: 上方判定のみ）。

### ② 行動制限型 — kind による遮断（数値でない）
恐慌・重圧・捕縛・気絶/失神/仮死/昏睡。消費側が active condition を見て遮断/警告。
- 重圧 = `targetAbility` を使う上方判定を不可（スート→能力値一致の技能判定＋能力値判定。制御は可）。**9-4 で判定時に配線**。
- 捕縛 = 指定武器で攻撃不可。**対象武器の指定機構（2026-07-15 実装）**＝効果設定シート詳細タブの `対象武器` プルダウン（対象アクターの `type:"weapon"` アイテム＋**生身**）。保持は **`targetWeapon`＝アイテム ID・空=生身**（攻撃の「攻撃で使用」`attackItemId` と同型・[[feedback_reuse_existing_ui_precedent]]）。従来の生キー手入力欄は指定機構として機能していなかったため置換。攻撃判定時の遮断配線は 9-4/13。
- 恐慌（リアクション不可）・気絶等（メインプロセス不可）は **13 申し送り**。

### ③ 計算型 — kind＋強度をコードが算出（実装済み `computeJammingPenalty`）
電子妨害n。**準備中(`isPrepared`)**のアウトフィットを `category∈{武器・アーマーギア・サイバーウェア・トロン・サイコアプリ}` かつ電制(hack)≤`magnitude` で数え（上限10）、全（上方）判定にマイナス。
- **−10**: 電制≤n の **全身義体(`fullCyborg`)・ヴィークル**を準備、または該当**タップ(`tap`)で `isGhost` 登場中**。
- **ウェット**（準備中アウトフィットに**ウェットの識別キー** `WET_IDENT_KEY` あり）かつ該当1個以上 → **−1**。ウェットは専用フィールドでなく **「ウェット」アウトフィットを識別キーで検出**（新フィールド不要）。実キーは **`background_wet`** に確定（2026-09-01 ユーザー裁定「background_wetの方が被りづらくて堅牢」＝辞典のウェットのアイテムはこの識別キーで入力する）。
- 強度違いは最大 n（非重複）。

### ④ 継続ダメージ型 — kind＋強度（発火は後続）
邪毒n。`magnitude=n` を保持。実発火（クリンナップごとに山札1枚＋n の肉体ダメージ）は**カット進行(13)＋ダメージ算出(12)**。9-4 は器のみ。

### 条件付き攻撃判定デバフ（萎縮・憎悪）
攻撃判定時（〈白兵〉〈射撃〉〈心理〉〈圧力〉を識別キーで検出）に `game.user.targets` を読み、`targetUuid` と照合して達成値 -5（`targetMode`）。戦闘(13)非依存。

## 4. BS 一覧の kind 割り当て

| BS | 型 | 効果値フラグ | 重複 |
|---|---|---|---|
| 恐慌 | ② | （なし） | 非 |
| 邪毒 | ④ | magnitude=n | 非（最大n） |
| 重圧 | ② | targetAbility | 非 |
| 衰弱 / 衰弱(-n) | ① | magnitude=n（全制御値 -n） | **重複** |
| 捕縛 | ② | 対象武器（`targetWeapon`＝アイテムID・空=生身） | **武器ごと** |
| 酩酊(小/大) | ① | magnitude=2/5 | 小大別・**重複** |
| 萎縮 | ①+対象 | targetUuid・targetMode=include | **対象ごと** |
| 憎悪 | ①+対象 | targetUuid・targetMode=exclude | 対象ごと存在・ペナルティ非重複 |
| 電子妨害 | ③ | magnitude=n | 非（n違いも非重複） |

## 5. 戦闘不能ダメージ状態

| 状態 | 型 | 効果 | 回復（発火は15/13） |
|---|---|---|---|
| 気絶 / 失神 | ② | メインプロセス不可（移行判定も） | カット進行終了 |
| 仮死 / 昏睡 | ②＋終端予約 | メインプロセス不可＋「シーン終了までに未治療→完全死亡」 | 治療(目標値20)→2シーン後 |
| 完全死亡 / 精神崩壊 / 抹殺(社会) | 終端マーカー | キャラロスト（社会はセッション終了後） | 原則不可（神業等） |

「この効果は BS として扱う」スタイル技能効果も `conditionKind` を持たせ、BS 解除で解除可能にする。

### 回復モデル（設計確定 2026-06-24・実装は発火フェーズ）

回復は **単一の回復機能を、受動（時間単位の進行で失効）と能動（マイナー/メジャー放棄等の行動消費）の両方で走らせる**（ユーザー確定）。`durationUnit` 等のフラグ設計と回復の**発火実装は、効果が実機で確認できるようになってから**（カット進行=13・時間管理=15 等が載った時点でまとめる）。フェーズ9 では条件の器・効果値・適用ロジックまで（回復は未実装）。

## 6. 5論点 裁定（2026-06-21）

1. `check`系の「あらゆる判定」は**上方判定のみ**。制御判定は「制御判定」を指定した効果のみ対象。
2. 重圧 = 指定能力値を使う判定が不可（そのままの意味。制御は可）。
3. 萎縮/憎悪 = 対象 UUID ＋ `game.user.targets` 照合で **9-4 完結**（戦闘13不要）。
4. 重複明記なしの BS は全て非重複。強度違いは最大 n。
5. 効果値は **condition 自身の専用フィールド**で設定（汎用 changes でなく）。付与 UI は既存ステータスエフェクト。

### 対象 BS（正本 Bad_Status.md に照合）
- **衰弱（数字なし）**: 「受ける際に RL が山札1枚を引き、対応スートの制御値をカードの数字分減少」→ スート＝対象能力値（その1つの制御値）、数字＝`magnitude`。
- **重圧（能力値指定なし）**: 「能力値指定がない場合は…山札1枚を引き、そのスートに対応する能力値に重圧」→ スート＝対象能力値のみ（数字なし）。能力値が**指定される**場合は引かず手動指定（現状の abilityField 維持）。
- **除外**: 邪毒のクリンナップ毎ドローは**効果決定でなく継続ダメージの発火**＝フェーズ13（別系統）。衰弱(-数字)/萎縮/憎悪/電子妨害は引かない。

### 確定仕様（ユーザー 2026-06-23）
- **数値**: N◎VA 値（絵札=10・A=11）で**統一・例外なし**（`getCardCheckValue` と同一）。
- **ドロー主体は BS で異なる**: **重圧＝受けたキャラクター（プレイヤー）**、**衰弱＝RL（GM）** が引く。
- **自動ドローしない**。付与時に**「BS受付状態」**（判定の pending と同様の待機状態）へ入り、適切な主体がドローして確定する。発火タイミングは付与時。
- **ジョーカー**: 明記なし。ダイアログで (a) 引き直し / (b) 引いた本人がワイルドカードとして**スート＋数字を任意決定**、のいずれかを選べるようにする。
- **山札が空**のケースは考慮しない。
- ドローしたカードは**捨て札へ**（消費）。結果は `flags.tokyo-nova-axleration.conditions[<kind>]`（targetAbility ＋ 衰弱は magnitude）へ書き込み、**チャットに記録**（例「衰弱: ♥7 → 生命の制御値 −7」）。
- **効果決定カードは1枚に一本化（2026-07-12 ユーザー指示）**: 「山札を引く」ボタンのカードと結果のカードを分けず、同一カードの状態領域を `conditionDraw` フラグからライブ描画する（未解決=ボタン／解決後=引いたカード+効果表示に置換。checkRequest・攻撃カードと同型）。結果には引いたカード（スート・数字・ワイルドカード指定）も明示。フラグ更新は非作者なら GM へ委譲（`applyMessagePatch`=自スコープフラグ限定の汎用パッチ委譲。2026-07-16 に旧 checkModify/attackUpdate/damageUpdate/usageEffectApplied を messagePatch 1種へ一本化）。

### 実装メモ（既存インフラ）
- 山札/捨て札: `TnxActionHandler.getActiveDeck()` / `getActiveDiscardPile()`。スート→能力値: `SUIT_TO_ABILITY`。数値: `getCardCheckValue`。
- 「BS受付状態」は判定の pending（`TnxCheckFlow.context`・HUD 表示・RL 要求フロー）と同型を流用しうる。主体振り分け（プレイヤー/GM）は RL 要求フローと同様。

## 特殊タグ［支配］（dominated・2026-07-12 ユーザー確定）

- **支配されたキャラクターは RL 操作になる**＝自動化せずに運用できる範囲。タグは type なしのマーカー（行動ブロック・ロスト処理なし・戦闘不能グループ・非重複）。
- 付与＝**ダメージタグ改変 AE**（対象側・inflicts カスケードで評価・`applyDamageTagMods` 純関数）: `damage.replaceTag.<元タグ>`（置換・例 昏睡/精神崩壊→支配）／`damage.addTag.<元タグ>`（追加・例 抹殺に支配）。負傷由来の付与のみ対象（手動付与の状態には効かない）。
- 解除（ユーザー裁定）: 上書き由来＝［昏睡］と同じ（治療目標値 20・`replacedFrom` が根拠・treatment-flow が参照）。追加由来＝追加元チャートの治療/無効化で同時解除（woundSource 紐づき・目標値には関与しない）。
- 適用効果はダメージ適用と**同時に自動付与**される（2026-07-12・押し順の順序依存なし）。

## 回復・治療系スタイル技能（用途の回復設定・2026-07-13 ユーザー確定）

BS・戦闘不能・負傷を除去する回復・治療系スタイル技能の表現。数も種類も多いため**用途の設定でフレキシブルに構成**する（AE キーではない＝回復は能動的な行動でありアイテムロール原則に乗せる。回復判定へのバフは既存の `check.*`/`check.all` がそのまま効く）。

- **範囲（`recoveryTargets`）**: 大分類（BS／戦闘不能／負傷・肉体／負傷・精神／負傷・社会）→小分類（個別タグ・空＝グループ全体）の行。複数行は OR。「BS：捕縛すべて」＝捕縛1行＋該当すべて、「BS すべて」＝BS 全体行＋該当すべて、「ダメージすべて治療」＝負傷グループ行＋該当すべて。
- **受けたシーン（`flags.receivedScene`・フェーズ17-2）**: 状態（コンディション）は生成時（`preCreateActiveEffect`・付与経路を問わず）に「どのアクトの何シーン目に受けたか」`{act: sessionState.actId, number: sessionState.sceneNumber}` を持つ。神業の治癒の「そのシーンで受けたものしか」（《腹心》《人命救助》＝完全死亡・精神崩壊のみ／《黄泉還り》を他人に＝すべて）の判定材料。アクト外は act が空で、比較側は不明を通す（検査できないものはゲートしない）。
- **神業由来の状態（`flags.fromMiracle`・フェーズ17）**: 神業の用途から生じた状態・効果の印。**神業の治療でしか除去できない**（回復の候補列挙と治療メニュー起点の両方でゲート）。刻む側は 17-3 の神業版ダメージカードの適用（終端状態の直接付与・`applyDamageChartResult` の `extraFlags`）で、カスケード（`createActiveEffect` フックの inflicts）も供給元の印を引き継ぐ。
- **除外（`recoveryExcludes`）**: 指定した**ダメージ効果タグ自身＋そのタグを与える負傷**を除外（「指定タグを含むもの以外すべて」＝ユーザー確定）。**通例は「完全死亡」「精神崩壊」を除外**（ダメージ全回復系の技能でも治療不可＝神業のみ）。**「抹殺」は神業以外で治療不可の可能性があるが性質が大きく違うため未確定**＝技能ごとの設定・卓裁定（システムはハードコードで強制しない＝技能を強制しない方針）。
- **回復数**: N 個（使用時に対象の状態一覧から選択）または「該当すべて」。
- **目標値**: 発動タブの目標値設定に**一本化**（2026-07-13・回復専用の式欄は廃止＝目標値の入力先を二重化しない）。「解説参照」「その他」の自由記入欄の式が `@condition.magnitude`（選択した状態の強度・複数選択時は最大）・`@condition.woundValue`（負傷のダメージ値＝**治療対象のダメージのチャート値**・同）を参照できる（→ [Check_Rules](../Game_Rules/Check_Rules.md)「用途の目標値の扱い」）。チャート値は保存された `woundValue` フラグ優先・無ければ kind のチャート行番号から導出（`woundChartValue`＝トークントグル/手動付与の負傷はフラグを持たないため。2026-07-18 是正）。
- **フロー**: アイテムロール→対象解決（ターゲット1体・無ければ確認して自分）→**対象が現在受けている状態から回復対象を選択**→宣言用途＝消費適用して即除去／check 用途＝判定（`ctx.recovery` 完了継続・成功で除去・失敗はそのまま・目標値なしは達成値報告のみ＝適用は卓裁定）。
- **回復したことの提示（2026-09-07 ユーザー指示）**: 帰結だけの短いカードを**別に出さない**。その使用を表しているカードの帰結行に「〈対象〉の〈状態〉を回復した」と出す——神業（治癒・黄泉還り等）＝神業カード／宣言の治療＝アイテムの解説カード（他の宣言用途と同じ）／判定の治療＝判定結果カード（`stampCardOutcome`。→ [Templates.md](../UI/Templates.md)）。**失敗は帰結行を出さない**（判定結果カード自身が「失敗」と示すため）。状態名の表記は `conditionDisplayName(kind, {quote:true})` 一本＝戦闘不能だけ ［］・**負傷（ダメージ）は「」**（［］ でくくると戦闘不能と読み違えるため・2026-09-07 ユーザー指示）。修理・改造も同じ機構（判定結果カードの帰結行）。
- **治療メニューとの一本化（2026-07-18 ユーザー確定）**: シートの状態クリック「治療」も本機構の用途起動に一本化（旧・治療専用の目標値ハードコード 15/20・代用判定・完了継続 `ctx.treatment` を廃止＝継続は `ctx.recovery` に統一）。入口 `treatment-flow.mjs` がクリックされた状態を**ダメージインスタンス（負傷＋紐づき戦闘不能/支配）の kind 集合**へ展開し、**選択した治療者**（操作可能なキャスト/ゲストから選択・既定=担当キャラ・1体なら即決。担当キャラ固定は RL=複数ゲスト操作で破綻＝2026-07-18 ユーザー是正）のアイテムから範囲適合する治療用途（純関数 `usageCanTreatKinds`）を照合→prebound 文脈（患者・クリック状態）で recovery-flow へ合流（対象解決・回復対象選択をスキップ）。適合ゼロ＝「治療できる技能が無い」で中止・複数合致（タグ改変 AE 等のまれな場合）のみ用途選択。**設定規約: 通常ダメージ用の治療用途は戦闘不能系タグ全8種を除外に入れる**（除外の inflicts 展開で戦闘不能を伴う負傷が自動脱落→気絶/失神=15・仮死/昏睡/支配=20 は kind 限定範囲＋数字目標値の用途で表現。→ [Damage_Rules](../Game_Rules/Damage_Rules.md)「治療の用途一本化」）。
- **除去の意味論（既存規約の流用）**: BS＝その効果のみ（woundSource は辿らない＝BS を回復してもダメージは治療されない）。**戦闘不能＝元となる負傷（ダメージ）ごと治療する**（2026-07-13 ユーザー確定。戦闘不能はダメージそのもの＝2026-07-09 裁定・医療の治療と同じ扱い。孤立＝手動付与のみ単体除去）。負傷＝治療と同じ範囲（負傷＋紐づき戦闘不能＋非BS。BS は残る）。除去権限が無ければ treatmentApply ソケットで GM 委譲。
- **社会負傷の治療**は専用スタイル技能か神業のみの経路（〈医療〉不可）＝範囲に「負傷（社会）」を設定した用途がその専用技能（2026-07-18: 治療メニューの社会ハードブロックも撤去＝可否は範囲設定が正）。
- 実装: `recovery-flow.mjs`（フロー）・`treatment-flow.mjs`（治療メニューの入口照合）・`conditions.mjs`（純関数 `recoveryKindMatches`/`recoveryKindExcluded`/`usageCanTreatKinds`・テスト付き）。再判定は失敗→成功の遷移でのみ除去を再実行（`rerunOnSuccessOnly`・2026-07-15 継続全種対応）。


## 効果の無視ゲート（「ダメージや BS の効果を受けない」・2026-07-16 ユーザー確定）

まれに「特定の（あるいは全ての）ダメージや BS の**効果を受けない**」効果が存在する。これは**ダメージ・BS を防ぐ／消す機構ではない**——タグ・BS・負傷そのものは付与され**残る**（シートにバッヂも出る）。無視するのは、それらが与える**具体的な効果（数値ペナルティ・行動制限の両方）だけ**。

- **対象の宇宙＝自分が受けているコンディションの効果**。効果が数値（酩酊 −2／衰弱／邪毒／電子妨害／萎縮・憎悪 −5）でも行動制限（重圧の判定不可・恐慌のリアクション不可・捕縛の武器不可・狼狽のムーブ不可）でも区別しない（どれも「コンディションの効果」）。※「行動制限」は BS と別の分類ではない＝**重圧・恐慌・捕縛・狼狽も BS**。数値か制限かで軸を割らない。
- **指定の粒度（個別・グループ・全ての全域）**: 個別 BS ／ 全 BS ／ ダメージ由来（全・系統別）／ 全て。「全〈系統〉ダメージの効果を受けない」で無視されるのは**その系統のダメージから生じた効果一式**（負傷自身の数値効果＋付随した BS＋付随した戦闘不能）。ダメージ由来は各効果の `woundCategory`（負傷自身）／`woundSource` → 元負傷の `woundCategory` で辿る。
- **消費段階のゲート**（付与時ではない）: 効果を**読み取って適用する各消費点**で、無視対象の行を飛ばす。標準の値バフ／判定バフ／ダメージバフと違い「加算」でなく「除外」。コンディションの効果は各サブシステムに**異なる時点で着地する**（達成値＝判定時・制御値／部位＝派生値算出時・恐慌／捕縛／邪毒＝フェーズ13）ため**単一パイプラインには畳めない**（文脈依存の実行時効果があり、個別読みが妥当）。堅牢性は**正規アクセサ `getEffectiveConditions(actor)` を必ず経由**する規約で担保（各行に `effectIgnored` を付与・消費点追加時は grep 全数掃引＝`readFlag`／`AE_FLAG_PARAMS` と同じ）。存在自体（バッヂ・回復・治療・カスケード）は別途 `readConditions`／`actor.effects`（無視されても残る）。
- **表示**: 無視中の BS はバッヂを残しつつ取り消し線＋淡色、tooltip に供給元名（ignore を与えた効果名）。トークンのステータスアイコンは対象外（ユーザー確定）。
- **手動オーバーライド（卓ツール・2026-07-16 ユーザー確定）**: ルール由来の AE とは別に、RL／プレイヤーが**個別インスタンスの効果をその場で止める**。BS バッヂのコンテキストメニュー「効果を無視する／無視を解除する」で `flags…manuallyIgnored` をトグル（可否ゲートなし・いつでも）。`ignore.*` と同じ `effectIgnored` に合流し、消費側の抑止・取り消し線を共有（tooltip は「手動で無視中」）。位置づけは「手動ダメージ修正」など既存の"卓の最終裁定"ツールと同じ＝ゲームルールそのものではない。
- AE キー（`ignore.all`／`ignore.bs`[`.<kind>`]／`ignore.damage`[`.<系統>`]）と実装詳細は [Active_Effects.md](Active_Effects.md)「無視ゲート」。純関数 `ignoreRuleMatches`／`gatherIgnoreRules`／`getEffectiveConditions`（`conditions.mjs`・テスト付き）。


## 負傷そのものの直接効果（特定技能ペナルティ／使用不可／報酬点不可・2026-07-16 ユーザー確定）

一部のダメージ（負傷）は BS へのカスケードではなく、**負傷そのもの**が効果を課す（ユーザー確定「負傷そのものに効果を持たせる。そうでなければ意味がない」）。従来「負傷は直接効果を持たず inflicts/notes で表す」とした前提を、この 7 負傷について更新する。効果は damage-chart の負傷 def に直接持たせ、`readConditions` の実効行から消費点が読む。

### 対象と効果（3メカニクス）

| 負傷 | ① 数値 −5 | ② 技能使用不可 | ③ 報酬点不可 | 持続 |
|---|---|---|---|---|
| 眼部損傷 phys-14 | 〈知覚=perception〉 | — | — | 治療まで |
| 口座凍結 soc-13 | — | 〈信用=stature〉固定 | ○ | 治療まで |
| 造反 soc-14 | — | 〈社会〉選択 | — | 治療まで |
| 人脈消失 soc-15 | — | 〈コネ〉選択 | — | 治療まで |
| 信用失墜 soc-6 | — | 〈信用=stature〉固定 | ○ | 次シーン（休眠） |
| スキャンダル soc-7 | — | 〈社会〉選択 | — | 次シーン（休眠） |
| 信頼喪失 soc-8 | — | 〈コネ〉選択 | — | 次シーン（休眠） |

- **「使用」＝判定**（組み合わせ参加技能も含む・ユーザー確定）。②は判定に参加する技能（ベース＋組み合わせ）の識別キーで照合。
- **使用不可は判定起動時にブロック**（警告を出して判定を開かない。**2026-07-16 改訂**＝当初「警告のみ・判定続行」としたが、重圧が「カードを消費できず完全ブロック」なのに合わせ、ユーザー裁定で完全ブロックへ変更）。照合は `gatherSkillUseWarnings`（重圧の能力値ブロック `getCheckBlock` とは別関数だが、起動ブロックの体裁は共通）。
- **技能の識別は識別キー**で行う（名前照合しない）。固定（知覚/信用）は def にキーをハードコード（判定ロジックの構造的最小限＝§4.1 許容）、選択（社会/コネ）は付与時にユーザーが選び `targetSkill`（識別キー）に確定。

### データ構造

- 負傷 def（`damage-chart.mjs`）: `skillPenalty:{skillKey,value}` ／ `skillBlock:{skillKey}` or `{category:"society"|"contact"}` ／ `bountyBlock:true` ／ `sceneDeferred:true`。
- condition インスタンスフラグ（`flags…conditions[<kind>]`）: `targetSkill`（選択結果の識別キー）・`pendingScene`（次シーン発火の休眠）。`readConditions` が両者を読む。

### 消費点（既存注入点を流用）

- ① `gatherConditionCheckSources`（達成値 −value・上方判定のみ・酩酊と同経路＝チャート内訳に自動表示）。ctx に参加技能識別キー `skillKeys`（`ctx.skillIds`→`identificationKey`）を渡す。
- ② `TnxCheckFlow.open` の `_activationBlockReason` が `gatherSkillUseWarnings` を参照し、該当すれば**警告＋起動中止（判定を開かない）**。
- ③ `hasBountyBlock`（`_onStartSkillCheck` の `bountyAvailable` を 0 に落とす＝消費ダイアログ自体をスキップ）。
- いずれも `active` かつ `!pendingScene`（休眠除外）。`effectIgnored`（無視ゲート）は入力側 `getEffectiveConditions` 経由で既に除外。

### 重圧の起動ブロック是正（2026-07-16 ユーザー指摘の修正）

重圧（対象能力値の上方判定不可）は従来カードプレイ時（`_execute` の `getCheckBlock`）でしかブロックせず、**能力値判定の起動まではできてしまう**のが誤り。是正:

- **能力値判定**は起動時にブロック。`_activationBlockReason` が `type==="abilityCheck"` かつ対象能力値が重圧なら起動中止。さらにシートで**対象能力値をグレーアウト＋クリック不能**（下記の共通ユーティリティ `applyTriggerDisable`）。制御判定トリガーは残す（重圧は制御可）。
- **技能判定**の重圧は、使うスート＝能力値が**カードで決まる**ため従来どおりカードプレイ時（`_execute`）でブロック（起動時には確定できない）。
- **山札からの判定（2026-11-24）**。能力値や参加技能から禁止を確定できればドロー前に止める。技能判定のスートは通常どおり引いてから、必要な宣言・スート変更を反映して照合する。重圧で拒否された実カードは元の山札の位置へ戻り、判定はカード選択待ちに戻る。公開済みの札の情報は残る。

### 使用不可トリガーのグレーアウト（共通ユーティリティ・2026-07-16 ユーザー要望で分離）

「判定トリガーをグレーアウト＋クリック不能にする」機能を再利用可能な単体関数 `applyTriggerDisable(root, selector, evaluate)`（`scripts/module/ui-trigger-disable.mjs`・テスト付き）に分離。`_onRender` から呼び、`evaluate` が無効化理由を返した要素に共通クラス `.tnx-trigger-disabled`（淡色・not-allowed）を付け、`check-trigger`・`data-action` を外してクリック不能にする（tooltip に理由）。

- **技能の使用不可**（造反/人脈消失/口座凍結 等の負傷）: `startSkillCheck` トリガーを、その技能の識別キーが `gatherSkillUseWarnings` に該当すればグレーアウト。複数テンプレート（tab-abilities×2・extra-sheet・tab-combat×3）に散在する技能トリガーを、レンダー後に一括処理（テンプレート個別条件を持たない）。
- **重圧の能力値**: `startAbilityCheck` トリガーを `getCheckBlock` でグレーアウト（能力値と技能で同じ関数を共有＝「能力値と同様」の見た目に統一）。
- 機能ブロックは別途 `_activationBlockReason`（open）で担保（グレーアウトは視覚的予告・二重の安全網）。

### 判定修正のマイナス表記是正（2026-07-16）

判定ボーナス／内訳の値をテンプレートで `+{{value}}` とハードコードしていたため、負値が `+-5` になっていた（酩酊 −2・眼部損傷 −5 等）。Handlebars ヘルパー `signed`（負値は `-n`・0以上は `+n`）を新設し、`check-result.hbs` の合計・各内訳（`checkBonus`／各 source `value`）に適用。

### 選択（社会/コネ「ひとつ」）と休眠

- **選択タイミング＝付与時**（ユーザー確定）。**付与経路を問わない `createActiveEffect` フック**（`promptWoundSkillSelection`・衰弱/重圧のドロー受付と同じ場所）で、対象の所持技能から該当プレフィックス（`society_`/`contact_`）の一般技能を候補にダイアログ提示 → `targetSkill`（識別キー）を `setFlag`。**付与ユーザー＝対象の所有者/GM**（フック `userId` 一致）の画面で選ぶ。候補ゼロは通知して選択なし（負傷自体は付与される）。
  - **2026-07-16 是正**: 当初 `applyDamageChartResult`（ダメージ適用経路のみ）に置いたため、トークンのステータス効果トグル等では選択ダイアログが出なかった。ドロー（衰弱/重圧）が経路を問わず出るのに合わせ、フックへ移設。
